# 티켓 검토 코멘트에 답하기

사용자(기획, 김민주)가 희록님 코멘트에 대한 결정을 말하면, **코멘트 → md 반영 → 커밋** 을 한 묶음으로 한다.
합의한 방식이다(2026-10-02): 코멘트로 먼저 알리고, 그 내용을 티켓 md 에도 반영해 pull 전에 개발이 기획 수정 여부를 판단하게 한다.

## 고정 값

- 저장소: `IoT-Solution/bim-to-dt-ontology`, 호스트 `GH_HOST=github.sec.samsung.net` (모든 `gh` 에 붙인다)
- 이슈 제목 끝의 `(OE-XXX-nn)` 이 티켓 ID 다. md 는 `docs/prd/features/E##-XXX/OE-XXX-nn.md` (이슈 본문 첫머리에도 경로가 있다)
- 대상: 칸반 Status 가 `👀 In Review` 인 이슈. 목록은
  `gh project item-list 1 --owner IoT-Solution --limit 300 --format json` 에서 status 로 거른다.
- **Status 는 바꾸지 않는다.** 이동은 희록님이 판단한다.
- 브랜치는 `prd_edit` 에 바로 push 한다. main 직접 push 금지, PR 은 사용자가 요청할 때만 만든다.

## 절차

1. **읽기.** `gh issue view N --json title,body,comments` 로 희록님 코멘트 전문을 읽고, 해당 md 를 연다.
   사용자에게 티켓별로 ①검토 요청 요지 ②현재 md 문구 ③고칠 후보를 보여 준다. 기억으로 답하지 않는다.
2. **결정 받기.** 사용자가 티켓별 답변·기획 결정을 말한다. 말하지 않은 결정을 지어내지 않는다.
   모호하면 묻고, 열린 결정이면 `docs/prd/questions.md` 번호로 가리킨다.
3. **초안 보이기 — 올리기 전에 반드시.** 코멘트 글과 md diff 를 같이 보여 주고 승인을 받는다.
   이슈 코멘트는 올리면 팀 전체에 보이고 지워도 남을 수 있다.
4. **md 반영 → 커밋 → push** (승인 뒤, **티켓마다 커밋 하나**).
5. **코멘트 게시.** 커밋 해시를 넣어 올린다. 본문은 UTF-8 파일로 쓰고 `gh issue comment N --repo … --body-file <파일>` 로 올린다
   (Windows 에서 `--body` 에 한글을 직접 넘기지 않는다). 파일은 scratchpad 에 둔다.
6. 올린 코멘트 URL 을 사용자에게 알린다.

## 코멘트 형식

**첫 줄은 항상 기획 수정 여부다.** 희록님이 pull 전에 판단하는 근거라서 빠뜨리지 않는다.

```
기획 수정: 있음 — `docs/prd/features/E02-OBJ/OE-OBJ-05.md` (커밋 abc1234, 브랜치 prd_edit)
```
```
기획 수정: 없음
```

이어서 희록님 코멘트의 항목별로 답한다. 수정이 있으면 **어느 절의 어느 문장이 어떻게 바뀌었는지** 를 적는다
(요구사항 / 수용 기준). 수정이 없으면 왜 없는지(현행 기획이 이미 그렇게 말함, 개발 쪽 판단 사항 등)를 적는다.
첫 줄 뒤에 확인 요청이 필요하면 "확인 필요" 로 따로 적는다. 사용자 이름으로 올라가므로 사용자 말투(존댓말)로 쓴다.

## md 반영 규칙 (`docs/prd/README.md` "고치는 법" 이 정본)

- **고치는 곳은 `## 요구사항` 과 `## 수용 기준` 뿐이다.** 기획 소유 절이다. `## 검증`·`## 메모` 는 개발 소유라 건드리지 않는다
  (희록님이 요청한 경우만).
- **결과를 최종 문구로 쓴다.** "코멘트에 따라 수정", "(R2 로 이동)" 같은 변경 표시·판본 표시를 본문에 넣지 않는다.
  경위는 git 이력과 이슈 코멘트가 가진다. 코멘트 전문을 그대로 붙여 넣는 것도 아니다 — 확정된 요구로 다듬어 반영한다.
- 열린 결정은 본문에 번호(`D1` 등)만 적고 내용은 `questions.md` 에 둔다.
- **릴리즈·우선순위·상태는 머리 필드만** 고친다. 하나라도 바꾸면 같은 커밋에서 Epic 폴더 `README.md` 표와
  `docs/prd/PRD_011.md` 3장 표도 맞춘다(셋이 어긋나면 테스트가 실패한다).
- ID 는 바꾸지 않는다. 머리 필드 값은 JSON 형식(따옴표 문자열, 대괄호 목록)을 지킨다.
- 개발 정본(`docs/bim-to-dt-ontology.md`)의 등급·R·F·E 를 건드려야 하는 답변이면 멈추고 사용자에게 알린다 — 개발 소유다.
- 기획 수정이 **없으면** md 를 건드리지 않고 커밋도 없다. 코멘트만 올린다.

## 커밋

- 커밋 전에 `npx vitest run src/lib/prd.test.ts` 로 표 일치를 확인한다. 실패하면 고치고, 못 고치면 보고한다. `--no-verify` 금지.
- 메시지: 한국어, 첫 줄 `OE-XXX-nn <무엇을 고쳤나> (희록님 검토 코멘트 반영)`, 본문에 이슈 번호.
  `Co-Authored-By` 줄은 세션 지침의 것을 쓴다.
- md 는 CRLF 로 바뀔 수 있다(autocrlf). 커밋 diff 에 줄 끝 변경만 잔뜩 뜨면 원본 줄 끝에 맞춘다.
- 여러 티켓을 한 번에 처리해도 커밋은 티켓마다 따로 만든다. push 는 마지막에 한 번 해도 된다.

## 보드 동기화 (`npm run board`)

티켓 md 를 고치면 이슈 본문에 붙은 md 사본이 어긋난다. 스크립트는 **제가 임의로 돌리지 않는다.**
커밋·코멘트를 끝낸 뒤 "보드 본문도 맞출까요?" 하고 묻고, 요청받을 때만 `npm run board -- --diff --only=OE-XXX-nn` 으로 먼저 보여 준 뒤
`--apply` 한다. Status 는 이 스크립트도 건드리지 않는다. 자세히는 `docs/prd/README.md` "MD 티켓과 보드 내 티켓 동기화".
