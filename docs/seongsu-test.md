# 성수 BIM 테스트 목록

기준일 2026-09-26. 성수 파일이 있는 PC(또는 55)에서 이 파일을 옆에 띄워 두고 위에서부터 돌린다. 항목마다 번호가
있으니 결과는 번호로 적는다(맨 끝 "결과" 칸). Claude 를 그 PC 에서 쓰면 "docs/seongsu-test.md 의 A 를 돌려 줘"처럼
시켜도 된다.

**왜 지금 재야 하나.** `check:sample` 의 성수 기준값은 정본에 적힌 숫자를 옮겨 넣기만 했고, 성수가 있는 곳에서는
한 번도 돌지 않았다(85ef1f7). 그 사이 성수 숫자를 움직일 수 있는 변경이 여럿 들어갔다(A 의 표). 숫자가 어긋나면
틀렸다고 단정하지 말고 코드와 문서 중 어느 쪽이 맞는지 가린다. 맞는 쪽으로 둘 다 고친다(CLAUDE.md).

차례
- 0 준비
- A 자동 검사 한 번에 (`npm run check:seongsu`)
- B~P 화면 테스트 (열기 · 3D · 패널 · 편집 · 저장 · 내보내기 · 55)
- Q 이미 알고 있는 버그 후보
- 결과

## 0. 준비

```bash
git pull                      # feature/3d-map-edit
npm install
ls -la data/성수/             # Factorial_건축.ifc (84MB), Factorial_기계.ifc (203MB)
```

- [ ] 0-1 파일 이름이 위와 같다. 다르면 자동 검사가 **실패하지 않고 조용히 건너뛴다.** 이름을 바꾸거나 환경변수로 준다:
      `SEONGSU_ARCH=경로 SEONGSU_MECH=경로 npm run check:seongsu`
- [ ] 0-2 옆에 `../ieum-pipeline` 과 `go` 가 있으면 받는 쪽 파서(`ttl.go`) 검사도 돈다. 없으면 그 묶음만 건너뛴다.
- [ ] 0-3 화면 테스트는 **GPU 가 켜진 크롬**에서 한다. 원격 데스크톱·헤드리스는 WebGL 이 CPU 로 돌아 속도가 열 배
      느리게 재진다. 크롬 주소창에 `chrome://gpu` 를 열어 WebGL 이 "Hardware accelerated" 인지 본다.
- [ ] 0-4 메모리 16GB 이상. 자동 검사는 두 파일을 형상까지 읽고 사본을 여러 벌 만든다(힙 12GB 까지 쓰게 해 두었다).

```bash
npm run check:seongsu 2>&1 | tee seongsu-check.log
```

### A-2 불변식 (seongsu.test.ts, 실패하면 버그)

| 번호 | 확인하는 것 |
|---|---|
| A-2-1 | 좌표 없는 설비에 좌표로 정한 소속이 없다. 좌표에 NaN 이 없다 |
| A-2-2 | 좌표로 정한 소속은 자기 층의 방이고, 다시 재도 같은 방이다(겹친 자리면 가장 작은 방) |
| A-2-3 | 방향은 포트만 말한다. 규칙 방향은 방향 없는 연결에만 붙고, 연 직후에는 확정·사람 방향이 없다. 연결의 두 끝은 모델에 있는 설비다 |
| A-2-4 | 규칙 방향은 두 번 돌려도 같다(되돌리기가 이 전제에 기댄다) |
| A-2-5 | TTL 에 기하가 없다. GeoJSON 의 물리존·기기 id 가 전부 TTL 주어로 있다 |
| A-2-6 | 건축·기계 좌표계가 맞는다(기계 설비 대부분이 건축 방 범위 안) |
| A-2-7 | 포트가 말한 연결은 끊기지 않는다 |
| A-2-8 | 설비 옮기기·방 이름·꼭짓점·패밀리 종류·계통 확정·연결 방향·잇기를 한 뒤 편집 파일로 저장·불러오면 TTL·GeoJSON 이 바이트 단위로 같다. 그 편집을 거꾸로 되돌리면 연 때와 같고 편집 파일이 빈다 |
| A-2-9 | 계통을 전부 확정해도 편집 파일이 브라우저 자동 저장 한도(약 5MB) 안이다 |
| A-2-10 | (ttl.go) 기계만 열어도 모든 기기가 위치(층)를 가진다 |
| A-2-11 | (ttl.go) 건축+기계에서 기기→기기 흐름이 받는 쪽에 전부 닿고, 소속 방이 있는 기기는 그 방을 위치로 가진다 |

이 PC 에서는 성수 대신 병원 건축+HVAC, 병원 건축+MEP(207MB), Duplex 건축+MEP 로 돌려 15개가 통과했다.

## Q. 가진 데이터로 찾은 버그 (2026-09-27)

성수 없이 가진 BIM(Duplex·병원·ifc4Mep·AC20·픽스처)으로 찾았고, **Q-1~Q-3 은 고쳤다**(2026-09-27). 고치기 전 코드에서

그대로인지 본다(Q-2). 덧붙이기 전에 편집하면 덧붙이기 버튼이 사라지는지 본다(Q-1).

찾은 방법
- `seongsu.test.ts` 를 가진 파일 조합 12개(건축+HVAC·MEP·MEP-1·MEP-2·ELE·CON·최적화본·COBie, AC20+ifc4Mep)에 돌렸다.

  ① 저장·불러오기 결과가 화면과 같은지 ② 전부 되돌리면 연 때와 같은지. 파일 넷 × 씨앗 15~20.
  **되돌리기는 한 번도 어긋나지 않았다.** 어긋난 것은 전부 저장·불러오기다.

|---|---|---|---|
| Q-1 | **덧붙이기 전에 한 편집이 합치면 기록에서 사라진다.** 덧붙이기는 소속·경계 편집이 있을 때만 막히고(`canAppend`) 이름·종류·확정·방향·잇기는 안 막는다. 합칠 때 이력을 비우고 기준을 새로 떠서, 값은 TTL 에 나가는데 "바뀐 것 0건"이고 편집 파일·자동 저장·Ctrl+Z 에서 빠진다 | 화면에서 재현: 방 이름을 고치면 "바뀐 것 1건" → 덧붙이면 "0건", TTL 에는 고친 이름이 남는다 | 높음 · **고침**: 편집이 하나라도 있으면 덧붙이기를 닫는다(되돌리면 다시 열린다) |
