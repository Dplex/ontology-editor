# 성수 BIM 테스트 목록

기준일 2026-09-29. 성수 파일이 있는 PC(또는 55)에서 이 파일을 옆에 띄워 두고 위에서부터 돌린다. 항목마다 번호가
있으니 결과는 번호로 적는다(맨 끝 "결과" 칸). Claude 를 그 PC 에서 쓰면 "docs/seongsu-test.md 의 A 를 돌려 줘"처럼
시켜도 된다.

**왜 지금 재야 하나.** `check:sample` 의 성수 기준값은 정본에 적힌 숫자를 옮겨 넣기만 했고, 성수가 있는 곳에서는
한 번도 돌지 않았다(85ef1f7). 그 사이 성수 숫자를 움직일 수 있는 변경이 여럿 들어갔다(A 의 표). 숫자가 어긋나면
틀렸다고 단정하지 말고 코드와 문서 중 어느 쪽이 맞는지 가린다. 맞는 쪽으로 둘 다 고친다(`docs/dev/testing.md`).

차례
- 0 준비
- A 자동 검사 한 번에 (`npm run check:seongsu`)
- B~O 화면 테스트 (열기 · 3D · 패널 · 편집 · 저장 · 내보내기 · 55 · 벽·문·창 · 계통). M 을 뺀 거의 전부를
  `npm run e2e:seongsu` 가 GPU 크롬으로 한 번에 돈다(4분). 잰 값은 `data/성수/화면-결과.md` 에 쓰인다
- Q 이미 알고 있는 버그 후보
- 결과

## 0. 준비

```bash
git pull                      # feature/3d-map-edit
npm install
ls -la data/성수/             # Factorial_건축.ifc (84MB), Factorial_기계.ifc (203MB)
```

- [ ] 0-1 파일 이름이 위와 같다. 다르면 자동 검사가 **실패하지 않고 조용히 건너뛴다.** 이름을 바꾸거나 환경변수로 준다:
      `SEONGSU_ARCH=경로 SEONGSU_MECH=경로 npm run check:seongsu`
- [ ] 0-2 옆에 `../ieum-pipeline` 과 `go` 가 있으면 받는 쪽 파서(`ttl.go`) 검사도 돈다. 없으면 그 묶음만 건너뛴다.
- [ ] 0-3 화면 테스트는 **GPU 가 켜진 크롬**에서 한다. 원격 데스크톱·헤드리스는 WebGL 이 CPU 로 돌아 속도가 열 배
      느리게 재진다. 크롬 주소창에 `chrome://gpu` 를 열어 WebGL 이 "Hardware accelerated" 인지 본다.
- [ ] 0-4 메모리 16GB 이상. 자동 검사는 두 파일을 형상까지 읽고 사본을 여러 벌 만든다(힙 12GB 까지 쓰게 해 두었다).
