## padding

값 40종, 363개 중 226개(62%)가 ±1px 안에서 같은 척도(4·6·8·12·16·24)로 옮겨진다. 나머지는 `0.15rem 0.55rem` 같은 칩·알약 내부 여백이라 컨트롤 높이 토큰(24·32·28)이 정해지면 padding 이 아니라 높이로 대체하는 게 맞다.

## 모서리·그림자·z-index

- 모서리: `--radius`(0.75rem)·`--radius-sm`(0.5rem) 구조는 두고, Linear 토큰으로 8·6px 로 바꾼다. 알약 `999px`(61곳)은 칩·토글만 남기고 단추 모서리는 6~8px 도 검토. 4·14·18px 등 단발 값 약 20곳은 6/8 로 정리.
- 그림자: `--shadow` 21곳은 `none`, 오버레이 40종 선언은 1종으로.
- z-index: 12종(1·2·3·4·5·6·7·8·20·30·50·1000) → 5단. 겹침 사고가 난 곳(3D 위 요소끼리)이 먼저다.

## 이 표가 못 하는 것

- `rem` 값이 루트 글자 크기에 곱해지므로 `html { font-size }` 가 바뀌면 전체가 같이 움직인다(현재 16px 기준으로 계산).
- 상속되는 글자 크기(`em`·퍼센트)와 `calc()` 안의 값은 세지 않았다.
- 컴포넌트가 지금 쓰는 값을 그대로 척도에 끼워 넣었을 뿐이라, 척도 자체가 맞는지는 시안(`system.css` 시험 결과)으로 판단한다.
