# 용어와 코드 체계

PRD_011 의 2장 "용어 정의" 와 부록 D "코드 체계" 를 옮긴 것이다. 정본 `../bim-to-dt-ontology.md` 1.1 의 BIM·IFC 용어와 겹치는 것은 거기를 따른다.

## 용어

| 용어 | 설명 |
|---|---|
| 초기 구축 모드 | 온톨로지가 없는 층을 처음 만드는 모드. 진입 시 온톨로지 존재 여부로 자동 분기 |
| 운영 편집 모드 | 온톨로지가 있는 층을 수정하는 모드 |
| IDF | EnergyPlus 입력 파일. Zone(열적 존 = 공조존)·Surface(두께 0)·HVAC 설비·Sizing(설계 풍량)·Schedule. 설비 위치 없음 |
| BIM / Revit / IFC / MEP / Level / Family·Type / Parameter / Shared Coordinates / Room·Space | 건축 정보 모델과 그 저작 도구·교환 포맷·구성 개념. 상세는 기획 문서 「고객사 대상 BIM 요구사항 정의」 3장 |
| 패밀리 / 유형 (Family / Type) | Revit 이 설비를 만드는 틀. **패밀리**는 같은 물건의 틀, **유형**은 그 안에서 크기·사양만 다른 판이다(예: 패밀리 `M_VAV Unit - Single Duct`, 유형 `150 mm`~`350 mm` 다섯, 병원 MEP 128대). IFC 로 내보내면 설비 이름이 `패밀리:유형:요소ID` 꼴이 된다. 에디터는 **패밀리 이름 + IFC 클래스**를 묶음 열쇠로 써서 종류를 패밀리 단위로 한 번에 지정한다(OE-EQP-14). 묶음은 BIM 원래 이름으로 정하므로 사람이 설비 이름을 고쳐도 묶음은 그대로다(OE-EQP-13). 이름이 Revit 꼴이 아니면 유형이 곧 패밀리다 |
| 물리존 (Physical Zone) | 에디터가 편집하는 공간 구획(용도·기능 기준, 예: 회의실). 온톨로지 공간 계층(사이트>건물>층>물리존)에 대응. 이상 알림 '발생 위치'·탐색기 단위. 공간명 고유 1개. ** 임포트 시 IfcSpace 1개 = 물리존 1개** (D15) |
| 룸 | 물리존 하위, 4면 벽으로 둘러싸인 편집 단위. ** 수동 구축·운영 편집에서 물리존을 나눈 단위로 정의를 좁힘** (D15) |
| 소속 허용 거리 | 설비 좌표가 어느 물리존 외곽선 안에도 들지 않을 때, 외곽선까지 이 거리(m) 이하인 가장 가까운 물리존에 소속시키는 값. 벽에 붙은 설비(스위치·온도조절기)의 배치점이 외곽선 위나 바로 밖에 찍히기 때문에 둔다. 사이트 설정이고 디폴트·상한은 U6(현재 구현 5cm). BIM 이 소속을 적은 설비에는 쓰지 않는다 (OE-MAP-01 5단계, K1) |
| 커스텀존 (=운영존) | 물리존 위에 운영 편의로 지정하는 다각형 단위. 별명 복수. Agent 질의 단위. 3D에서 물리존과 레이어드 |
| 공조존 (HVAC Zone) | HVAC 설비가 담당하는 구역. 물리존과 별개 체계(N:M). 계통도·serviceSpace 기준. IDF에서 자동 생성, 공간 편집 모드의 공조존 도구에서 수정 |
| 계통 (System) | 공조기 → 배관/덕트 → 토출구 → 담당 공간의 연결. 공조존은 계통이 담당하는 공간의 집합 |
| 토출구 (Air Terminal) | 공조 공기가 나오는 천장 개구부. 좌표를 가지며 소속 계통·설치 물리존으로 담당 관계 판정 |
| 계통도 | 계통을 2D 모식도로 단순화한 것. 17종(공조·냉수·냉각수·DVM·난방·바닥난방·지열 등). 상세는 아래 "배관 계통" |
| 배관 (Pipe) | 설비 간 냉온수·냉매·덕트 경로. 점(x·y·z) 폴리라인. 좌표 없는 배관은 반영하지 않음. 배관마다 Flow Type(CHWS·HWR·SA 등)을 가진다 — 아래 "배관 계통" |
| 배관 있는 설비 | 계통 정보가 저장된 설비(AHU·VAV 등). 냉매 배관(REF)도 배관이므로 PAC·시스템 에어컨(DVM) 실내기·EHP 실외기도 여기에 든다. 단 이 셋은 **배관을 그리는 것이 필수가 아니다**(없어도 미완성으로 보지 않는다). 냉매 배관은 계통도를 표시할 때 보여 준다. 배치·명칭·이동(연결 배관 함께)·삭제 (OE-OBJ-11) |
| 배관 없는 설비 | 센서·조명·CCTV·엘리베이터·에스컬레이터처럼 별도 배관이 연결되지 않은 독립 설비. PAC·DVM 은 냉매 배관을 가질 수 있어 여기에 들지 않는다. 배치·이동·삭제·명칭 수정, 서로 겹쳐 배치 불가 (OE-OBJ-10) |
| 엘리베이터 (EV) | 건물 내 수직 이동 장치. **배관 없는 설비이면서 수직 관통 오브젝트다 — 둘 다 맞다.** 설비로서는 배치·이동·삭제·명칭 수정과 겹침 불가 규칙을 따르고, 수직 관통 오브젝트로서는 속한 모든 층을 표시·편집하며 승강로의 공통 수직 축과 층별 형상·진입 지점을 관리한다. 확인된 정차 층에서만 로봇 통과 가능하고 무정차·미확인 층은 구분한다. 설치면은 바닥 전용 (OE-OBJ-10·14) |
| 에스컬레이터 | 건물 내 연속 보행식 이동 설비. 엘리베이터와 같이 **배관 없는 설비이면서 수직 관통 오브젝트다.** 설치면은 바닥 전용. R1부터 서로 다른 층별 진입/종료 위치·형상과 상행/하행 방향을 관리한다 (OE-OBJ-10·14, OE-ML-11) |
| 내력벽 | loadBearing=true 인 벽. 물리존에서 수정(이동·삭제·크기 조절) 불가. loadBearing 이 true 인지 false 인지 알 수 없으면 '모름'으로 표시하고 내벽처럼 수정할 수 있다 (OE-OBJ-06) |
| 내벽 | 물리존에서 생성할 수 있는 하위 대상. 1면으로 된 벽이며 건물 내부에 있다. 다른 내벽을 관통할 수 없고, 로봇이 이동할 수 없는 불가 영역이다. 내벽 전용 설비와 창문·문을 배치할 수 있다 (OE-OBJ-05) |
| 외벽 | 건물 바깥과 접한 벽. 전체 층 단위로 생성·삭제·이동·크기(x,y,z) 편집, 외벽 전용 설비(예: 외기 온·습도 센서)와 창문·문을 배치할 수 있다. 외벽 여부는 IFC `Pset_WallCommon.IsExternal` 로 읽을 수 있고 없으면 '모름'이다(ArchiCAD 는 이 속성이 없다). 이 속성이 BIM 수용 기준선에 드는지는 확인 필요 (OE-OBJ-04) |
| 개구부 (문·창) | 벽에 뚫린 문·창. **내벽과 외벽 모두에 배치할 수 있고, 벽 종류로 문·창을 나누지 않는다.** 문은 바닥이 뚫려 있고 천장이 막혀 로봇이 지날 수 있고, 창은 바닥면·천장면이 모두 막혀 로봇이 지날 수 없다. 통과 속성은 GeoJSON `passable` 에 기록 (OE-OBJ-07). 토출구의 "천장 개구부"와는 다른 말이다 |
| 기본 공간 오브젝트 | 에디터가 공간을 이루는 것으로 기본 제공하는 편집 대상(PRD #3 표의 "기본 공간 오브젝트" 분류). **커스텀존 · 물리존 · 룸 · 벽(외벽·내벽·내력벽) · 문/창문 · 바닥/천장** 여섯 종이다. 설비·배관·공조존·추가 공간 오브젝트는 들지 않는다. 설비와 같은 인터랙션(클릭→클릭 배치, 드래그 이동)을 쓴다 (OE-OBJ-01~08·15). OE-OBJ-02 의 "벽/공간존"은 별도 용어가 아니라 이 중 벽과 물리존을 말하는 것으로 읽는다 |
| 추가 공간 오브젝트 | 기본 공간 오브젝트에 들지 않는, 공간을 꾸미는 사물 — 책상·의자·소파·책장·파티션·칠판·화분 등. 사용자가 3D 에셋을 추가하면 종류가 늘어난다. 생성·삭제·이동·크기 조절 가능, 서로 겹침 불가. 에디터 안에서만 제공하고 DT 뷰어마스터에는 노출하지 않는다(TBD). 레이아웃 수정을 위한 온톨로지 연동이 필요하다. 설비와 같은 인터랙션을 쓴다 (OE-OBJ-09·15) |
| 설치면 | 설비가 붙는 면 — 천장·바닥·벽. 설비 종류마다 허용하는 면(**허용 설치면**)과 z 로 자동 판정한 면(**판정 설치면**)이 따로 있다. 설비별 type 은 아래 "설치면 type" |
| 공간 편집 모드 / 설비 편집 모드 | 편집 팔레트의 두 모드(OE-UI-04). 공간: 벽·룸·문·창·추가 공간 오브젝트·물리존·커스텀존·공조존(공조존 도구에서 설비는 담당 지정용 선택만). 설비: 배관 없는/있는 설비·배관·계통·미배치 설비, 층간 배관은 다중층 편집 모드에서 공통 배관 그리기·편집으로 작성·수정하며, 층 편집 화면에서는 [다중층 편집에서 계속]으로 작성 상태를 유지하여 전환. 지금 모드가 아닌 오브젝트는 선택·조회만. 모드는 UI 상태이며 저장하지 않는다 |
| 천장 편집 모드 | 설비 편집 모드의 [바닥·벽 / 천장] 토글에서 천장 쪽을 고른 상태. 상단 시점·천장면 반투명, 천장 설비만 배치·이동·삭제·명칭 수정·종류 지정. 공간 편집 모드와 설비 편집 모드의 바닥·벽 쪽에서 천장 설비는 선택·조회만 (OE-OBJ-08) |
| 다중층 뷰 | 여러 층을 함께 띄워 층을 넘는 것(수직 관통 오브젝트·라이저)을 편집하는 별도 화면. 편집 모드(공간/설비)와 다른 축이다. 진입은 OE-ML-01의 세 경로. 수직 관통 오브젝트는 층 편집 화면에서 선택·조회만 가능하며, 같은 층 수평 배관·분기 연결은 OE-PIP-15의 예외로 편집 가능하다. 보기 층 범위는 실제 관통·운행 구간과 별개다 (OE-ML-01·05) |
| 편집 권한자 | 편집을 시작하고 [반영하기] 를 직접 실행할 수 있는 사용자. Phase 1 은 권한을 구분하지 않고, Phase 2 는 DT 회원 권한(Admin·Super Admin 가능, Viewer 불가)을 따른다 (OE-COM-01·02) |
| 편집 잠금 | 층 단위로 한 사람만 편집하게 막는 것(R2). 같은 층은 동시 편집 불가, 다른 층은 가능. 정상 종료 시 즉시, 비정상 종료 시 heartbeat 중단 60초 후 해제 (OE-COM-05~07) |
| 온톨로지 생성 / 임시 저장 / 미리보기 / 반영하기 / 버전 히스토리 | #8 / #15 / #16 / #17 / #19 정의 참조 |
| ** 등급 (Grade 0~5)** | BIM 하나로 온톨로지가 어디까지 생기는지의 척도(1.8). 파일 목록·검토 화면 칩 |
| ** 수용 기준선** | 미달 시 생성 차단·재제출 요청하는 경계. 게이트(등급 2)와 목표선(등급 3) 구분 |
| ** 요구사항 R0~R24** | 고객사 BIM 요구 항목. 필수 11 · 권장 14. 정본 = 개발 저장소. R25(BAS 매핑 키)는 제안 |
| ** 출처 (Provenance)** | BIM · 계산 · 사전 · 사람 · 외부. 검토 화면 값마다 표시 |
| ** 이름 사전** | 패밀리·계통·방 이름으로 종류를 정하는 규칙 모음 |
| 포트 (Port) | 설비·덕트·배관·이음쇠에 붙은 연결 구멍(접속점). IFC 의 `IfcDistributionPort` 이고, Revit 패밀리의 커넥터(connector)가 내보내지며 포트가 된다. 누구의 포트인가(IFC4 `IfcRelNests` / IFC2x3 `IfcRelConnectsPortToElement`), 무엇과 이어졌나(`IfcRelConnectsPorts`), 흐름 방향(`FlowDirection`: SOURCE 나감 · SINK 들어옴 · SOURCEANDSINK)을 담는다. 포트를 따라가면 "AHU SOURCE → 덕트 → VAV SINK" 사슬이 나오고, 그 결과가 TTL 의 `AHU feeds VAV` 다. 에디터에서 포트는 ① **설비라는 증거**(포트가 있는 Proxy 는 설비, OE-BIM-13·OE-EXT-05) ② **방향의 유일한 BIM 근거**(원본 방향은 직접 고치지 않으며 유효 연결은 확정 없이 `feeds` 로 나간다. 연결 해제 보정은 가능하고 해제된 연결은 출력에서 제외한다, K13·OE-PIP-06)다. 포트가 없으면 형상 접촉으로 연결만 추정하고 방향은 비운다(K3·K4). 화면은 포트 방향을 진한 색, 규칙 방향을 옅은 색으로 가른다. 고객사 요구는 R17(성수 실측 62%, PRD 1.8) |
| ** 규칙 방향** | 포트 방향이 없을 때 계통·설비 종류로 추정한 흐름 방향. 사람이 계통 단위로 확정한 것만 `feeds`로 내보냄 |
| ** 완전성 검사** | DT가 쓰려면 이어져야 하는 것을 8규칙으로 확인. 위반마다 이유와 "한 번에 고치기" |
| ** 판본 비교** | 같은 건물의 이전·이후 BIM 비교(GUID 유지·변경 항목) |
| ** 편집 파일** | 열었을 때와 달라진 값만 id+식별 정보(Revit 요소 ID·이름·위치)로 저장한 JSON. GUID 바뀐 판본에 재적용 |
| ** 수직 관통 오브젝트** | EL·ES·계단·샤프트. 물리존과 구분하는 별도 오브젝트이며 부모 ID 아래 층별 형상·위치·진입/종료 지점·연관 물리존을 관리한다. 샤프트·EL 승강로는 공통 수직 축, 계단·ES는 층별 형상을 지원한다 (#24·#25, OE-ML-02) |

## 천장 관련 높이

"천장" 은 BIM 에서 높이가 다른 두 면(반자, 슬래브 하단)을 가리킬 수 있다. 이 문서의 높이는 전부 **층 바닥에서 잰 z** 다. 책장 한 칸으로 보면 쉽다 — 칸의 바닥이 층 바닥, 윗칸의 바닥판이 슬래브, 칸 안에 낮게 친 가리개 천이 반자, 천 위의 숨은 공간이 플레넘이다.

| 용어 | 뜻 | 예 (사무실) |
|---|---|---|
| 층 바닥 높이 (Level) | 이 층 바닥의 높이 | 0m |
| **층고** | 이 층 바닥부터 **윗층 바닥**까지. Level 의 차 | 4.0m |
| 슬래브 하단 | 윗층 바닥판의 아랫면. 플레넘의 지붕 | 4.0m 근처 |
| **반자 (h_c)** | 눈에 보이는 천장 마감면. 이 문서에서 "천장" 은 반자를 말한다 | 2.7m |
| **플레넘** | 반자와 슬래브 하단 사이의 숨은 공간. 덕트·배관·VAV 가 든다 | 2.7m ~ 4.0m |
| 방 높이 | 방(IfcSpace) 상자의 높이. 같은 방도 판본마다 값이 다르다(아래) | 2.7m 또는 4.0m |
| **판정 문턱** | 설치면을 가르는 z 컷오프. 바닥 z ≤ 0.3m, 천장 z ≥ h_c−0.3m, 벽은 벽선 0.3m 이내 | — |

옛 규칙은 천장 문턱이 "층고−0.6m" 였다. 층고 4.0m·반자 2.7m 인 사무실에서 조명 z=2.7m 는 3.4m 에 못 미쳐 천장이 아니라 벽 또는 "미정" 이 된다. 반자 기준(2.4m)이면 천장으로 읽힌다.

**BIM 에서 읽을 수 있는 것.** 가진 BIM 5개 중 4개를 재서 정리했다(2026-10-02, 성수 미측정).

| 알고 싶은 것 | BIM 의 어디 | 실측 |
|---|---|---|
| 층 바닥 높이 | `IfcBuildingStorey.Elevation` | 층이 있는 파일 전부 |
| 층고 | Elevation 의 차(계산). 속성 `GrossHeight`·`NetHeight`(ArchiCAD), `Storey Height`(COBie) | 차는 전부, 속성은 AC20·COBie |
| **반자 높이를 직접** | `FinishCeilingHeight` | **AC20 만** (7/7) |
| 방 높이 | Revit `Unbounded Height`, 방 형상의 압출 깊이 | 건축 판본: Duplex 21/21·병원 269/269. **설비 판본은 층고와 같아 반자로 못 씀** |
| 천장 부재 | `IfcCovering` CEILING | Revit 건축 판본만(Duplex 13·병원 250). 높이는 아직 안 읽음 |
| 없음 | — | COBie 판본(`UsableHeight` 가 0), 방이 없는 ifc4Mep |

같은 병원이 판본마다 다르다 — 건축 판본의 방 높이 중앙값은 2.8m(층고 4.57m), 설비 판본(MEP Space)은 4.57m 로 층고와 같다. Revit 이 MEP Space 를 윗층 바닥까지 늘려 내보내기 때문이다. 건축 판본의 2.8m 가 반자인지 방 볼륨의 위쪽 한계인지는 BIM 만 봐서는 구분되지 않는다.

**h_c 를 정하는 방법.**
- **방향(정함).** 에디터가 층고·반자 높이·방 높이를 미리 정해 두지 않는다. **BIM 에 있으면 그 값을 따르고, 없으면 사용자가 설정한다.** 값마다 출처(BIM · 사람)를 표시한다.
- **읽는 순서(제안).** ① 반자 높이를 직접 말하는 속성 → ② 건축 판본의 방 높이 → ③ 천장 부재의 높이 → ④ 사용자 설정. **설비 판본의 방 높이는 쓰지 않는다.** 건축과 설비를 합칠 때 같은 방은 건축 판본의 값을 쓴다.
- **모를 때(제안).** 0 이나 "층고−0.6m" 로 채우지 않는다. 천장 판정을 "미정" 으로 두고 사용자에게 입력을 요청한다. 설정 단위(사이트·층·물리존)는 미정이다(Q7).
- **설비 z 로 추정(제안).** 설치면이 반자 부착형인 설비의 z 는 h_c 의 단서지만 곧 h_c 는 아니다(플레넘 VAV·FCU 는 반자 위, 매달린 조명은 반자 아래). 반자 면에 붙는 종류만 쓰고, 종류는 BIM 의 IFC 클래스·이름으로 정한 것만 쓰며(높이로 짐작한 종류는 순환이다), 방·층 단위의 최빈값을 쓴다. 입력창의 기본값(후보, 출처 "계산")으로만 보이고, 사람이 확정하기 전에는 값이 아니다.

**천장 설비의 두 구역(제안).** 어느 구역인지는 아래 설치면 type 표의 종류가 정한다.

| 구역 | 대상 | 허용 z | 기본 z |
|---|---|---|---|
| 반자 부착 | 디퓨저·그릴, 감지기, 조명, 스프링클러 헤드, 스피커, 천장형 센서, CCTV, 카세트 실내기 | z ≥ h_c−0.3m | h_c |
| 플레넘 | 천장 속 VAV·FCU, 덕트형 실내기 | h_c < z < 층고 | h_c 바로 위 |

소속 물리존은 x·y 평면으로만 판정하므로 플레넘 설비도 아래 방 소속이다. 천장 모드의 이동은 x·y 만이고 z 는 속성 패널에서 고친다. z 를 고쳐 구역을 벗어나면 막고 이유를 보인다(Q10).

## 설치면 type

설비 종류마다 **어느 면에 붙일 수 있나**를 정리한 표다. 천장 편집 모드(OE-OBJ-08)가 "허용 설치면에 ceiling 이 없는 종류는 배치·드롭·이동을 막는다"고 하는데, 그 허용 설치면의 값이다. **설비별 설치 가능 면의 정본은 이 표다.** OE-OBJ-08 은 이 표를 따르고, 둘이 다르면 이 표가 우선한다. 설비 목록(Overview §7·§8)의 57종을 따르고, 목록에 없는 설비(옛 OE-OBJ-08 에 있던 것 포함)는 표 아래에 따로 둔다.

**값.** 설치면은 천장(ceiling)·바닥(floor)·벽(wall) 셋이다. 한 종류가 여러 형태를 가질 수 있어(FCU 는 천장 속과 바닥형이 둘 다 있다) 허용 설치면은 집합이다.

| type | 뜻 |
|---|---|
| 천장 전용 | 천장에만 붙는다. 천장 편집 모드에서만 배치·이동한다 |
| 바닥 전용 | 바닥에만 붙는다 |
| 벽 전용 | 벽에만 붙는다. 외벽에만 붙는 것(외기 센서)과 내벽에만 붙는 것(스위치)이 나뉜다 |
| 복수(천장·벽) 등 | 허용 면이 둘이다. 배치할 때 한 면에 골라서 설치한다. |
| 설치면 없음 | 면에 붙는 설비가 아니다. **부착**(배관·덕트 위 부품 — 붙은 배관의 위치를 따른다) · **지중** · **이동체** |

**근거 열.** `기획` = 기획이 확정한 값(옛 OE-OBJ-08 에 적혀 있던 것과 이후 기획이 이 표에서 직접 고친 것). `제안` = 설비 목록의 성격으로 정한 것이라 **기획 확인이 필요하다**. 확인되면 `기획` 으로 바꾼다.

**허용 설치면 ≠ 판정 설치면.** 판정은 OE-EQP-03 이 BIM 의 z(바닥 기준)로 하고, 문턱과 h_c 는 위 "천장 관련 높이" 를 따른다. 판정은 BIM 이 말한 현재 위치이고, 허용은 에디터가 새로 놓을 때 쓰는 규칙이다. 아직 정해지지 않은 것이 둘 있다(둘 다 제안 — 확인 필요).

1. **z 를 재는 점.** 패밀리 삽입점이 바닥면인지 중심인지에 따라 바닥 설비도 "미정" 이 된다(높이 1.5m AHU 가 중심 원점이면 z=0.75m). z 는 오브젝트 바운딩박스의 최저점으로 읽는 안이다(Q8).
2. **판정이 허용 밖일 때**(예: z=2.9m 인 AHU). 허용 설치면을 우선하고, 불일치 설비는 임포트 리포트에 표시하는 안이다. 삽입점·좌표 오류를 잡는 검사로도 쓸 수 있다(Q9).

## 배관 계통

배관은 **무엇이 흐르느냐(Flow Type)** 로 갈리고, 계통도는 그 흐름을 설비 단위로 묶은 그림이다. 기획 문서 「빌딩 계통도 종류」(§9.2 계통도 종류, §12-1 범례·Flow Type)를 옮겼다.

**"환기" 는 還氣(리턴)다.** 원문의 "환기"는 환기팬의 換氣(ventilation)로 읽힐 수 있어 RA 는 "리턴(還氣)" 으로 적는다. 환기팬(설비 목록 41~44)은 換氣다.

### 설비 연결 방향 (Source → Target)

Flow Type 은 위 방향으로 흐른다고 보고, 환수는 반대 방향 환수선이 있다고 가정해 그린다. 펌프를 사이에 둔 것은 직접 연결이 아니라 펌프가 매개한다는 뜻이다.

|---|---|---|---|---|
| 냉각수 | 냉각탑 | 펌프 | CWS | CWR |

| 냉수 | 터보·흡수식 냉동기 | 펌프 (P101·P103 계열) | CHWS | CHWR |

| 냉매 | 시스템 에어컨 실외기 | 시스템 에어컨 실내기, 캐비닛형 냉난방기, 공조기(일부) | REF | 없음 |

- 공조기 일부는 냉수와 냉매를 함께 받는다(혼합 매체, 하이브리드 DX+CHW).
- 캐비닛형 냉난방기는 온톨로지에서 상류가 시스템 에어컨 실외기뿐이라 냉매다. 설비 목록의 "수 방식" 과 다르다.
