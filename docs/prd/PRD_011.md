## 1. 개요

### 1.1 배경 및 목적

- **[운영]** 운영 중 리모델링·벽체 변경·설비 재배치가 발생하면 3D 모델·공간 계층·설비 소속·관제 화면·AI 응답이 서로 다른 상태가 되기 쉽다. 변경 반영이 구축 조직이나 개별 시스템에 의존하면 느리고 무엇이 최신인지 알 수 없다.
- **[구축]** 온톨로지가 없는 사이트(예: SR 캠퍼스)는 물리존·공조존·설비·배관 정보를 처음부터 만들어야 한다. BIM이 있으면 가져와 골격을 자동 생성하고, 없으면 수동으로 구축할 수 있는 도구가 필요하다.
- 레이아웃 에디터는 두 목적을 한 도구에 담는다: **온톨로지 생성 툴**이면서, 권한 있는 운영자가 공간·오브젝트·공조존·배관을 **하나의 버전 단위로 편집하고 검증·영향 확인을 거쳐 게시**함으로써 모든 소비 시스템(관제 화면·이상 알림·계통도·AI Agent)의 기준 버전을 일치시킨다.
- 공간 변경 전 영향을 미리 검토할 수 있는 **미리보기**를 제공한다.

**사용자 플로우**
- 초기 구축: 에디터 실행 → 사이트·층 선택 → [IDF/BIM 가져오기] 또는 [빈 층에서 시작] → 검토 화면(등급·요구사항·완전성) → 물리존·커스텀존·공조존·설비·배관 구축·보정 → 검증 → [온톨로지 생성·내보내기] → DT 등록
- 운영 편집: 에디터 진입 → 층 선택(잠금) → 편집 → ① [임시 저장] / ② [미리보기] → [반영하기] → DT·온톨로지 반영 + 새 버전 → 결과 리포트 → (필요 시) 되돌리기 / ③ [편집 종료]

### 1.2 대상 사용자

| User | Job to be done |
|---|---|
| 구축 담당자 (삼성·협력사) | IDF·BIM 또는 수동 입력으로 사이트의 초기 온톨로지(물리존·공조존·설비·배관)를 구축하고 DT에 등록한다 |
| 레이아웃 에디터 수행 사용자 (고객사 관리자) | 레이아웃 변경을 수행하고, 게시 전 미리보기로 결과와 영향을 확인한다 |
| 일반 관제 사용자 | 레이아웃 변경 사실을 인지하고 원하는 시점에 최신 레이아웃으로 전환한다 |
| AI Agent 사용자 | 변경된 레이아웃 버전과 커스텀존을 바탕으로 공간·설비를 질의한다 |
| 로봇 관제 | 문·창문·벽·천장 설비의 통과 가능/불가 정보를 이동 경로 판단에 쓴다 |
| ** 고객사 BIM 담당·설계사** | 요구사항(R0~R24)·IDS로 자체 검사한 BIM을 제출하고, 결과 리포트(등급·재제출 항목)를 받는다 |

### 1.6 시작점 분기

| 온톨로지 | 입력 | 에디터 모드 | 동작 |
|---|---|---|---|
| 없음 | BIM 건축+MEP, **등급 2 이상** | 초기 구축 | 공간 골격·설비·소속 자동 생성 → 검토 화면 → 보정 → 생성. IDF 있으면 공조존 자동, 없으면 조닝 모드 수동 |
| 없음 | BIM, **등급 2 미달** | 초기 구축(생성 차단) | 검토 화면에서 누락 분류(X/A/B/C) → 필수 누락은 재제출 요청(1안). [생성] 비활성. 고객사 결과 리포트 발행 |
| 없음 | BIM 건축만 (MEP 없음, 등급 0) | 초기 구축 | 공간 골격만 자동. 설비 전량 수동(#13), R9 재제출 요청 병행 |
| 없음 | BIM 無 | 초기 구축 | 3D 스캔·평면도 배경에서 수동(#7) |

| 있음 | 기존 온톨로지 + 3D 모델 | 운영 편집 (공간 편집 / 공조 조닝 / 배관 모드) | 층 잠금 · 임시 저장 · 미리보기 · 반영 · 버전 히스토리 |

※ BIM(물리 공간)과 공조존(에너지 시뮬레이션 IDF)은 별개 체계. 물리존은 BIM/스캔에서, 공조존은 IDF에서 오며 둘의 매핑을 에디터가 만든다.
※ **IFC2x3도 등급 0~2를 만족할 수 있다**(개발 실측: Revit 샘플·성수 전부 IFC2x3). IFC4는 권장(R10)이며 분기 조건이 아니다. gbXML·IDF는 공조존 출처(등급 5)이므로 분기 조건에서 제외.

### 1.7 배포 형태 및 DT 연동

| 항목 | 내용 |
|---|---|
| 배포 형태 | Unity DT 내부가 아닌 **별도 에디터 프로그램(Three.js)**. 현재 별도 제작·제공 중인 에디터를 기반으로 확장. SRCN 개발팀 Astra 사용 불가 영역은 국내 내부 리소스 개발 |
| 진입점 | DT 스마트 관제 > 3D View의 '레이아웃 에디터' 버튼 = 에디터 실행 링크. 초기 구축은 DT 없이 단독 실행 |
| 현재 PoC 산출물 | **GeoJSON(기하: 물리존 외곽선·벽·문·창·설비 좌표) + Brick TTL(의미: 계층·소속·연결)**, 같은 IfcGlobalId로 연결. 술어 4종(`hasPart`·`hasLocation`·`feeds`·`hasPoint`). DT 파서(ieum-pipeline `ttl.go`)가 읽는 것 확인 |
| DT↔에디터 데이터 교환 | ① 파일 export→DT import **(PoC 전제, 결정 전 진행 기준)** ② 온톨로지 서버 API ③ 공유 DB. 반영·되돌리기·배너·잠금(#2 #15 #17~#19)의 소재지가 이 결정에 종속 → **D-INT** |
