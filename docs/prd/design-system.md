# 디자인 시스템 — 온톨로지 에디터

에디터 화면이 **어떻게 보이고 무엇을 어떤 모양으로 알리나**를 정한다. 기능(무엇을 하나)은 티켓이 정하고, 이 문서는 그 기능을
화면에 올릴 때 쓰는 색·글자·크기·부품과 규칙만 둔다. 디자인 시스템의 정본은 이 문서 하나다.

이 시스템은 두 층이다. 한 문서 안에서 층마다 장을 나눠, 같은 값을 두 번 적지 않는다.

| 층 | 무엇 | 장 | 요구사항 |
|---|---|---|---|
| 공통 | 색 토큰(라이트·다크) · 척도(글자·간격·컨트롤 높이·모서리·그림자·z) · 컴포넌트 기본 규칙 · 상태(호버·눌림·포커스·비활성) · 모션 | **A1~A7** | [OE-UI-23](features/E03-UI/OE-UI-23.md) |

# 공통 층 (OE-UI-23)

## A1. 성격

차분하고 촘촘한 편집 도구. 색은 거의 중립, 강조색은 인디고 하나, 구분은 그림자가 아니라 선. 위계는 **채움 > 선 > 글자** 3단이고 "지금 해야 할 일" 하나만 채움으로 칠한다. 글자는 12px 이상, 누르는 것은 24×24px 이상이다. 범위는 1024px 이상 화면(모바일·태블릿은 범위 밖).

## A5. 상태

| 상태 | 규칙 | 개발 앱 현재 |
|---|---|---|
| 호버 | 모든 누르는 컴포넌트에 있다. 배경을 한 단 진하게(`--surface-soft`). 링크 단추만 밑줄 | 모드 스위치 · 접기 머리 · 진단 칩 · 분절은 호버 없음 → 추가 |

| 키보드 포커스 | 전 컴포넌트 공통 `:focus-visible`: 2px `--focus` 고리 + 2px 오프셋 | 브라우저 기본(1px 거의 검정). 다크에서 약함 |
| 비활성 | `opacity: 0.45` + `cursor: not-allowed`, 네이티브 단추도. 이유는 툴팁으로(OE-UI-03) | 0.45 와 0.42 혼재, 네이티브 단추는 미적용 |

## A6. 모션

- 호버 색 전환 120ms(`--t-hover`), 눌림 100ms(`--t-press`), 패널 진입 180ms(`--t-panel`). 모두 ease-out(`--ease` = `cubic-bezier(0.22, 1, 0.36, 1)`). `transition: all` 금지 — 바뀌는 속성만 적는다.
- 자주 하는 동작(편집 · 선택 · 단축키)은 기다리게 하지 않는다. 숫자 굴림은 처음 한 번만 300ms 이하. 바뀐 줄 번쩍임 0.8초 이하. 진행 막대는 줄마다 지연 없이 0.3초 이하. 목록 선택으로 일어나는 스크롤 이동은 즉시.
- 움직임 끄기(`prefers-reduced-motion`): 이동 · 확대만 끄고 배경색 변화는 남긴다.
- 리플레이(`ReplayHud` · `ReplayGeo`, 어두운 극장식 연출)는 이 시스템의 대상이 아니라 별도 "보여주기 모드".
- 개발 앱에서 줄일 모션 목록(굴림 900ms · 번쩍임 1.6s · `transition: all` 3곳 등)은 [`prototype/design-audit/MOTION.md`](prototype/design-audit/MOTION.md).

## A7. 하지 않는 것 · 열려 있는 것

- 3D 장면 색(벽 회색 · 위반 분홍, Three.js 재질)은 이 문서 밖. 에디터에서 정한 3D 색은 2.3 의 존 · 벽 · 천장면뿐이다.
- 웹폰트 도입(사내망에서 받을 수 있는지 모름 — 시스템 글꼴 유지), 그라데이션 장식, 카드마다 그림자.
- 모바일 · 태블릿(1024px 미만).
- 3D 위 요소끼리의 자리 규칙: 개발 앱 편집 모드에서 3D 아래 조작 안내 글이 오른쪽 범례와 겹친다(성수 1440px, 원래부터). 에디터 확장은 4장의 캔버스 위 패널 자리로 정했다.

# 에디터 확장 (OE-UI-17)

## 1. 원칙

공통 층의 성격(A1 — 차분하고 촘촘한 편집 도구 · 강조색 하나 · 그림자 대신 선 · 채움 > 선 > 글자 3단 위계 · 12px 하한)을 그대로 따르고, 에디터에서 다섯 가지를 더한다.

1. **3D 가 주인공이다.** 캔버스는 공통 `--bg` 위에 둔다. 색은 편집 대상(존 · 설비 · 선택)과 상태에만 쓴다.
2. **색 하나에 뜻 하나.** UI 상태 색(선택 · 정상 · 주의 · 위험)과 존 분류 색을 따로 둔다. 분류 색은 캔버스 · 목록 점 · 레이어 체크에만 쓰고, 상태를 알리는 데 쓰지 않는다.
3. **지금 상태는 항상 보인다.** 모드 · 편집 기준(임포트 결과 · vN) · 임시 저장본 여부 · 저장 안 된 변경 수 · 지금 도구가 화면에 늘 떠 있다.
4. **못 쓰는 것은 숨기지 말고 이유를 단다.** 비활성 버튼 · 도구에는 왜 못 쓰는지와 어디서 쓰는지를 툴팁으로 보인다(OE-UI-03 공통 규칙).
5. **화면에서만인 것과 남는 것을 가른다.** 레이어 켜고 끄기 · 설치면 필터처럼 저장본 · TTL · GeoJSON 에 남지 않는 것은 "화면에서만" 이라고 적는다.

## 2. 색

| `--accent-soft` | 선택 행 · 켜진 도구 바탕 | — |
| `--on-accent` | 주 버튼 글자(흰색 하드코딩 금지) | 6.6:1 |
| `--focus` | 키보드 포커스 고리 | 8.2:1 |
| `--warn-fg` · `--warn-bg` · `--warn-line` | 주의(아래 2.2) | 11.1:1 |
| `--error` · `--error-soft` | 위험(아래 2.2) | 6.8:1 |

### 2.2 에디터 확장 — 의미 색

공통 층에 없는 "정상" 하나만 더하고, 나머지는 공통 토큰을 뜻에 묶는다.

| 뜻 | 토큰 | 쓰는 곳 |
|---|---|---|
| 선택 · 주 동작 | `--accent` | 선택 행 · 켜진 도구 · 켜진 종류 칸 · [반영하기]/[구축하기] · 신규 태그 |
| 정상 | **`--ok #6cc9a0`**(8.9:1) · `--ok-soft #16261f` (확장) | 운영 편집 배지 · 생성 가능 · 임시 저장됨 |
| 주의 | `--warn-*` | 초기 구축 배지 · 저장 안 된 변경 · 임시 저장본 · 변경 태그 · 경고(W · Z) |
| 위험 | `--error` · `--error-soft` | [편집 종료] · 삭제 · 생성 막힘 · 저장 실패 |
| 중립 | `--muted` · `--surface-soft` | 기준 배지 · 변경 없음 · 출처 칩 |

### 2.3 에디터 확장 — 존 분류 색

3D · 평면도 · 목록 점 · 레이어 체크가 같은 색을 쓴다. 면은 옅게(8~14%), 경계는 점선. 상태 색과 겹치지 않게 골랐다.

| 존 | 토큰 | 값(대비) |
|---|---|---|
| 물리존 | `--zone-space` | `#38bdf8` 하늘(8.3:1) |
| 커스텀존 | `--zone-custom` | `#f472b6` 분홍(6.7:1) |
| 공조존 | `--zone-hvac` | `#a3e635` 연두(11.8:1) |
| 벽 | — | 윗면 `#dfe6ef` · 옆면 `#b9c4d3` |
| 천장면 | — | `#9fb3cc` 투명도 50%(불투명도 0.5) — 2026-10-16, OE-OBJ-08 AC6. 프로토타입은 개발 코드(`src/lib/viewer.ts` 의 0.22)를 그대로 써서 아직 0.22 로 보인다 |

물리존 칠하기(OE-UI-26)가 켜진 동안은 물리존 분류 색 대신 범례 색(상태 색과 겹치지 않는 순서 팔레트)을 쓴다.

와이어프레임 v0.2 는 물리존 파랑 · 커스텀존 보라 · 공조존 주황이었다. 공통 강조색이 인디고라 파랑 · 보라가 선택과 헷갈리고, 주황은 주의와 겹쳐 바꿨다.
그 밖의 3D 장면 재질 색은 이 문서 밖이다(A7).

## 5. 에디터 부품

공통 컴포넌트(단추 주 · 보조 · 3차, 분절 · 탭, 칩, 어두운 독, 배지, 입력, 카드, 표)는 A4 를 따른다. 아래는 에디터에서 어떤 공통 컴포넌트를 쓰는지와 에디터에만 있는 부품이다.

| 부품 | 공통 컴포넌트 | 에디터 규칙 |
|---|---|---|
| 헤더 동작 | 단추 — 주 · 보조 | 주는 [반영하기]/[구축하기] 하나 |
| 편집 모드 · 3D/평면도 | 분절 | 켠 칸 = `--accent` 채움 + `--on-accent`. 편집 모드는 레일 맨 위 세로 분절(칸 72×28), 3D/평면도는 캔버스 왼쪽 위 레이어 패널과 같은 폭의 가로 분절(높이 28) |
| 층 범위 칩 [현재층 ▾ · 다중층 ▾] | 분절 | 캔버스 오른쪽 위, 높이 28. [현재층]은 층 이름 선택 상자를 품고, 단일 층일 때 `--accent` 채움으로 켜진다. 초기 구축만 층을 바꿀 수 있고 운영 편집은 화살표 없이 이름만 보인다(툴팁에 까닭). 다중층 중에는 [다중층 ▾]가 범위 이름("B2F~1F · 3개 층")으로 켜진다 |
| 모드 · 기준 · 생성 가능 배지 | 배지 | 정상(`--ok`) · 주의(`--warn-*`) · 중립 |
| 변경 태그 | 배지 | 신규(`--accent-soft` + `--accent`) · 변경(`--warn-*`) · 변경 없음(중립). 목록 행과 선택 오브젝트 이름 옆 |
| 출처 칩 | 배지(출처 3종) | BIM · 계산 · 사전 · 사람 · 외부(OE-UI-13). 사람 · 외부 모양은 공통 3종에 맞춰 더한다 |
| **도구**(레일) | 에디터 전용 | 아이콘 17 + 이름 12px, 72×52, 모서리 8. 켜짐 = `--accent-soft` 바탕 + `--accent` 테두리. 접근성 이름은 "＋ 물리존 그리기" 처럼 동작까지 |
| 종류 칸(층 현황) | 분절 | 5칸 격자(물리존 · 커스텀존 · 공조존 · 설비 · 공간 오브젝트, 최소 높이 56), 칸마다 개수(16 굵게) 위 · 이름(12) 아래. 켜진 칸 = `--accent` 테두리 + `--accent-soft`. 개수는 화면 낭독에서 뺀다 |
| **목록 행** | 에디터 전용 | 높이 32, 점(존 색) · 이름 · 태그 · 오른쪽 값(면적 · 설치면). 선택 = `--accent-soft` |
| 섹션 · 키-값 행 | 카드 · 표 | 섹션 위아래 12 · 좌우 16, 제목 14. 키-값은 라벨 `--muted` · 값 `--fg` |
| **뜨는 패널**(레이어 · 도구 안내 · 그리기 바) | 3D 위 오버레이 | `--surface` 92% + `--line` + 그림자 1종, 모서리 8 |
| 뷰 컨트롤 바 | 어두운 독 | 높이 28 칩 단추 묶음 |
| **토스트** | 3D 위 오버레이 | 결과 알림 한 줄, × 로 닫는다. 오류는 `--error` 테두리 |
| **우클릭 메뉴** | 팝오버 | 행 32, 맨 위 대상 이름 · 모드 잠금 이유. 위험 항목은 `--error`, 구분선 아래 |
| 레이어 패널 | 3D 위 오버레이 | 묶음 머리(존 · 공간 · 설비, 12px `--muted`) 아래 체크 줄. 설비의 하위 줄은 들여 쓴다. 상위 줄(설비 전체)은 하위가 일부만 켜지면 반쯤 찬 체크. 체크 색은 존 분류 색 · 그 밖은 `--accent` |
| 다중층 범위 팝오버 | 팝오버 | 층 범위 칩 아래. 시작 층 ~ 종료 층 고르기(지하층 먼저) · [전체] · [지금 층 ±1] · [고른 오브젝트의 관통 범위] · "보기 범위만 바꿉니다" 안내 · [다중층 보기]. 다중층 중에는 위치 표시가 범위 + "다중층" 배지가 되고, [다중층 ▾] 칩이 범위 이름으로 켜지며 [현재층]을 누르면 단일 층으로 돌아온다 |
| 설비 종류 칩 | 칩 | 높이 24, 이름 + 개수. 켜진 칩 = `--accent` 채움. 다시 누르면 풀린다 |
| 막힌 이유 칩 | 단추 — 주의 | [구축하기]/[반영하기] 왼쪽, `--warn-*`. "구축하기 막힘 · 첫 이유", 누르면 기준 · 검증 드로어. 공유 테스트 빌드(`VITE_GATE_BYPASS=1`)에서만 "기준 미달(테스트용 허용)" 으로 바뀌고 [구축하기]를 막지 않는다 — 제품 규칙이 아니다 |
| **기준 · 검증 드로어** | 팝오버 | 헤더의 편집 기준 버튼이 연다. 비모달 — 정보 패널과 같은 폭(360)으로 그 자리만 덮어 3D · 캔버스 위 조작을 가리지 않는다. 생성 기준 · 수용 기준선 등급 · 규칙 경고. ✕ · Esc · 버튼으로 닫고 포커스는 버튼으로. 들어올 때 180ms 밀려 들어옴(움직임 끄기면 없음) |
| **안내 바** | 에디터 전용 | 높이 36, `--surface` 위 한 줄. 새 버전 = `--accent-soft`, 오류 = `--error-soft` |
| **상태줄** | 에디터 전용 | 28, 고정폭 12px, `--muted`. 값만, 문장 없이 |
| 게이지 | 에디터 전용 | 높이 6, 알약. 통과 `--accent` · 미달 `--warn-fg` |

미리 강조(커서 아래 골라질 것, OE-UI-27)는 `--accent` 테두리만, 고른 것은 `--accent` 테두리 + `--accent-soft` 면으로 구별한다. 임시 숨기기 · 격리 · 섹션 박스가 켜진 동안은 캔버스 테두리에 `--accent` 띠와 "임시 보기 — 화면에서만" 을 보인다(OE-UI-19 · OE-UI-29).

상태(호버 · 눌림 0.97 · 포커스 고리 2px `--focus` · 비활성 0.45 + 이유 툴팁)와 모션(호버 120ms · 눌림 100ms · 패널 180ms, `transition: all` 금지)은 A5 · A6 그대로다.
에디터 전용 부품도 같은 규칙을 쓴다.

## 6. 상태를 보이는 규칙

| 무엇 | 어떻게 | 어디 |

# 부록 — 근거와 시험 결과 (2026-10-15, 개발 앱 대상)

공통 층은 개발 앱(`src/App.vue`)을 Playwright 로 재고, CSS 를 덧입혀 전후를 비교해 정했다. 앱 코드는 고치지 않았다. 시험 코드와 재현 방법은 [`prototype/design-audit/`](prototype/design-audit/README.md).

**진단(출발점).** Duplex 열람 화면에서 글자 크기 17종(9.36~16.8px), 11.5px 이하 글자 약 70곳, 24px 미만 클릭 대상 14개, 세로 2705px. 토큰은 색 · 모서리에만 있고 글자(24종) · 간격(gap 16종 · padding 40종) · 단추 높이(16종)에는 없었다. `:active` 규칙 0개, z-index 12종. 같은 컴포넌트가 여러 모양(분절 · 탭 5곳 따로 구현, 네이티브로 남은 체크박스 154개).

**후보 비교 → Linear 계열.** 앱의 `:root` 토큰만 덮어 Linear · Vercel · Stripe 계열을 같은 화면에 입혔다. 모두 AA(4.5) 통과.

| | Linear | Vercel | Stripe |
|---|---|---|---|
| 인상 | 차분 · 촘촘, 인디고 | 흑백 정밀, 헤어라인 | 네이비 + 보라, 부드러운 그림자 |
| 둥글기 / 그림자 | 8px / 없음 | 6px / 없음 | 10px / 부드러운 그림자 |
| 줄 간격 | 1.5 | 1.55 | 1.65 |
| 다크에서 3D 와 패널 | 중간 | 가장 분리(순흑) | 패널이 3D 보다 파랗게 뜸 |

편집 도구라 화려함보다 차분 · 촘촘이 맞고, 그림자 없이 선으로 구분해 패널이 많은 화면에서 덜 시끄러워 Linear 계열을 골랐다(2026-10-15 PM). 토큰만 바꿔서는 작은 글자 · 작은 클릭 영역 · 툴바 무게가 풀리지 않아 척도 · 컴포넌트 · 상태 규칙(A3~A5)을 따로 정했다.

**시스템 시험.** A3~A5 규칙을 시험 CSS(`system.css` + Linear 토큰 + `fixes.css`)로 앱 위에 얹어 다시 쟀다. 대상 NBU Medical Clinic(건축 + HVAC)과 성수(건축 + 기계), 1440px.

| 측정 | 원본 | 시험 시스템 |
|---|---|---|
| 단추 모양 수 — 보기 / 편집 | 31 / 39 | 27 / 31 |
| 단추 높이 종류 — 보기 / 편집 | 16 / 19 | 9 / 9 |
| 12px 미만 글자(보기 · 편집) | 73 · 75 | 3 · 7 |
| 눌림 반응(`:active`) | 0 | 눌러지는 컴포넌트 전부 |
| 호버가 없던 컴포넌트 | 모드 스위치 · 접기 머리 · 진단 칩 · 편집 대상 | 0 |
| 포커스 고리 | 브라우저 기본 | 2px accent(다크 밝은 accent) |
| axe 색 대비 위반 (Clinic: 라이트 · 다크 × 보기 · 편집) | 1 · 1 · 1 · 3 | 0 · 0 · 0 · 0 |
| axe 색 대비 위반 (성수) | 2 · 1 · 2 · 3 | 1 · 0 · 1 · 0 |
| 남은 axe | 경고 영역 키보드 스크롤 불가, 미배치 링크 24px 미만 | 경고 영역(소스 `tabindex` 필요), `target-size` 해석 불확실, 성수 `.aux` 1곳 |

- 덧입히기로는 모양 수가 크게 줄지 않았다(31→27). 같은 컴포넌트가 여러 클래스로 따로 구현돼 있어, 개발 앱에 옮길 때는 소스 클래스를 합쳐야 한다. 값이 얼마나 움직이는지는 [`TOKEN-MAP.md`](prototype/design-audit/TOKEN-MAP.md)(글자 선언 266개 중 95% 가 ±1px 안).
- 색 대비는 `--muted` 상향, 켠 칸 글자를 `--on-accent` 로, 계통 칩 `small` 을 본문색으로 바꿔 풀었다.
- 옮길 때 권하는 순서: 단추 한 벌(크기 2 × 위계 3) → 입력 한 벌(네이티브 체크박스 · 숫자 입력부터) → 배지 한 벌(`.src` · `.issue-code` · `kbd` 를 12px 이상) → 카드 · 오버레이 그림자 → 표 밀도.
- 한계: 컴포넌트 계측은 Clinic 만, 성수는 상태 · axe · 스샷만 돌렸다. 시험 CSS 는 `!important` 덮어쓰기라 실제 소스 치환과 결과가 다를 수 있다. 호버 · 눌림의 "느낌" 은 눈으로 보지 않았다.
