# OE-INT-01 데이터 교환 방식 결정

## 관련 티켓

- [OE-COM-05](../E01-COM/OE-COM-05.md): 잠금 소재지
- [OE-WF-01](../E14-WF/OE-WF-01.md): 임시 저장 소재지
- [OE-WF-10](../E14-WF/OE-WF-10.md): 반영 소재지
- [OE-WF-18](../E14-WF/OE-WF-18.md): 버전 소재지

## 요구사항
> User story : 구축 담당자와 DT 개발팀은 에디터 결과를 DT로 넘기는 데이터 교환 방식(파일 내보내기와 가져오기, 온톨로지 서버 API, 공유 DB)을 개발 구현에 맡긴다. 기획은 방식을 정하지 않고 사용자가 보는 동작만 요구한다. 잠금·임시 저장·반영·버전이 어디에 저장될지는 개발이 구현 상황에 맞춰 정하며, 사용자 입장에서는 어느 방식이든 [임시 저장]·[반영하기]·버전 히스토리가 같은 화면과 같은 동작으로 보여야 한다. 편집 기능과 화면 개발은 저장 방식과 분리해 진행할 수 있어야 한다.

에디터와 DT 의 데이터 교환 방식(D-INT) — ① 파일 export→DT import, ② 온톨로지 서버 API, ③ 공유 DB — 은 개발 구현에 맡긴다(2026-10-14 결정). 서버가 필요한 방식을 쓸지, 서버를 새로 둘지도 개발이 판단한다. 잠금(OE-COM-05)·임시 저장(OE-WF-01)·반영(OE-WF-10)·버전(OE-WF-18)의 저장 위치도 개발이 정한다. 사용자에게 보이는 동작은 저장 위치와 무관하게 같아야 한다(S6).

## 수용 기준

- **AC1** 데이터 교환 방식과 저장 위치가 어느 쪽이든 [임시 저장]·[반영하기]·버전 히스토리가 같은 화면과 같은 동작으로 보인다.
