# OE-BIM-16 검토 화면 — 등급 칩

## 요구사항

검토 화면 위에 등급 칩 5개를 보인다 — 공간·설비·소속·연결망·방향(PRD 1.8). 파일 목록의 칩과 파일을 열었을 때의 칩은 같은 임포터로 계산해 수치가 같다.
게이트(0~2)는 BIM+계산만으로, 목표선(3·4)은 사전 포함·미포함 두 수치를 병기한다(D12 권고안). 산식은 OE-REQ-04.

## 수용 기준

- 파일 목록의 등급 수치와 파일을 연 뒤 검토 화면의 수치가 같다.
- 등급 3·4 칩에 두 수치가 병기된다.

## 검증 (이 repo)

- `scripts/check-sample.test.ts` "파일 목록의 등급 칩": 가진 BIM 마다 칩 다섯 개의 수치
- `scripts/check-sample.test.ts` "목록의 칩과 파일을 연 뒤의 칩이 같다 — 읽을 것 옵션을 바꿔도": 서버 목록(`data-catalog.ts`)과 열람(워커 + 규칙 방향) 수치가 같다
- `src/lib/profile.test.ts` "설비 파일은 칸마다 빠진 만큼 분수로 보인다": 방향 칩이 `2/3 → 3`(포트·확정 → 확정 전 규칙 포함)
- `e2e/data-list.spec.ts` "등급 응답의 모양이 달라도 목록이 멈추지 않는다"
- 화면: `docs/figures/app-tier-direction-two.png` (Duplex MEP 의 방향 칩 `0/27 → 23`)

## 메모

- 칩 다섯은 공간·설비·소속·연결망·방향이고, 목록과 열람이 같은 `profileOf`(`src/lib/profile.ts`)로 잰다.
- 방향(등급 4) 칩은 두 수치를 같이 보인다: 포트 + 사람이 확정한 규칙 방향 → 확정 전 규칙 방향까지 넣은 기기 수(예 Duplex MEP `0/27 → 23`).
  칩 색은 앞 수치(내보내는 것과 같은 기준)로 정한다. 확정 전 규칙이 더하는 것이 없으면 수치 하나다.
- 연결망(등급 3) 칩의 두 번째 수치는 아직 없다. 등급 3 지표(계통 소속 기기)는 사전이 채우는 몫이 없어(성수 60% (BIM 60%)) PRD 1.8 의
  "97%(사전 포함)" 과 맞지 않는다. 산식은 D12·OE-REQ-04 결정 후에 맞출 예정이다.
