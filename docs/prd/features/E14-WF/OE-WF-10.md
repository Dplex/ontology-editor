## 요구사항

### User story

고객사 관리자가 레이아웃 변경을 마치고 [반영하기]를 누르면 DT 3D 맵과 온톨로지에 한 번에 반영되어 관제 화면과 AI Agent 답변이 동시에 새 레이아웃을 따른다. 온톨로지 반영이 실패하면 DT 반영도 전체 취소되어 '3D에서는 바뀌었는데 Agent는 옛 방 이름을 말하는' 불일치가 생기지 않는다. 반영 후 새 버전이 만들어지고 배너·GNB 알림이 나가며, 처리 시간 목표는 10분 이내다. 반영 경로(파일·API·DB)는 D-INT에 따르지만 사용자 관점에서는 버튼 한 번으로 3D 맵·온톨로지·버전·알림이 모두 처리되어야 하며, 반영 중에는 진행 상태가 보여 실패 시 어느 단계였는지 안다.

[반영하기] 는 편집 내용을 DT 3D 맵과 온톨로지에 한 번에 반영한다. 둘 중 하나만 반영된 상태를 만들지 않는다 — 온톨로지 반영이 실패하면 DT 반영도 전체 실패로 처리하고 반영 전 상태로 되돌린다(OE-SYNC-02, KPI_1).
반영이 끝나면 새 버전을 만들고(OE-WF-13) 배너·알림을 보낸다(OE-WF-15·16). 처리 시간 목표는 10분 이내다(KPI_3). 반영 경로는 D-INT.

## 수용 기준

- 온톨로지 반영 실패 시 DT 3D 맵이 반영 전과 같다.
- 반영 성공 시 버전 히스토리에 새 버전이 1개 생긴다.
