# OE-WF-10 반영하기

## 관련 티켓

- [OE-SYNC-02](../E15-SYNC/OE-SYNC-02.md): DT·온톨로지 부분 반영 금지
- [OE-WF-13](./OE-WF-13.md): 반영 후 새 버전 생성
- [OE-WF-15](./OE-WF-15.md): 반영 완료 배너
- [OE-WF-16](./OE-WF-16.md): 반영 GNB 알림
- [OE-INT-01](../E20-INT/OE-INT-01.md): 반영 경로 결정
- [OE-GEN-01](../E08-GEN/OE-GEN-01.md): 초기 구축의 [구축하기]

## 요구사항
> User story : 고객사 관리자가 [반영하기]를 누르면 편집 내용이 DT 3D 맵과 온톨로지에 한 번에 반영된다. 둘 중 하나만 반영된 상태는 만들어지지 않으며, 온톨로지 반영이 실패하면 DT 반영도 전체 실패로 처리되어 반영 전 상태로 돌아간다. 반영이 끝나면 새 버전이 만들어지고 배너와 알림이 나간다. 사용자는 관제 화면과 AI Agent 답변이 동시에 새 레이아웃을 따르는 것을 기대할 수 있어야 하며, 3D에서는 바뀌었는데 Agent는 옛 방 이름을 말하는 불일치를 겪지 않는다. 반영 처리 시간에는 목표가 있고 반영 경로는 데이터 교환 방식 결정에 따른다.

[반영하기] 는 편집 내용을 DT 3D 맵과 온톨로지에 한 번에 반영한다. 둘 중 하나만 반영된 상태를 만들지 않는다 — 온톨로지 반영이 실패하면 DT 반영도 전체 실패로 처리하고 반영 전 상태로 되돌린다(OE-SYNC-02, KPI_1).
반영이 끝나면 새 버전을 만들고(OE-WF-13) 배너·알림을 보낸다(OE-WF-15·16). 처리 시간 목표는 10분 이내다(KPI_3). 반영 경로는 D-INT.
[반영하기]는 운영 편집에만 있다. 초기 구축에는 층별 반영이 없고 DT 등록은 [구축하기]로 사이트 단위로 한다(OE-GEN-01).

## 수용 기준

- **AC1** 온톨로지 반영 실패 시 DT 3D 맵이 반영 전과 같다.
- **AC2** 반영 성공 시 버전 히스토리에 새 버전이 1개 생긴다.
