# OE-REQ-03 어휘 표와 이름 사전

## 요구사항
> User story : 구축 담당자는 BIM에서 설비 종류·계통·용량·공간 용도를 읽는 기준이 두 가지로 나뉘어 있음을 확인할 수 있다. IFC 표준이 뜻을 정한 값은 어휘 표로 바로 확정되고, 고객사가 사이트 관행에 따라 붙인 설비·물리존·계통 이름은 이름 사전에서 후보로 제안된 뒤 사람이 확인해야 확정된다. 임포터와 고객사 검사 파일이 같은 어휘 표를 쓰므로 고객사가 검사 파일로 통과한 값을 에디터가 못 읽는 일이 없고, 새 고객사 BIM에서 반복되는 이름은 이름 사전에 쌓여 다음 구축의 수동 작업이 줄어든다. 사용자는 어떤 값이 표준에 따라 확정된 것이고 어떤 값이 이름으로 추정된 후보인지 구별할 수 있어야 한다.

### 어휘 표와 이름 사전의 정의 구분

| 구분 | 어휘 표 | 이름 사전 |
|---|---|---|
| 한 줄 정의 | IFC 표준이 정한 값 → 내부 의미 | 고객사가 BIM에 붙인 이름 → 내부 의미 후보 |
| 목적 | 표준을 지킨 BIM을 빠짐없이, 같은 뜻으로 읽는다. 에디터와 고객사 검사 파일(IDS)의 판정 기준을 하나로 맞춘다. | 표준 칸이 비었거나 다른 칸에 적힌 BIM에서, 반복되는 현장 이름으로 종류·용도를 보완 제안한다. |
| 담는 것 | 지원 IFC 스키마별 클래스, PredefinedType, USERDEFINED/ObjectType 값, Pset 속성 이름, 단위, 그리고 이들과 내부 종류·계통·용량 필드의 의미 연결 | BIM에서 관측한 설비·패밀리/유형·방(물리존)·계통 이름, 표준 값의 별칭·약어·언어별 표기, 후보 내부 종류, 적용 범위(사이트·파일·패밀리), 관측 값·예시·출처, 확인 상태·확인자·버전 |
| 근거 | IFC 표준과 내부 온톨로지 정의 | 실제 고객사 BIM 관측 |
| 확정 여부 | 일치하면 바로 확정 | 후보. 사용자 확인 후 확정. 미확인·모호 후보는 자동 적용하지 않는다 |
| 함께 쓰는 곳 | 임포터, 고객사 검사 파일(IDS), 요구사항 R 번호 | 임포터의 보완 제안, 검토·보정 화면 |
| 바뀌는 때 | 지원 스키마·내부 필드가 바뀔 때. 바뀌면 임포터와 IDS가 함께 바뀐다 | 새 고객사 BIM에서 새 이름이 관측되거나 사용자가 후보를 확인할 때 |
| 출처 표시 | BIM | 사전 |

### 서로 간의 관계
- 같은 관리 기준 안에서 연계하되, 확정 어휘(어휘 표)와 후보 매핑(이름 사전)을 섞지 않는다.
- 이름 사전의 후보 내부 종류는 어휘 표·내부 온톨로지에 정의된 종류 중에서만 가리킨다. 고객사 BIM에서 많이 관측되었다는 이유로 새 표준 어휘가 되지 않는다.
- 임포트 판정 순서: BIM 표준 값(어휘 표) 우선 → 누락 시 이름 사전 제안 → 사용자 확인 후 확정.

### 공통 원칙
- 관측 이름을 수집한 사실은 매핑 확정을 뜻하지 않는다.
- 사전 항목이 있다는 이유로 BIM 값이나 사용자 보정을 덮어쓰지 않는다.
- 용량 관련 이름은 속성 이름 매핑에만 쓰고, 이름에서 수치 용량을 만들어내지 않는다.
- 새 고객사에서 기존 사전 항목을 재사용할 때 적용 범위와 근거를 확인한다.
- 원본 명칭은 바꾸지 않고 유지한다.

## 수용 기준
- 어휘 표 기준으로 확정된 값과 이름 사전 후보가 출처(BIM / 사전)로 구분되어 보인다.
- BIM 표준 값·관측 이름·후보 매핑·사용자 확인을 구분해 조회할 수 있고 원본 명칭이 유지된다.
- 어휘 사전 항목이 있다는 이유만으로 BIM 값이나 사용자 보정을 덮어쓰지 않는다.
- 같은 이름의 복수 후보와 사이트·패밀리 범위가 구분되며, 사용자 확인 전에는 수치 용량·확정 종류를 만들지 않는다.
- 임포터와 IDS의 표준 어휘·R 번호가 일치한다. 어긋나면 테스트가 실패한다.
