## 요구사항
> User story : 구축 담당자와 고객사 관리자는 에디터의 어느 자리에서든 같은 색은 같은 뜻으로, 같은 모양의 부품은 같은 동작으로 읽을 수 있다. 강조색은 선택과 주 동작, 주황은 저장하지 않은 변경과 임시 저장본, 빨강은 삭제와 종료처럼 색 하나에 뜻 하나가 정해져 있고, 물리존·커스텀존·공조존은 상태 색과 겹치지 않는 분류 색으로 3D·평면도·목록에서 같게 보여 처음 보는 도구도 색과 모양으로 무엇을 하는지 짐작한다. 3D 가 잘 보이도록 에디터는 어두운 화면이 기본이다. 기획·UX·개발이 같은 토큰과 부품 이름으로 말해 화면마다 다르게 만들어지는 일이 없다.

에디터 화면(초기 구축 ③ · 운영 편집)의 디자인은 두 층이다. 공통 토큰·척도·컴포넌트 상태·모션은 OE-UI-23 을 따르고(정본 [design-audit/DESIGN.md](../../prototype/design-audit/DESIGN.md)), 이 티켓은 그 위에 에디터에만 있는 것을 더한다. 값과 규칙의 정본은 [디자인 시스템](../../design-system.md)이다.
- 에디터는 공통 토큰의 다크 값을 기본으로 쓴다.
- 의미 색 — 선택·주 동작은 공통 강조색, 정상(운영 편집·생성 가능·임시 저장됨)은 에디터가 더하는 정상 색, 주의(저장 안 된 변경·임시 저장본·변경됨·경고)와 위험(삭제·종료·막힘)은 공통 경고·오류 색. 같은 색을 장식으로 쓰지 않는다.
- 존 분류 색 — 물리존·커스텀존·공조존(OE-UI-16)은 상태 색과 겹치지 않는 분류 색으로 3D·평면도·목록 점·레이어 체크에서 같게 쓰고, 상태를 알리는 데 쓰지 않는다. 물리존 칠하기(OE-UI-26)가 켜진 동안은 물리존 분류 색 대신 범례 색을 쓴다.
- 화면 뼈대는 OE-UI-04 의 네 영역에 안내 바·상태줄(OE-UI-18)과 캔버스 위 패널(OE-UI-19 · OE-UI-20)을 더한 것이다. 영역마다 크기와 무엇을 두는지는 디자인 시스템 4장.
- 에디터 전용 부품(도구 레일의 도구 · 목록 행 · 뜨는 패널 · 토스트 · 우클릭 메뉴(OE-UI-21) · 안내 바 · 상태줄 · 변경 태그(OE-UI-22))도 공통 상태 규칙(호버·눌림·포커스·비활성)과 12px 하한을 따른다.
- 미리 강조(커서 아래 골라질 것, OE-UI-27)는 고른 것의 강조와 구별되는 옅은 강조색을 쓴다.
- 비활성 버튼·도구에는 이유를 툴팁으로 보인다(OE-UI-03 공통 규칙). 출처는 출처 칩으로 보인다(OE-UI-13).
- 와이어프레임의 릴리스 꼬리표(R1·R2)는 기획 검토용이라 제품 화면에 넣지 않는다.

## 수용 기준

- **AC1** 에디터 화면의 색·글자 크기·간격·컨트롤 높이가 공통 토큰(OE-UI-23)과 디자인 시스템의 에디터 확장 값으로만 이루어진다.
- **AC2** 의미 색(강조·정상·주의·위험)이 디자인 시스템 2.2 의 뜻 밖으로 쓰인 곳이 없고, 존 분류 색이 상태 표시에 쓰인 곳이 없다.
- **AC3** 물리존·커스텀존·공조존이 3D·평면도·목록·레이어 패널에서 같은 색으로 보인다.
- **AC4** 에디터 전용 부품에도 12px 미만 글자와 24px 미만 버튼이 없다.
- **AC5** 미리 강조와 고른 것의 강조가 3D · 평면도에서 서로 다르게 보인다.
