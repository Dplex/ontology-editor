# OE-UI-23 화면 디자인·모션 기준

## 관련 티켓

- [OE-UI-04](./OE-UI-04.md): 화면 레이아웃 — 3D·패널·도구 팔레트·액션바의 자리. 이 티켓은 그 자리의 모양을 정한다
- [OE-UI-13](./OE-UI-13.md): 출처 표시 — BIM·계산·사전 배지의 글자 크기 하한을 이 티켓이 정한다
- [OE-UI-15](./OE-UI-15.md): 초기 구축 화면 흐름 — 시작 화면·열람 화면이 같은 토큰을 쓴다

## 요구사항
> User story : 구축 담당자는 BIM 을 열고 검토하고 고치는 동안 글자를 읽기 위해 눈을 찌푸리지 않고, 지금 해야 할 일(보기/편집, 구축하기)이 어디인지 바로 보며, 숫자가 굴러오거나 번쩍이는 동안 기다리지 않는다.

화면의 모양(색·글자·모서리·구분선)과 모션을 한 기준으로 묶는다. 기능·화면 구성은 바꾸지 않고, 같은 기능을 읽기 쉽고 덜 시끄럽게 보이는 방법을 정한다. 기준(토큰·척도·컴포넌트·상태·모션)은 [디자인 시스템](../../design-system.md) A1~A7 이 정본이고, 진단·후보 비교·시험 결과는 그 부록에 있다. 개발 앱을 잰 시험 코드(`themes.ts`·`fixes.css`·`layout.css`·`system.css`)와 개발 앱으로 옮길 때 쓰는 자료(지금 값이 척도로 얼마나 움직이는지 `TOKEN-MAP.md` · 줄일 모션 목록 `MOTION.md`)는 `docs/prd/prototype/design-audit/` 에 있다.

**1. 시각 기준.** 차분하고 촘촘한 편집 도구 성격으로, 색은 중립을 쓰고 강조색은 한 가지(인디고)만 쓴다. 카드·패널은 그림자 없이 1px 선으로 나누고, 그림자는 3D 위에 뜬 독·팝오버에만 쓴다. 후보 3종(Linear·Vercel·Stripe 계열)을 같은 화면에 입혀 비교해 Linear 계열로 정했다(2026-10-15 PM). 구체적 토큰값(라이트·다크)은 디자인 시스템 A2 가 정본이다.

**2. 글자와 클릭 영역.** 화면의 글자는 12px 이상이다(출처 배지 · `kbd` 단축키 표시 · 범례 포함). 지금은 17가지 크기(9.36~16.8px)가 섞여 12px 미만이 약 70곳이다(Duplex 열람 화면 기준). 버튼·링크는 24×24px 이상으로 눌린다. 편집에서 자주 쓰는 도구는 32px 이상을 권한다.

**3. 상단 툴바 위계.** 보기/편집 전환과 경고 칩만 테두리를 둔 주 요소로 보이게 하고, 열기·읽을 것·덧붙이기·내보내기·도움말·테마는 테두리 없는 보조 요소로 낮춘다. 편집 막대에서는 구축하기(반영하기)가 색을 채운 주 요소다(채움 > 선 > 글자 3단 위계).

**4. 모션.** 자주 하는 동작(편집·선택·단축키)에서는 기다리게 하는 움직임을 빼고, 처음 한 번만 보는 움직임만 길게 둔다. 구체적으로 숫자 굴림은 화면에 처음 들어올 때만 300ms 이하로 하고 편집으로 바뀔 때는 값만 바꾼다. 바뀐 줄 번쩍임은 0.8초 이하로 하고, 진행 막대는 줄마다 지연 없이 0.3초 이하로 채운다. 목록 선택으로 일어나는 스크롤 이동은 즉시 간다. `transition: all` 은 쓰지 않고 바뀌는 속성만 적는다. 주요 버튼에는 눌림 반응(약 0.97배, 100ms 이하)을 둔다. 움직임 끄기(`prefers-reduced-motion`)를 켠 사용자에게는 이동·확대만 끄고, 바뀐 줄의 배경색 변화는 남긴다. 리플레이(편집 이력 보여주기)는 사용자가 일부러 보는 모드라 이 기준의 시간 한도에서 뺀다.

**5. 확인 방법.** 기준은 화면 캡처와 접근성 검사로 지킨다 — Duplex · 큰 파일(성수) · 1440/1024px · 라이트/다크 · 보기/편집 조합을 Playwright 스크린샷 기준선과 axe(WCAG 2.2 AA)로 돌려, 디자인을 바꾸는 변경마다 전후 차이를 본다.

**범위 밖.** 모바일·태블릿 폭(1024px 미만) 대응은 이 티켓에서 다루지 않는다(2026-10-15 결정). 진단에서 390px 폭의 가로 넘침(열람 883px · 편집 1287px)과 3D 영역 문제가 확인됐고 시험용 CSS(`layout.css`)로 해결 가능성을 보았으나, 모바일 사용이 R1 요구인지 근거가 PRD 에 없어 뺐다. 3D 장면 색(벽 회색·위반 분홍)은 Three.js 재질이라 따로 정한다. 서체는 사내망에서 웹폰트를 받을 수 있는지 몰라 시스템 글꼴을 유지한다. 3D 카메라 이동의 시간과 리플레이의 건너뛰기·모션 끄기 동작은 아직 확인하지 않았다.

## 수용 기준

- **AC1** 라이트·다크 모두 본문·보조 글씨·강조색·버튼 글씨의 대비가 4.5:1 이상이다. 자동 접근성 검사(axe, WCAG 2.2 AA)의 위반이 0건이다.
- **AC2** 시각 토큰이 디자인 시스템 A2 의 값(배경·면·글씨·선·강조색·모서리)을 따른다. 카드·패널은 그림자 없이 선으로 나뉘고, 그림자는 3D 위에 뜬 독·팝오버에만 있다.
- **AC3** 열람·편집 화면에서 보이는 글자 중 12px 미만이 없다(출처 배지·`kbd`·범례 포함).
- **AC4** 버튼·링크는 모두 24×24px 이상이다(체크박스는 이름표 글자까지 눌리는 영역으로 센다).
- **AC5** 상단 툴바에서 테두리가 있는 요소는 보기/편집 전환과 경고 칩뿐이고, 나머지는 테두리 없는 글자 버튼이다. 편집 막대에서 구축하기(반영하기)는 색을 채운 주 단추이고 나머지 단추는 선 또는 글자 단추다.
- **AC6** 숫자 굴림은 화면에 처음 들어올 때만 일어나고 300ms 이하다. 편집으로 값이 바뀔 때는 굴리지 않고 값만 바꾼다. 바뀐 줄 번쩍임은 0.8초 이하, 진행 막대 채움은 줄마다 지연 없이 0.3초 이하다.
- **AC7** 목록·표에서 항목을 골라 일어나는 스크롤 이동은 즉시 간다. 코드에 `transition: all` 이 없다.
- **AC8** 주요 버튼(구축하기·보기/편집·툴바 알약·팔레트 버튼)은 누르는 동안 0.97배 안팎으로 줄고 100ms 이하로 돌아온다.
- **AC9** 움직임 끄기를 켜면 이동·확대 애니메이션이 없고, 바뀐 줄의 배경색 변화는 남는다.
- **AC10** 키보드로 이동할 때 모든 누르는 컴포넌트와 입력에 보이는 포커스 고리가 있다(2px 안팎, 바탕과 대비 3:1 이상, 라이트·다크 모두). 지금은 브라우저 기본 1px 고리(거의 검정)라 다크에서 약하다.
- **AC11** 누르는 컴포넌트는 호버·눌림·포커스·비활성 상태가 서로 구별된다. 비활성은 투명도 값 하나로 같고 브라우저 기본 단추에도 적용된다. 지금은 모드 스위치·접기 머리·진단 칩·편집 대상 단추에 호버 변화가 없다.
- **AC12** AC1~AC5 · AC10~AC11 을 Duplex·큰 파일 × 1440·1024px × 라이트·다크 × 보기·편집 조합의 스크린샷 기준선과 axe 검사로 확인하고, 디자인을 바꾸는 변경은 전후 스크린샷 차이를 낸다.
