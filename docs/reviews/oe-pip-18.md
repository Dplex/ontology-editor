## 구현한 것
요구사항은 "흐름 없는 기기가 형상 접촉으로 연결되는 것 방지 — 재현율과 함께 측정 후 결정" 이다. **측정한 뒤 제외하기로 했다**(ADR-0010).

포트가 없는 파일은 메시가 맞닿은 요소를 연결로 추정하고 고립된 요소는 50mm 까지 범위를 넓혀 연결하는데(`topology.ts`), 여기에 모든 설비가 들어가 있었다.
`import.ts` 에서 **종류를 아는 흐름 없는 기기**(`kinds.ts` 의 `flow: {}` — 조명·콘센트·감지기·CCTV·거울·소화기함·분전반 등)를 형상
추정과 범위 확장 연결에서 제외했다. 종류를 모르는 기기는 그대로 포함한다.

**재현율**: 포트가 있는 파일 3개에서 포트를 가리고 형상으로만 추정해, 포트 연결을 정답으로 비교했다. 제외해도 결과가 같다 — 포트가 흐름 없는
기기를 연결하는 경우가 없기 때문이다.

| 파일 | 포트 연결 | 정밀도 (포함 → 제외) | 재현율 (포함 → 제외) |
|---|---|---|---|
| 병원 HVAC | 3,693 | 99.9% → 99.9% | 87.8% → 87.8% |
| Duplex HVAC | 485 | 95.3% → 95.3% | 70.9% → 70.9% |
| ifc4Mep | 1,995 | 79.5% → 79.5% | 75.0% → 75.0% |

**빠진 연결**(형상 추정을 실제로 쓰는, 포트 없는 파일):

| 파일 | 연결 | 빠진 것 |
|---|---|---|
| 병원 건축 + MEP | 13,890 → 13,608 | 283개 — 대부분 천장 조명 ↔ 디퓨저(범위 확장 연결이 디퓨저를 옆 조명에 연결했다), 조명끼리 16쌍, 콘센트끼리·콘센트 ↔ 전선관, 욕실 부속끼리. 대신 디퓨저 ↔ 덕트 이음쇠 1개가 새로 연결됐다 |
| 병원 전기 | 16 → 0 | 나란히 붙은 조명기구 16쌍 |
| Duplex MEP | 785 → 783 | 조명 ↔ 위생기구 2 |
| 병원 건축 | 2 → 0 | 욕실 부속끼리 |

디퓨저 수백 개는 유일한 연결 상대가 조명이었다 — 덕트에 닿은 적이 없는데 "연결됨" 으로 보였다. 완전성 검사의 "연결망에 든 기기" 가
병원 건축+MEP 에서 850 → 849/884 로 바뀐 것이 그 결과다(조명에만 연결돼 있던 말단 하나). 규칙 방향(일치 3,670 등)은 어느 파일도 바뀌지 않았다.

임포트 경고도 바뀐다 — "연결이 없던 설비" 에 흐름 없는 기기를 포함하지 않는다. Duplex MEP: 224대 중 121대 → **141대 중 119대**(연결하지 못한 22대는 그대로).
병원 MEP: 2,551대 중 745대 → 516대 중 464대(연결하지 못한 것 51 → 52).

저장 위치: 형상으로 추정한 연결은 방향이 없으면 TTL 에 들어가지 않고(기존 동작), GeoJSON·3D 의 연결망 표시와 완전성 검사·흐름 추적에 쓰인다.
흐름 없는 기기는 이제 어디에도 형상 연결이 없다.
