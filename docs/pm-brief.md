# BIM 기반 DT 온톨로지 구축 범위

기준일: 2026-09-29 · 정본: `docs/bim-to-dt-ontology.md`(등급·요구사항은 정본 기준)

## 용어

BIM·파일

| 용어 | 뜻 |
|---|---|
| BIM | 건물을 3D 객체와 속성으로 만든 설계 모델. 벽·방·설비가 각각 객체로 들어 있음 |
| Revit · ArchiCAD | BIM을 만드는 저작 도구. 확보한 파일은 대부분 Revit에서 나옴 |
| IFC | BIM을 도구와 상관없이 주고받는 표준 파일 형식. IFC2x3(구버전)과 IFC4(신버전)가 있음 |
| 건축 BIM · 설비(MEP) BIM | 같은 건물이라도 분야별로 따로 만든 파일. 건축에는 층·방·벽이, 설비(MEP: 기계·전기·배관)에는 설비·덕트·배관이 있음 |
| 패밀리 | Revit에서 같은 모양·용도의 객체를 묶는 단위(예: "FCU 천장형"). 크기별 유형이 여럿 들어 있음 |
| Proxy | 종류를 지정하지 않고 내보낸 객체. 파일만 봐서는 무슨 설비인지 알 수 없음 |
| `PredefinedType` | IFC에서 객체 종류를 적는 표준 칸(예: 에어 터미널 중 디퓨저인지 그릴인지) |
| GUID | 객체마다 붙는 고유 id. 새로 만드는 온톨로지의 id로 그대로 씀 |
| 좌표계 · 원점 | 모델 좌표의 기준. 건축·설비 파일의 기준이 다르면 설비가 엉뚱한 방에 놓임 |
| 배치점 | BIM에 적힌 객체의 위치 좌표. 실제 형상과 떨어져 있는 경우가 있어 형상 중심으로 보정함 |
| 개구부 | 벽에 뚫린 문·창 자리 |
| 공간 경계 | 방을 둘러싼 벽·문을 BIM이 직접 적어 둔 정보. 어느 문이 어느 방 둘을 잇는지 알 수 있음 |
| LOD | BIM의 상세 수준. 300은 설계대로의 정확한 크기·위치, 400은 제조사·용량 정보까지 포함 |
| OmniClass | 방 용도 분류 코드 표준(예: 사무실, 화장실) |
| IDS | 요구사항을 기계가 읽을 수 있게 적는 파일 형식(buildingSMART 표준, Information Delivery Specification). 무엇을 요구할지는 각 프로젝트가 정하고, IDS는 그것을 담는 형식. 검사 도구(ifctester, Solibri 등)에 IFC 파일과 함께 넣으면 지켰는지 자동으로 확인됨 |

설비

| 용어 | 뜻 |
|---|---|
| 기기 | 공조기·FCU·토출구·밸브·센서처럼 역할이 있는 장비 |
| 도관 | 덕트·배관과 이음쇠. 설비 객체의 대부분(약 85%)이 도관 |
| 공조기(AHU) · FCU · VAV | 공조기는 건물에 공기를 공급하는 대형 장비, FCU는 방마다 두는 소형 냉난방기, VAV는 방으로 가는 풍량을 조절하는 장치 |
| 토출구 · 말단 | 공기가 방으로 나오는 끝단(디퓨저, 그릴 등). 흐름의 끝에 있는 기기를 말단이라 부름 |
| 원천 기기 | 흐름이 시작되는 기기(공조기, 보일러, 펌프 등) |
| 계통 | 공조기 → 덕트 → 토출구처럼 하나의 흐름으로 묶인 설비 묶음(예: 3층 급기 계통) |
| 포트 | 설비끼리 이어지는 접속구. 덕트·배관이 기기에 꽂히는 입구·출구에 해당. BIM에는 어느 포트끼리 연결되어 있는지와, 공기·물이 나가는 쪽(SOURCE)인지 들어오는 쪽(SINK)인지를 적을 수 있음 |
| 흐름 방향 · 상류 · 하류 | 공기·물이 흐르는 방향. 흐름을 거슬러 올라간 쪽이 상류(공조기 쪽), 따라 내려간 쪽이 하류(토출구 쪽) |

온톨로지·DT

| 용어 | 뜻 |
|---|---|
| 온톨로지 | 공간·설비·관제점 사이의 관계(어디에 있다, 무엇에 공급한다 등)를 적은 데이터. DT가 이것을 읽어 화면과 기능을 만듦 |
| Brick · TTL | Brick은 건물 온톨로지의 표준 어휘, TTL은 그 어휘로 쓴 파일 형식 |
| GeoJSON | 방 외곽선·설비 좌표 같은 도형을 담는 파일 형식. 온톨로지(TTL)와 id로 연결 |
| 물리존 | 방 하나. BIM의 공간(`IfcSpace`) 하나에 해당 |
| 공조존 | 같은 공조 설비가 담당하는 구역. 여러 방이 하나의 공조존에 들 수 있음 |
| 커스텀존 | 운영자가 직접 그려 지정하는 구역 |
| 관제점 | BAS가 측정·제어하는 값 하나(예: 3층 회의실 온도) |
| BAS | 건물 자동제어 시스템. 관제점 목록과 실시간 값을 가짐 |

이 문서에서 쓰는 말

| 용어 | 뜻 |
|---|---|
| 피처 | DT가 온톨로지에서 필요로 하는 정보 항목(예: 설비가 속한 방) |
| 등급 | 이 BIM으로 온톨로지를 어디까지 만들 수 있는지를 0~5로 나눈 것(1장) |
| 이름 사전 · 사전 | 객체 이름(예: "FCU3", "라인디퓨저")으로 종류를 알아내는 규칙 모음. 도메인 지식을 담음 |
| 규칙 방향 | 포트에 방향이 없을 때 계통·설비 종류로 추정한 흐름 방향 |
| 에디터 | 이 과제에서 만든 도구. BIM을 읽어 온톨로지를 만들고, 빠지거나 틀린 것을 고침 |
| 번호 | R0~R25는 요구사항, E1~E11은 편집 기능, #N은 PRD 기능 번호 |
| 산출물 | 온톨로지 파일(TTL: 공간·설비의 관계)과 도형 파일(GeoJSON: 방 외곽선·설비 좌표). 두 파일은 같은 id로 연결 |

## 요약

- 필수 요구 11개를 갖춘 BIM이면 등급 0~2(공간 골격, 설비 위치)까지 대부분 자동 생성 가능. 빈 곳은 에디터에서 보완
- 고객사 파일(성수)은 필수 11개 중 6개만 표준 위치에 있었으나 공간 골격·설비 위치·소속이 77~100% 자동 생성. 빈 곳은 외곽선 없는 방 55, 기본 이름 "공간" 42, 방을 그리지 않은 공용부의 설비 571
- 공간 골격(층, 방, 외곽선, 이름, 벽·문·창)은 BIM만으로 생성
- 설비가 속한 방은 계산으로 구함. 건축·설비 파일을 합친 뒤 좌표로 판정
- 설비·계통·방 종류는 BIM에 없는 경우가 많아 이름 사전(도메인 지식)으로 보완
- 흐름 방향은 포트에 방향이 있을 때만 확실. 없으면 규칙으로 추정하고, 사람이 확정한 것만 반영
- 공조존과 관제점은 BIM 밖에서 받음(관제점은 BAS)

BIM 조건에 따른 차이

| 조건 | 있을 때 | 없을 때 |
|---|---|---|
| 건축·설비 파일의 좌표계와 층 이름 일치 | 설비 소속 방 자동 판정 | 오류 없이 소속이 비어 있음 |
| 포트의 흐름 방향 | BIM에서 방향을 그대로 사용 | 규칙으로 추정 후 사람이 확정 |
| 종류·분류를 표준 위치에 기입 | BIM에서 종류를 그대로 사용 | 이름 사전과 수작업으로 보완 |

## 1. 등급

고객사 필수 요구 범위는 등급 0·1·2. 0+와 4+는 권장 항목을 채우면 얻는 확장. 고객사 BIM은 대부분 등급 1~3에 그칠 것으로 예상하며, 등급 4는 포트에 흐름 방향을 넣어 내보낸 파일에서만 나왔음.

| 등급 | 온톨로지에 추가되는 것 | DT 기능 | 필요한 것 |
|---|---|---|---|
| 0 공간 골격 | 층, 방 외곽선, 벽·문·창 | 3D Map, 탐색기 트리 | 건축 BIM |
| 0+ 공간 의미 | 방 종류, 방-문-방 연결 | "회의실" 검색, 로봇 경로 | 방 분류 코드, 공간 경계 |
| 1 설비 목록 | 설비와 좌표 | 3D에 설비 표시 | 설비(MEP) BIM |
| 2 설비 소속 | 설비가 속한 방 | 이상 알림의 발생 위치 | 건축·설비가 같은 좌표계 |
| 3 계통·연결망 | 같은 계통·배관에 이어진 설비(방향 없음) | 계통별 보기 | 계통 정보, 맞닿은 형상 |
| 4 흐름 방향 | 공조기 → 토출구 흐름 | 담당 설비 추적, 상류·하류 조회 | 포트의 흐름 방향 |
| 4+ 담당 공간 | 공조기가 급기를 보내는 방 | 계통도의 담당 공간 | 흐름 방향(포트 또는 확정한 규칙 방향) |
| 5 운영 | 공조존, 관제점 | 계통도, 실시간 값 | BIM 밖 자료(BAS 등) |

## 2. 값의 출처

에디터는 화면의 값마다 출처를 표시함.

| 출처 | 내용 | 정확도 | 온톨로지 반영 시점 |
|---|---|---|---|
| BIM | 파일에 적힌 값 | BIM 품질에 따름 | 임포트 즉시 |
| 계산 | BIM 좌표·형상으로 판정(설비 소속, 연결 추정, 파일 합치기) | 소속 96~97%, 연결 추정 정밀도 약 80% | 임포트 즉시. 단, 형상으로 추정한 연결에는 방향을 넣지 않음 |
| 사전 | 이름 사전·흐름 규칙으로 정한 값 | 규칙 방향과 포트 방향 일치율 84~99% | 종류는 임포트 즉시. 흐름 방향은 사람이 확정한 뒤 |
| 사람 | 에디터에서 지정·확정한 값 | — | 편집 즉시 |
| 외부 | BAS(관제점), 운영자(커스텀존) 등 BIM 밖 자료 | — | 불러온 즉시. BAS 관제점 연결은 아직 없음(6장) |

흐름 방향을 확정 없이 반영하지 않는 이유: 틀린 방향이 들어가면 온톨로지를 쓰는 쪽에서 BIM 값과 추정값을 구별할 수 없음.

## 3. 피처별 채움 비율

확보한 BIM 기준 관찰값이며 보장값 아님. 대부분 Revit 파일이고 고객사 실측 파일은 성수 1건. 근거는 부록 A.

| 피처 | 주 출처 | BIM만으로 | 나머지 |
|---|---|---|---|
| 공간 계층·이름 | BIM | 92~100%(성수는 기본 이름 "공간" 42개) | 사람이 이름 입력 |
| 방 외곽선 | BIM | 89~100% | 사람이 3D에서 그림 |
| 벽·문·창, 개구부 소속 | BIM | 77~100%(성수 개구부 관계 없는 문·창 137개) | 고객사에 요청 |
| 내력벽 | BIM | 도구에 따라 0% 또는 100%(기본값일 수 있음) | "모름"으로 둠 |
| 방-문-방 연결 | BIM, 계산 | 60~90%(성수는 공간 경계가 없어 0%) | 공간 경계가 없으면 문 위치로 계산(성수 44%). 층 사이는 계단실·승강로의 겹친 자리로 계산 |
| 방 종류 | 사전 | 0~20% | 사전 포함 최대 65%, 나머지는 사람 |
| 설비 종류 | BIM, 사전 | 50~80%(성수 1%) | 사전 포함 70~100%, 나머지는 사람(패밀리 단위) |
| 설비 위치 | BIM | 77~100% | 형상 중심으로 보정(계산), 좌표가 없으면 사람이 배치 |
| 계통 소속 | BIM | 30~100%(내보내기 설정에 따라 다름) | 사람 |
| 계통 종류 | 사전 | 거의 0% | 사전 포함 30~90% |
| 설비가 속한 방 | 계산 | 0~99%(설비 파일이 방과 소속을 함께 담은 경우에만) | 건축 파일과 합쳐 좌표로 판정(정확도 96~97%) |
| 연결 | BIM(포트) | 포트가 있으면 100%, 없으면 0% | 형상으로 추정(계산), 방향 없음 |
| 흐름 방향 | BIM(포트) | 포트 방향과 원천 기기가 있으면 약 99%, 없으면 0% | 규칙으로 추정(사전) 후 사람이 확정 |
| 용량 | BIM | 대부분 비표준 위치에 있거나 없음 | 설비 대장 별도 수령 |
| 공조존 | 외부 | IFC에 자리는 있으나 값이 비어 있음 | BIM 밖 자료 또는 사람이 지정 |
| 관제점 | 외부 | 관제점 ID는 IFC에 자리 없음 | BAS |

## 4. 고객사 BIM 요구사항

DT에 필요한 피처와 확보한 BIM 실측을 근거로 우리가 정한 요구사항. 필수 11개, 권장 14개.

| R | 요구 | 구분 | 왜 필요한가(없으면) |
|---|---|---|---|
| R0 | 구문 오류 없는 파일 | 필수 | 파일을 아예 읽지 못함 |
| R1 | 층 이름이 DT 층 표기와 같고, 분야별 파일끼리도 같음 | 필수 | 탐색기 트리의 층 기준. 건축·설비 파일은 층 이름으로만 합칠 수 있음 |
| R2 | 층마다 공간(`IfcSpace`)과 바닥 외곽선. 설비가 놓인 공용부(복도·샤프트·기계실·옥탑)도 공간으로 | 필수 | 방(물리존)이 만들어지지 않음. 3D Map과 설비 소속 판정의 기준. 공간이 없는 자리의 설비는 층까지만 위치를 가짐 |
| R3 | 방 이름·번호(이름은 기본값 "공간"이 아닌 것), 분야별 파일끼리 같은 번호 | 필수 | 탐색기에 표시할 이름이 없고, 파일·판본끼리 같은 방을 맞추지 못함 |
| R4 | 벽·문·창과 개구부 관계 | 필수 | 3D Map의 벽, 로봇 통과 여부, 방-문-방 연결을 만들 수 없음 |
| R5 | 공간 경계 | 권장 | 어느 문이 어느 방 둘을 잇는지 BIM에서 바로 얻음. 없으면 문 위치로 계산 |
| R6 | 길이 단위 선언 | 필수 | 좌표가 1,000배 등으로 틀려도 오류가 나지 않음 |
| R7 | 3D 스캔과 같은 원점·북방향(IFC2x3은 기준점 협의) | 필수 | 온톨로지와 3D 스캔이 통째로 어긋남 |
| R8 | 형상 LOD 300 | 권장 | 계약상 표현. 실제로 필요한 형상 정확도는 R2·R11·R16으로 확인 |
| R9 | MEP 포함 | 필수 | 설비가 하나도 없음 |
| R10 | IFC4 형식 | 권장 | 계통 종류·지도 좌표를 표준 위치에서 읽음. IFC2x3도 등급 0~2는 가능 |
| R11 | 설비마다 위치, 배치점이 형상 위에 있음 | 필수 | 설비가 어느 방에 있는지 판정할 수 없음 |
| R12 | 건축·설비 파일이 같은 좌표계 | 필수 | 설비 소속이 오류 없이 틀림 |
| R13 | 다시 내보낼 때 GUID 유지 | 필수 | id가 바뀌어 DT 쪽 이력·관제점 연결이 끊김 |
| R14 | 방 분류(OmniClass) | 권장 | 방 종류("회의실")를 BIM에서 바로 얻음. 없으면 이름 사전 |
| R16 | 이어진 설비 요소끼리 맞닿음 | 권장 | 포트가 없을 때 형상으로 연결을 추정할 수 있음 |
| R17 | 계통 묶음·이름·종류 | 권장 | 계통별 보기와 흐름 방향 추정의 입력. 없으면 Revit 속성과 이름 사전으로 보완 |
| R18 | 포트 흐름 방향(연결마다 한쪽 이상), 원천 기기 포함 | 권장 | 흐름 방향(등급 4)을 BIM에서 바로 얻음. 없으면 규칙으로 추정 후 사람이 확정 |
| R19 | 공조기와 말단을 같은 계통으로 묶음 | 권장 | 공조기가 담당하는 방을 계산할 수 있음 |
| R20 | 공조존 값 | 권장 | 별도 자료 없이 BIM에서 공조존 확보 |
| R21 | 센서가 측정하는 설비 | 권장 | 관제점이 어느 설비 것인지 연결 |
| R22 | 용량 | 권장 | 용량 검증. LOD 400 정보라 없으면 설비 대장을 따로 받음 |
| R23 | 벽 내력 여부 | 권장 | 내력벽 편집 제한 |
| R24 | Proxy 사용 안 함 | 권장 | 종류를 알 수 없는 설비가 생기지 않음 |
| R25 | 설비 종류(`PredefinedType`, 정해 둔 이름) | 권장 | 설비 종류를 BIM에서 바로 얻음. 없으면 이름 사전 |

구분 기준

- 필수: 등급 0~2(R13은 다시 내보낸 뒤의 id 유지)에 필요하고, 빠지면 복원할 수 없고, 우리 코드가 실제로 쓰는 항목
- 권장: 없어도 등급 0~2는 가능. 빠진 부분은 계산·사전·수작업으로 보완
- R15(방 높이)는 실측 결과 필요 없어 삭제
- R7은 확보한 파일 중 만족한 것이 없음(IFC2x3에는 표준 위치가 없음). 고객사와 기준점을 합의해야 함(6장)

참고

- 요구하지 않는 것: 방 높이, 마감·가구·구조 해석, 관제점 ID·실시간 값(IFC에 없음)
- Revit 기본 설정으로 내보낸 파일에도 권장 항목 값은 대부분 있으나 비표준 위치에 저장됨. 고객사에는 값 입력보다 내보내기 설정 변경을 요청
- 검사: 이 중 속성으로 확인할 수 있는 항목을 IDS 파일(`docs/requirements.ids`)로 옮겨 두어, 고객사가 검사 도구로 납품 전에 직접 확인할 수 있음. 형상이나 파일 간 비교가 필요한 항목(R8, R12, R13 등)은 IDS로 표현할 수 없어 우리가 파일을 열어 확인

## 5. 누락 시 대응

재요청(1안)과 에디터 보완(2안)은 누락 종류에 따라 나눔. 기준은 계산으로 복원 가능한지 여부.

| 누락 | 예 | 대응 |
|---|---|---|
| IFC에 자리가 없는 정보 | 관제점 ID, 실시간 값 | BIM 밖(BAS 등)에서 수령 |
| 필수 요구 | 층 이름, 외곽선, 단위, 좌표계 | 1안. 추측으로 채우면 오류 없이 틀림 |
| 부재 자체 | 배관 사이 이음 부재 없음 | 1안. 계산으로 만들 수 없음 |
| 관계만 | 소속·연결 판정 오차, 좌표 없는 설비, 모르는 종류 | 2안. 계산·사전으로 보완 후 에디터에서 확인 |

## 6. 현재 상태와 다음 할 일

구현된 것(데모에서 확인 가능)

- IFC 임포트(IFC2x3·IFC4), 건축·설비 파일 합치기
- 설비 소속 판정, 형상으로 연결 추정, 규칙 방향 추정과 계통 단위 확정
- 이름 사전으로 설비·방·계통 종류 판정, 화면 값마다 출처 표시
- 종류를 모르는 패밀리에 종류 후보 제안. 이름의 낱말과, 같은 건물에서 계통·이웃·높이가 닮은 패밀리를 근거로 함. 정하는 것은 사람
- 등급 표시, 요구사항 보고서, 판본 비교
- 완전성 검사: 공기 계통(원천-말단), 물 계통(열원-공조기·FCU·방열기), 한쪽 끝만 이어진 덕트·배관(연결망이 끊긴 자리), 소속 방, 연결망
- 편집(E1~E8): 방 이름·경계, 벽·문·창, 설비, 계통·연결. 되돌리기, 편집 파일 저장·불러오기
- 내보내기(TTL, GeoJSON). DT 쪽 파서로 실제로 읽히는지 확인
  - 공조기가 급기를 보내는 방(담당 공간)을 온톨로지에 포함. 포트·사람이 정한 방향·확정한 규칙 방향으로 이어진 것만
  - 계단실·승강로가 위층의 어느 계단실·승강로와 이어지는지 도형 파일에 포함(로봇이 층을 옮길 자리)

결정 필요

- 고객사에 전달할 요구사항 범위, R7 기준점과 R1 층 이름 표기 합의
- DT와의 데이터 교환 방식(PRD 1.7: 파일 / API / 공유 DB). 편집 결과 저장 위치, 이전 판 되돌리기(#19), 편집 잠금(#2)이 이에 따라 정해짐
- BIM GUID와 기존 온톨로지 id의 매핑 방식
- 요구사항 추가 검토: 설비마다 BMS 관제점 ID(또는 설비 태그)를 BIM 파라미터로 넣어 달라고 요청할지. 들어오면 관제점과 설비를 사람이 잇지 않아도 됨. 선행 사례(BIM-to-BRICK, 2025)가 이 방식으로 BIM과 BMS를 이음
- Revit 요소 ID를 온톨로지에 외부 참조로 함께 넣을지. 다시 내보낸 BIM에서 GUID가 바뀌어도(확보한 판본에서 63%) 같은 설비를 찾을 수 있고, 기존 온톨로지 id 매핑의 보조 열쇠가 됨. 새 술어라 DT 파서와 맞춰야 함

가능한 개발 목록

- BAS 관제점 목록과 설비 연결(E11). AI Agent·실시간 값에 필요. 위의 관제점 ID 요구가 받아들여지면 BIM에서 바로 읽음
- 규칙 방향 오류 수정(전열교환기, 천장형 배기팬)
- 방 종류 사전 보강(성수의 약어 방 이름 등). 방 안의 설비로 종류를 짐작하는 방법도 검토
- 순환수 환수·급탕 흐름 규칙
- 공조존 편집(E9), 커스텀존(E10). 데이터 교환 방식 결정 후
