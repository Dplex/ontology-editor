# BIM 기반 DT 온톨로지 구축 범위

기준일: 2026-09-29 · 기준 문서: `docs/bim-to-dt-ontology.md`(등급·요구사항은 이 문서를 따름)

DT가 쓰는 온톨로지(방·설비·관제점 사이의 관계)를 고객사 BIM에서 자동으로 만들고, 빠지거나 틀린 것은 에디터에서 사람이 고치는 것이 이 과제의 범위. 이 문서는 세 질문에 답함.

1. DT 온톨로지에 무엇이 있어야 하는가 → 1장(등급), 4장(피처)
2. 고객사 BIM이 그중 어디까지 주는가 → 4장, 부록 A
3. 고객사 BIM에 최소한 무엇을 요구하는가 → 3장

## 용어

본문을 읽는 데 필요한 것만 둠. 나머지는 부록 C.

| 용어 | 뜻 |
|---|---|
| BIM | 건물을 3D 객체(벽·방·설비 하나하나)와 속성으로 만든 설계 모델 |
| IFC | BIM을 프로그램과 상관없이 주고받는 표준 파일 형식. IFC2x3(구버전)과 IFC4(신버전)가 있음 |
| 건축 BIM · 설비 BIM | 같은 건물이라도 분야별로 따로 만든 파일. 건축에는 층·방·벽이, 설비(MEP)에는 공조기·덕트·배관 등이 있음. 둘을 합쳐야 설비가 어느 방에 있는지 알 수 있음 |
| 온톨로지 | 방·설비·관제점 사이의 관계(어디에 있다, 어디로 공기를 보낸다 등)를 적은 데이터. DT가 이것을 읽어 화면과 기능을 만듦 |
| 산출물 | 이 과제가 만드는 파일 두 개. 관계를 담은 온톨로지 파일(TTL)과 방 외곽선·설비 좌표를 담은 도형 파일(GeoJSON). 같은 id로 이어짐 |
| 에디터 | 이 과제에서 만든 도구. BIM을 읽어 온톨로지를 만들고, 빠지거나 틀린 것을 사람이 고침 |
| 피처 | DT가 온톨로지에서 필요로 하는 정보 항목(예: 설비가 있는 방) |
| 계통 | 공조기 → 덕트 → 토출구처럼 한 흐름으로 이어진 설비 묶음(예: 3층 급기 계통) |
| 공조기 · 토출구 · 원천 · 말단 | 공조기는 공기를 만들어 보내는 큰 장비, 토출구(디퓨저·그릴)는 공기가 방으로 나오는 구멍. 흐름이 시작되는 기기를 원천, 끝나는 기기를 말단이라 부름 |
| 포트 · 흐름 방향 | 포트는 기기와 덕트·배관이 이어지는 접속구. BIM은 포트마다 공기·물이 나가는 쪽인지 들어오는 쪽인지 적을 수 있고, 이것이 흐름 방향의 가장 확실한 출처 |
| 규칙 방향 | 포트에 방향이 없을 때 계통·기기 종류로 우리가 추정한 흐름 방향 |
| 표준 칸 · 다른 자리 | 표준 칸은 IFC 규격이 값마다 정해 둔 자리. Revit(BIM 프로그램)은 같은 값을 자기 전용 칸에 넣기도 해서, 이 문서는 그것을 "다른 자리"라 부름. 값은 있지만 다른 프로그램은 못 읽을 수 있음 |
| 이름 사전 | 객체 이름(예: "FCU3", "라인디퓨저")으로 종류를 알아내는 규칙 모음. 설비·건축 분야 지식을 우리가 정리해 넣은 것 |
| 관제점 · BAS | BAS는 건물 자동제어 시스템, 관제점은 BAS가 재거나 제어하는 값 하나(예: 3층 회의실 온도) |
| 공조존 | 같은 공조 설비가 맡는 구역. 여러 방이 한 공조존에 들 수 있음 |
| 번호 | R0~R24는 요구사항(3장), E1~E11은 편집 기능(6장) |

## 요약

- 자동으로 되는 것: 필수 요구 11개(3장)를 갖춘 BIM이면 공간 골격(층·방·벽)과 설비가 어느 방에 있는지(등급 2)까지 대부분 자동으로 만들어짐. 고객사 파일(성수)은 필수 중 표준 칸에 제대로 있던 것이 6개뿐이었는데도 공간 골격·설비 위치·설비가 있는 방이 77~100% 자동으로 채워짐
- 사람 몫: 설비·방·계통 종류는 이름 사전으로 채우고, 사전이 모르는 것은 사람이 정함. 흐름 방향은 포트에 적혀 있을 때만 확실하고, 없으면 규칙으로 추정한 것을 사람이 확정해야 온톨로지에 들어감
- 고객사에 요구할 것: 필수 11개. 값이 이미 있어도 다른 자리에 저장된 경우가 많아, 대개 내보내기 설정만 바꿔 달라고 하면 됨. 공조존·관제점은 BIM 밖(에너지 시뮬레이션 모델·BAS)에서 받음

BIM 조건에 따른 차이

| 조건 | 있을 때 | 없을 때 |
|---|---|---|
| 건축·설비 파일의 좌표 기준과 층 이름이 같음 | 설비가 있는 방을 자동으로 찾음 | 오류 메시지 없이 방이 비거나 틀림 |
| 포트의 흐름 방향 | BIM의 방향을 그대로 씀 | 규칙으로 추정한 뒤 사람이 확정 |
| 종류·분류를 표준 칸에 적음 | BIM의 종류를 그대로 씀 | 이름 사전과 사람이 채움 |

## 1. 등급

이 BIM으로 온톨로지를 어디까지 만들 수 있는지를 단계로 나눈 것. 위 등급은 아래 등급이 있어야 함. 고객사에 필수로 요구하는 것은 등급 2까지 만들 수 있는 정도이고, 0+·4+는 권장 항목(3장)까지 채우면 더 얻는 단계. 확보한 파일로 보면 고객사 BIM은 대부분 등급 1~3에 그치고, 등급 4는 포트에 흐름 방향을 넣어 내보낸 파일에서만 나왔음.

| 등급 | 온톨로지에 더해지는 것 | DT에서 되는 것 | BIM에 필요한 것 |
|---|---|---|---|
| 0 공간 골격 | 층, 방 외곽선, 벽·문·창 | 3D Map, 탐색기 트리 | 건축 BIM, 길이 단위, 원점 (R1~R4·R6·R7) |
| 0+ 공간 의미 | 방 종류, 문으로 이어진 방과 방 | "회의실" 검색, 로봇 경로 | 방 분류 코드, 방을 둘러싼 벽·문 정보 (R14·R5) |
| 1 설비 목록 | 설비와 좌표 | 3D에 설비 표시 | 설비 BIM (R9·R11) |
| 2 설비 소속 | 설비가 어느 방에 있는지 | 이상 알림의 발생 위치 | 건축·설비 파일이 같은 좌표 기준과 같은 층 이름 (R12·R1) |
| 3 계통·연결망 | 같은 계통·배관에 이어진 설비(방향 없음) | 계통별 보기 | 계통 정보, 서로 맞닿게 그린 설비 (R16·R15) |
| 4 흐름 방향 | 공조기 → 토출구 흐름 | 담당 설비 추적, 상류·하류 조회 | 포트의 흐름 방향 (R17) |
| 4+ 담당 공간 | 공조기가 공기를 보내는 방 | 계통도의 담당 공간 | 흐름 방향(포트 또는 사람이 확정한 규칙 방향), 공조기와 말단을 한 계통으로 (R18) |
| 5 운영 | 공조존, 관제점 | 계통도, 실시간 값 | BIM 밖 자료(공조존은 IDF, 관제점은 BAS) |

## 2. 값의 출처

에디터는 화면의 값마다 어디서 왔는지 표시함. 온톨로지를 받는 쪽은 이것을 구별할 수 없어서, 만드는 쪽에서 구별해 둠.

| 출처 | 무엇 | 얼마나 맞나 | 온톨로지에 들어가는 때 |
|---|---|---|---|
| BIM | 파일에 적힌 값 | BIM 품질에 따름 | 파일을 열 때 바로 |
| 계산 | BIM의 좌표·모양으로 우리가 판정한 값(설비가 있는 방, 연결 추정, 파일 합치기) | 설비가 있는 방은 BIM에 적힌 답과 96~97% 일치. 추정한 연결은 약 80%가 맞음 | 파일을 열 때 바로. 단, 모양으로 추정한 연결에는 방향을 넣지 않음 |
| 사전 | 이름 사전·흐름 규칙으로 정한 값(종류, 흐름 방향) | 규칙으로 정한 방향이 포트에 적힌 실제 방향과 84~99% 일치 | 종류는 파일을 열 때 바로. 흐름 방향은 사람이 확정한 뒤 |
| 사람 | 에디터에서 정하거나 확정한 값 | — | 고치는 즉시 |
| 외부 | IDF(공조존), BAS(관제점), 운영자가 그린 구역 등 BIM 밖 자료 | — | 불러오는 즉시. BAS 관제점 연결은 아직 없음(6장) |

흐름 방향을 사람의 확정 없이 넣지 않는 이유: 틀린 방향이 들어가면 온톨로지를 쓰는 쪽은 그것이 BIM에 적힌 방향인지 우리가 추정한 방향인지 구별할 수 없음.

## 3. 고객사 BIM 요구사항

DT에 필요한 정보와 확보한 BIM을 재 본 결과로 우리가 정한 요구사항. 필수 11개, 권장 14개. 필수는 고객사가 꼭 지켜야 하는 것, 권장은 없어도 등급 2까지는 되지만 있으면 사람 손이 덜 가는 것.

| R | 요구 | 구분 | 왜 필요한가(없으면) |
|---|---|---|---|
| R0 | 파일이 형식 오류 없이 열림 | 필수 | 파일을 아예 읽지 못함 |
| R1 | 층 이름이 DT의 층 표기와 같고, 건축·설비 파일끼리도 같음 | 필수 | 탐색기 트리의 층을 만들 수 없음. 건축·설비 파일은 층 이름으로 맞춰 합침 |
| R2 | 층마다 방(IFC의 공간 객체)과 방의 바닥 외곽선. 설비가 놓인 공용부(복도·샤프트·기계실·옥탑)도 방으로 그림 | 필수 | 방이 만들어지지 않음. 방이 없는 자리의 설비는 몇 층인지까지만 알 수 있음 |
| R3 | 방 이름·번호(이름이 기본값 "공간"이 아님), 건축·설비 파일끼리 같은 번호 | 필수 | 탐색기에 보일 이름이 없고, 파일끼리 같은 방을 맞추지 못함 |
| R4 | 벽·문·창과, 문·창이 어느 벽에 달렸는지 | 필수 | 3D Map의 벽, 로봇이 지나갈 문, 방과 방을 잇는 문을 만들 수 없음 |
| R5 | 방을 둘러싼 벽·문 정보(공간 경계) | 권장 | 어느 문이 어느 두 방을 잇는지 BIM에서 바로 얻음. 없으면 문 위치로 계산 |
| R6 | 길이 단위(mm·m)를 파일에 적음 | 필수 | 좌표가 1,000배 틀려도 오류가 나지 않음 |
| R7 | 3D 스캔과 같은 원점·북쪽 방향(IFC2x3 파일은 기준점을 따로 협의) | 필수 | 온톨로지와 3D 스캔이 통째로 어긋남 |
| R8 | 모양 상세도 LOD 300(설계대로의 크기·위치) | 권장 | 계약서에 쓰는 표현. 실제로 필요한 모양 정확도는 R2·R11·R15로 확인 |
| R9 | 설비(MEP) 포함 | 필수 | 설비가 하나도 없음 |
| R10 | IFC4 형식 | 권장 | 계통 종류·지도 좌표를 표준 칸에서 읽음. IFC2x3도 등급 2까지는 됨 |
| R11 | 설비마다 위치가 있고, 그 위치가 실제 설비 모양에서 떨어져 있지 않음 | 필수 | 설비가 어느 방에 있는지 판정할 수 없음 |
| R12 | 건축·설비 파일이 같은 좌표 기준 | 필수 | 오류 메시지 없이 설비가 엉뚱한 방에 들어감 |
| R13 | 다시 내보낼 때 객체 id(GUID)를 유지 | 필수 | id가 바뀌어 DT 쪽 이력·관제점 연결이 끊김 |
| R14 | 방 용도 분류 코드(OmniClass) | 권장 | "회의실" 같은 방 종류를 BIM에서 바로 얻음. 없으면 이름 사전 |
| R15 | 이어진 설비끼리 모양이 맞닿게 그림 | 권장 | 포트가 없어도 맞닿은 자리로 연결을 추정할 수 있음 |
| R16 | 계통 묶음·이름·종류 | 권장 | 계통별 보기와 흐름 방향 추정의 재료. 없으면 Revit 전용 칸과 이름 사전으로 채움 |
| R17 | 포트의 흐름 방향(연결마다 한쪽 이상). 흐름이 시작되는 원천 기기도 모델에 있음 | 권장 | 흐름 방향(등급 4)을 BIM에서 바로 얻음. 없으면 규칙으로 추정한 뒤 사람이 확정 |
| R18 | 공조기와 말단을 같은 계통으로 묶음 | 권장 | 공조기가 공기를 보내는 방을 계산할 수 있음 |
| R19 | 공조존 값 | 권장 | 다른 자료 없이 BIM에서 공조존을 얻음 |
| R20 | 센서가 어느 설비를 재는지 | 권장 | 관제점이 어느 설비의 것인지 이을 수 있음 |
| R21 | 설비 용량(풍량·출력 등) | 권장 | 용량 검증. 설계 후반(LOD 400)에 들어가는 정보라, 없으면 설비 대장을 따로 받음 |
| R22 | 벽이 내력벽인지 | 권장 | 내력벽은 편집을 막음 |
| R23 | 종류를 정하지 않은 객체(Proxy)를 쓰지 않음 | 권장 | 무슨 설비인지 모르는 객체가 생기지 않음 |
| R24 | 설비 종류를 표준 칸(`PredefinedType`)이나 정해 둔 이름으로 적음 | 권장 | 설비 종류를 BIM에서 바로 얻음. 없으면 이름 사전 |

구분 기준

- 필수는 셋을 다 만족하는 것: 등급 2까지 만드는 데 필요하고, 빠지면 우리가 되살릴 수 없고, 우리 코드가 실제로 씀. R13만 등급과 상관없이, 다시 받은 파일에서 같은 객체를 알아보는 데 필요해서 필수
- 권장은 없어도 등급 2까지는 되는 것. 빠진 부분은 계산·사전·사람이 채움
- R7은 확보한 파일 중 지킨 것이 없음(IFC2x3에는 적을 표준 칸이 없음). 고객사와 기준점을 합의해야 함(6장)

참고

- 요구하지 않는 것: 방 높이, 마감·가구·구조 해석, 관제점 ID·실시간 값(IFC에 적을 자리가 없음)
- Revit 기본 설정으로 내보낸 파일에도 권장 항목 값은 대부분 있으나 다른 자리에 저장됨. 고객사에는 값을 새로 넣어 달라기보다 내보내기 설정을 바꿔 달라고 요청
- 검사: 고객사가 납품 전에 스스로 확인할 수 있게, 속성으로 확인되는 항목은 검사 파일(IDS, `docs/requirements.ids`)로 만들어 둠. 모양이나 파일 사이 비교가 필요한 항목(R8, R12, R13 등)은 IDS로 적을 수 없어 우리가 파일을 열어 확인

## 4. 피처별로 무엇이 채우나

같은 피처라도 BIM에 따라 0%도 100%도 채워지므로 비율 대신 무엇에 달렸는지를 적음. 괄호는 3장의 요구사항 번호. 확보한 파일에서 잰 비율은 부록 A.

| 피처 | 어디서 채우나 | BIM에 이것이 있으면 자동 | 없으면 |
|---|---|---|---|
| 층·방 이름 | BIM | 층 이름, 방 이름·번호(기본값 "공간"이 아닌 것) (R1·R3) | 사람이 이름을 넣음 |
| 방 외곽선 | BIM | 공용부까지 그린 방 (R2) | 사람이 3D에서 그림 |
| 벽·문·창, 문·창이 달린 벽 | BIM | 벽·문·창과, 문·창이 어느 벽에 달렸는지 (R4) | 고객사에 요청 |
| 내력벽 | BIM | 벽의 구조 속성 (R22). BIM 프로그램이 기본값으로 채워 둔 것일 수 있어 그대로 믿지 않음 | "모름"으로 둠 |
| 문으로 이어진 방과 방 | BIM, 없으면 계산 | 방을 둘러싼 벽·문 정보 (R5) | 문 위치로 계산. 층 사이는 계단실·승강로가 겹치는 자리로 계산 |
| 방 종류 | BIM, 없으면 사전, 그래도 모르면 사람 | 방 용도 분류 코드 (R14) | 방 이름으로 사전이 판정. 모르면 사람이 이름을 고침 |
| 설비 종류 | BIM, 없으면 사전, 그래도 모르면 사람 | 표준 칸의 종류, 종류 없는 객체를 안 씀 (R24·R23) | 이름 사전. 모르면 사람이 같은 모델의 설비를 한꺼번에 정함(에디터가 후보를 보여 줌) |
| 설비 위치 | BIM, 필요하면 계산으로 보정 | 설비 모양에서 떨어지지 않은 위치 (R11) | 모양의 중심으로 보정. 좌표가 없으면 사람이 놓음 |
| 계통 소속 | BIM | 계통 묶음 (R16). 내보내기 설정에 달림 | 사람 |
| 계통 종류 | BIM, 없으면 사전 | 표준 칸의 계통 종류 (R16) | 계통 이름으로 사전이 판정 |
| 설비가 있는 방 | 계산 | 같은 좌표 기준의 건축 파일 (R12·R2) | 몇 층인지까지만 알 수 있음 |
| 연결 | BIM, 없으면 계산 | 포트 (R17) | 맞닿은 자리로 추정(R15). 방향은 비워 둠 |
| 흐름 방향 | BIM, 없으면 규칙으로 추정한 뒤 사람이 확정 | 포트의 흐름 방향과 원천 기기 (R17) | 규칙으로 추정한 뒤 사람이 계통 단위로 확정 |
| 용량 | BIM | 표준 칸의 용량 (R21) | 설비 대장을 따로 받음 |
| 공조존 | 외부 | 없음(IFC에 자리는 있으나 실제 파일은 비어 있음) | 에너지 시뮬레이션 모델(IDF) 등 BIM 밖 자료. IDF도 없으면 사람이 정함(E9, 예정) |
| 관제점 | 외부 | 없음(IFC에 적을 자리가 없음) | BAS |

확보한 파일에서 본 경향

- 공간 골격과 설비 위치는 대부분 BIM에서 나옴. 빈 곳은 파일 작성 습관에서 생김. 성수에서는 외곽선 없는 방 55개(전체 508개 중), 이름을 기본값 "공간"으로 둔 방 42개, 어느 벽에 달렸는지 적히지 않은 문·창 137개, 방을 그리지 않은 공용부(복도·기계실 등)에 놓인 기기 571대(전체 4,911대 중)
- 방·설비·계통 종류는 BIM이 표준 칸에 적는 일이 드물어 사전이 크게 보탬. 사전이 모르는 것은 사람 몫
- 연결과 흐름 방향은 포트를 넣은 만큼만 BIM에서 나옴(성수는 일부 연결에만 포트 방향). 나머지 연결은 맞닿은 자리로 추정하고, 방향은 규칙으로 추정한 뒤 사람이 확정

## 6. 현재 상태와 다음 할 일

구현된 것(데모에서 확인 가능)

- IFC 불러오기(IFC2x3·IFC4), 건축·설비 파일 합치기
- 설비가 있는 방 판정, 맞닿은 자리로 연결 추정, 규칙으로 흐름 방향 추정(사람이 계통 단위로 확정)
- 이름 사전으로 설비·방·계통 종류 판정, 화면 값마다 출처 표시
- 종류를 모르는 설비에 후보 제안. 이름의 낱말과, 같은 건물에서 계통·이웃·높이가 닮은 설비를 근거로 함. 정하는 것은 사람
- 파일마다 등급 표시, 요구사항을 얼마나 지켰는지 보고서, 같은 건물의 이전·이후 파일 비교
- 빠진 곳 검사: 공조기에서 말단까지 이어지는가, 열원(보일러·냉동기)에서 공조기·FCU·방열기까지 이어지는가, 한쪽 끝만 이어진 덕트·배관(연결이 끊긴 자리), 방이 없는 설비, 어디에도 안 이어진 설비
- 공조존: IDF(에너지 시뮬레이션 모델)에서 읽어 방·설비와 이음
- 편집 E1~E8(아래 표). 3D·평면도·표에서 고치고, 빠진 곳 검사에서 바로 고치기, 되돌리기, 편집 파일 저장·불러오기 포함
- 내보내기(TTL, GeoJSON). DT 쪽이 파일을 읽는 코드로 실제로 읽히는지 확인
  - 공조기가 공기를 보내는 방(담당 공간)을 온톨로지에 포함. 포트·사람이 정한 방향·확정한 규칙 방향으로 이어진 것만
  - 계단실·승강로가 위층의 어느 계단실·승강로와 이어지는지 도형 파일에 포함(로봇이 층을 옮길 자리)

정해야 할 것(앞은 정할 사람)

- **PM**: 고객사에 전달할 요구사항 범위
- **PM·고객사**: R7 기준점과 R1 층 이름 표기
- **PM·DT 개발팀**: DT와 데이터를 주고받는 방식. PRD(이 과제의 제품 요구사항 문서) 1.7이 파일 / API / 공유 DB 셋을 열어 둠. 이것이 정해져야 편집 결과를 어디에 저장할지, 이전 판으로 되돌리기(PRD 기능 #19), 여럿이 동시에 고치지 못하게 막기(#2)가 정해짐
- **DT 개발팀과 합의**: BIM의 객체 id(GUID)와 기존 온톨로지 id를 서로 맞추는 방식
- **PM**(받아들이면 고객사에 요청): 설비마다 BAS 관제점 ID(또는 설비 태그)를 BIM 속성으로 넣어 달라고 할지. 들어오면 관제점과 설비를 사람이 잇지 않아도 됨. 2025년 발표된 BIM-to-BRICK 연구가 이 방식으로 BIM과 BAS를 이음
- **DT 개발팀과 합의**: Revit 요소 ID(Revit이 객체마다 매기는 번호)를 온톨로지에 함께 적을지. 다시 내보낸 BIM에서 GUID가 바뀌어도(확보한 파일에서 63%) 같은 설비를 찾을 수 있고, 기존 온톨로지 id와 맞출 때 보조 식별자가 됨. 온톨로지에 새 관계 이름을 더하는 것이라 DT 쪽 읽기 코드와 맞춰야 함

가능한 개발 목록

- BAS 관제점 목록과 설비 연결(E11). AI Agent·실시간 값에 필요. 위의 관제점 ID 요구가 받아들여지면 BIM에서 바로 읽음
- 규칙으로 정한 흐름 방향이 틀리는 기기 고치기(전열교환기 같은 환기 장치, 천장형 배기팬)
- 방 종류 사전 보강(성수의 약어 방 이름 등). 방 안의 설비로 종류를 짐작하는 방법도 검토
- 냉난방용 물이 돌아오는 관(환수)과 온수 공급(급탕)의 흐름 방향 규칙
- 공조존 편집(E9), 커스텀존(E10). 데이터 주고받는 방식이 정해진 뒤

| 개구부 | 문·창을 넣으려고 벽에 뚫은 구멍(건축 용어). BIM은 문·창이 어느 벽의 개구부에 끼워졌는지를 관계로 적음. 이 문서에서는 "문·창이 달린 벽"으로 풀어 씀 |
| 공간 경계 | 방을 둘러싼 벽·문을 BIM이 직접 적어 둔 정보. 어느 문이 어느 두 방을 잇는지 알 수 있음 |
| LOD | BIM의 상세 수준. 300은 설계대로의 정확한 크기·위치, 400은 제조사·용량 정보까지 포함 |
| OmniClass | 방 용도 분류 코드 표준(예: 사무실, 화장실) |
| IDS | 요구사항을 검사 프로그램이 읽을 수 있게 적는 파일 형식(buildingSMART 표준). 검사 도구(ifctester, Solibri 등)에 IFC 파일과 함께 넣으면 지켰는지 자동으로 확인됨 |
| 기기 · 덕트·배관 | 기기는 공조기·FCU·토출구·밸브·센서처럼 역할이 있는 장비. 덕트·배관은 공기·물이 지나는 관과 이음쇠(엘보·티 등)로, BIM 설비 객체의 약 85%를 차지 |
| FCU · VAV | FCU는 방마다 두는 소형 냉난방기, VAV는 방으로 가는 바람의 양을 조절하는 장치 |
| 상류 · 하류 | 흐름을 거슬러 올라간 쪽이 상류(공조기 쪽), 따라 내려간 쪽이 하류(토출구 쪽) |
| Brick · TTL | Brick은 건물 온톨로지의 표준 어휘, TTL은 그 어휘로 쓴 파일 형식 |
| GeoJSON | 방 외곽선·설비 좌표 같은 도형을 담는 파일 형식 |
| 물리존 | DT에서 방 하나를 부르는 이름. BIM의 공간 객체(`IfcSpace`) 하나에 해당. 이 문서에서는 "방"이라 씀 |
| 커스텀존 | 운영자가 직접 그려 정하는 구역 |
| 등급 | 이 BIM으로 온톨로지를 어디까지 만들 수 있는지를 0~5로 나눈 것(1장) |
| PRD · #N | PRD는 이 과제의 제품 요구사항 문서(사내 Confluence PRD_011). #N은 그 문서의 기능 번호 |
