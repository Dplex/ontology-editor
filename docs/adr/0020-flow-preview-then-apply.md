# ADR-0020 연결별 방향은 미리보기 뒤 [적용] 으로 정한다

## 맥락

OE-PIP-04 는 포트가 방향을 말하지 않은 연결에 사람이 'A → B' 를 고르고 [적용] 해야 방향이 정해지게 한다. 적용 전 방향은 미리보기라
TTL `feeds` 에 나가지 않는다. 규칙 방향과 반대면 차이를 보이고 보정 사유를 받는다. [수동 지정 해제] 는 규칙 방향(확정이면 내보내고,
미확정이면 화면에만)이나 방향 미지정으로 돌아간다. 적용·해제는 이력에 남는다.

이 PR 전에는 표의 [상류로]·[하류로], 3D 화살표 클릭, `D` 키가 누르는 즉시 방향을 바꿨다(`setFlowDirection`).

## 결정

**미리보기는 화면에만 있다.** `flowDraft`(App.vue)가 연결과 방향을 들고 표에 미리보기 상자를, 3D 에 점선 액센트 화살표(`preview`)를
그린다. 모델은 그대로라 바뀐 것·자동 저장·TTL 이 움직이지 않는다. [적용] 할 때 `applyFlow`(connection-release.ts)가 연결의
`edited` 에 방향·시각·사유를 남긴다.

- **사유는 규칙 방향과 반대일 때만 받는다.** 규칙과 같은 방향을 사람이 정하는 것은 확정 대신 연결 하나만 굳히는 일이라 따로 설명할
  것이 없다. 규칙 방향이 없는 연결(방향 미지정)도 사유 없이 적용한다.
- **3D 화살표와 `D` 는 미리보기만 돌린다**(나감 → 들어옴 → 거둠). 적용은 표의 [적용] 이고, `D` 로 미리 보면 [적용] 에 초점이 가서
  `Enter` 로 누른다. 사유가 필요하면 [적용] 이 거절하면서 사유 칸으로 초점을 옮긴다. 처음부터 사유 칸에 두면 `D` 를 다시 눌러 다음
  미리보기로 갈 때 글자로 들어간다.
- **이력은 해제 보정(ADR-0019)과 같은 `connectionLog` 에 `flow`·`unflow` 로 남는다.** 화면 제목은 "연결 편집 이력" 이다. 되돌리기도
  같은 스냅숏(`ReleaseSnapshot`)이 연결의 `edited` 와 이력을 같이 든다.
- 편집 파일의 `flows` 줄에 `at`·`reason` 이 붙는다. 해제한 연결에 정해 둔 방향은 `connectionsReleased` 줄의 `edited` 로 남아, 취소하면
  다시 쓰인다.
- 누구도 방향을 말하지 않은 연결의 표 글은 '연결' 에서 '방향 미지정' 으로 바꿨다.

## 고려한 다른 길

- **화살표 클릭·`D` 는 그대로 바로 적용하고 표만 미리보기로**: 같은 연결의 방향을 바꾸는 길이 둘인데 하나는 미리보기를 건너뛰고,
  규칙과 반대 방향도 사유 없이 정해진다.
- **사유를 늘 받기**: 규칙과 같은 방향을 정할 때도 칸을 채워야 해서, 성수처럼 규칙이 닿지 않는 연결이 많은 파일에서 손이 많이 간다.

## 결과

- 기존 시험 넷이 바뀌었다(`smoke`·`edit-3d` 의 방향 시험 셋, `shortcuts` 의 `D`). 누르면 바로 바뀌던 것을 기대했다.
- 되돌리려면 `cycleFlow`·`previewFlow`·`submitFlow`(App.vue)를 `setFlowDirection` 바로 부르기로 바꾸고, `applyFlow` 의 사유 검사를
  걷어 내면 된다.
