# ADR-0013 3D 음영은 하늘빛과 카메라에 붙인 주광 두 개로만 낸다

## 맥락

형상이 있는 설비도 3D 에서 계통 색 한 덩어리로 보였다. 설비 형상은 대부분 상자가 아니다. 정점 24개 이하인 순수 상자는
성수 기계 디퓨저 169대뿐이고, 정점 중앙값은 Duplex MEP 254 · ifc4Mep 836 · 성수 기계 140 · 성수 건축 2,361 이다.
그런데도 덩어리로 보인 것은 빛 때문이었다. 고른 주변광(AmbientLight 1.25)이 밝기의 대부분이었고, 하나뿐인 방향광은 세계에
고정되어 있었다. 그래서 어느 쪽 면이든 밝기가 거의 같았고, 시점을 해 반대편으로 돌리면 모든 면이 그늘이 되었다.

조건은 성수(설비 형상 1,016만 정점)에서 회전이 지금처럼 매끄러워야 한다는 것이다(OE-UI-14, 사용자 요청 "렌더링에 부하가
최대한 덜 걸리게").

## 결정

주변광을 하늘빛(HemisphereLight: 위는 흰색, 아래는 회청색 `0x6f7684`, 0.9)으로 바꾸고, 방향광(1.45)은 카메라의 자식으로 두어
화면 왼쪽 위에서 비추게 한다. 재질(MeshLambertMaterial)과 설비 색(계통 색, 꼭짓점 색)은 그대로 둔다.

- 하늘빛은 윗면을 밝게, 아랫면을 어둡게 해서 덕트·배관의 위아래를 가른다.
- 주광이 카메라를 따라가므로 어느 시점에서 보아도 면마다 밝기가 다르다.
- 3D 는 시점이 바뀔 때만 다시 그린다(`viewer.ts` 의 `dirty`). 빛이 카메라를 따라가도 더 그리는 프레임은 없다.

성수에서 잰 값(`npm run e2e:seongsu` 의 C-11, 회전·확대 중 프레임 간격)은 바꾸기 전과 같다.

| | 중앙값 | 95% | 최대 |
|---|---|---|---|
| 바꾸기 전 | 17ms | 18ms | 19ms |
| 바꾼 뒤(3회) | 17ms | 18ms | 43 · 19 · 20ms |

43ms 는 한 번만 나왔고 다시 잰 두 번은 19·20ms 였다. 여는 동안 가장 긴 멈춤(B-4)은 바꾸기 전 547ms, 바꾼 뒤 487~713ms 로
실행마다 흔들리는 범위 안이다.

## 고려한 다른 길

- **그림자(shadow map)**: 그림자 지도를 그리려고 장면을 한 번 더 그려야 한다. 성수에서는 그리기 비용이 두 배가 된다.
  면을 가르는 데는 그림자가 필요하지 않다.
- **SSAO 같은 후처리**: 화면 전체를 프레임마다 한 번 더 처리하므로 GPU 가 약한 노트북에서 회전이 먼저 느려진다.
- **PBR 재질(MeshStandardMaterial)**: Lambert 보다 픽셀당 계산이 많고, 환경 맵이 없으면 오히려 밋밋하다.
- **IFC 재질 색으로 칠하기**: 형상은 더 실물 같아지지만 계통 색이 사라진다. 계통을 색으로 가르는 것이 이 화면의 일이라
  (범례·연결망 칠하기) 고르지 않았다.
- **BIM 형상이 상자 수준인 기기를 종류별 3D 모델로 바꿔 그리기**: 모델 파일(GLB)을 구해야 하고, 화면이 BIM 과 달라진다.
  빛만 고쳐도 볼 만해지는지를 먼저 보기로 했다.

## 결과

- 어려워진 것: 계통 색 범례의 색과 3D 의 색이 면에 따라 조금 달라진다. 빛을 받는 면이 범례 색에 가깝고, 그늘진 면은 더 어둡다.
- 내보낸 3D 를 보는 뷰어(`src/viewer/Scene3D.vue`)는 이 결정 밖이다. 빛 설정이 따로 있고 고치지 않았다.
- 되돌리려면 `viewer.ts` 의 `createViewer` 에서 빛 두 개를 예전 값(AmbientLight 1.25, 세계 `(20, 40, 20)` 에 둔
  DirectionalLight 0.9)으로 돌리고, `scene.add(camera)` 를 뺀다.
