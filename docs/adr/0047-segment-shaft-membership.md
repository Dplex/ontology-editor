# ADR-0047 덕트·배관 구간의 샤프트 소속

## 맥락

OE-ML-09#4 는 샤프트를 지운 뒤 안의 배관·연결은 남고 소속만 해제되라고 하고, OE-ML-14#5·6 은 오프셋을 고치기 전에 샤프트 소속 영향을 보이고(이탈은 고친 뒤 표시),
위치만 겹친 배관이 샤프트에 저절로 소속되지 않게 하라고 한다. 지금까지 배관과 샤프트 사이에는 관계가 없었다. 가진 BIM 에는 샤프트 안 배관을 묶는 관계가 없고
(IfcShaft 는 IFC4.3), Revit 도 파이프 샤프트를 개구부로만 낸다.

## 결정

- **사람이 정한다.** 다중층 뷰에서 덕트·배관 구간을 고르면 "샤프트" 칸이 뜨고, 후보는 두 끝이 샤프트 축(모든 층 같은 평면 형상, 경계 밖 5cm 까지) 안이고 구간의 층이 샤프트 구간에 드는 것뿐이다. 축 밖 구간은 거절한다. 저절로 붙이지 않는다.
- **구간에 샤프트 id 만 적는다**(`Equipment.shaftId`). 읽는 쪽은 `shaftOf` 로 그 샤프트가 있는지 본다. 샤프트를 지우면 소속은 효력이 없고 배관·연결은 그대로다 — 샤프트 지우기를 되돌리면 소속이 돌아온다(구간을 따로 떠 둘 필요가 없다).
- **이탈**: 샤프트나 구간을 옮겨 축을 벗어나도 소속은 두고 알린다(편집 안내, 구간 패널의 "축 밖"). 사람이 배관을 옮기거나 소속을 푼다.
- **영향 표시**: 오프셋 높이를 바꾸기 전 영향에 같이 늘어나는 구간 중 샤프트에 든 것, 샤프트 지우기 확인에 안의 배관 수.
- **내보내기**: GeoJSON 구간 feature 의 `shaftId`(샤프트 조각 feature 의 `parentId`). TTL 에는 내지 않는다 — Brick 에 샤프트 소속 술어가 없고, 온톨로지 소비처가 아직 쓰지 않는다. 편집 파일은 설비 줄의 `shaft`(넣음 id · 뺌 null).

## 고려한 다른 길

- **축 안에 있으면 저절로 소속.** OE-ML-14#6 이 막는다. 옆 샤프트·같은 자리를 지나는 다른 계통 배관이 섞인다.
- **샤프트 쪽에 구간 목록을 적기.** 구간을 지우거나 나누면(분기) 목록을 고쳐야 하고, 편집 파일이 구간·샤프트 두 곳에 같은 사실을 적는다.
- **샤프트를 지울 때 구간의 `shaftId` 를 지우기.** 되돌리기에 구간 스냅샷이 따로 필요하다. 효력만 잃게 하면 지우기·되돌리기가 샤프트 하나로 끝난다.

## 결과

- 시험: `shaft.test.ts`(저절로 안 붙음·축 밖 거절·GeoJSON·차이·편집 파일 왕복·샤프트를 편집으로 만든 경우·이동 이탈·지우기와 되돌리기) · `e2e/riser.spec.ts`(Duplex 라이저를 둘러 샤프트를 만들고 넣기 → 오프셋 영향 → 지우기 확인·배관 그대로).
- 알려진 불편: 샤프트 가운데를 누르면 안의 배관이 먼저 잡힌다(배관이 판보다 앞). 샤프트는 조각 판에서 배관이 없는 가장자리를 누른다. 고르기 순서를 바꿀지는 따로 본다.
- 되돌리려면 `shaft.ts`, `Equipment.shaftId`, 편집 파일의 `shaft`, GeoJSON 의 `shaftId` 를 걷어낸다.
