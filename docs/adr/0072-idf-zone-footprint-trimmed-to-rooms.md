# ADR-0072 IDF 공조존 바닥을 BIM 방에 맞춰 다듬는다

## 맥락

ADR-0069 로 성수 IDF(`Factorial.idf`)를 성수 BIM 위에 맞춰 놓으면 기준층 존 넓이의 96% 가 방과 겹친다. 남은 어긋남이 어디서 오는지 존
경계를 25cm 간격으로 짚어 보면(성수 건축 IFC, 존 79, 점 2만여 개) 세 가지다.

| 어긋남 | 경계 점 몫 | 원인 |
|---|---|---|
| 벽 두께 안을 지남 | 30% | DesignBuilder 는 존 바닥을 벽 중심선까지 그린다. 존 넓이가 순 넓이의 1.0~1.19 배다 |
| 벽 없는 열린 바닥을 지남 | 44% | 창가 띠와 안쪽을 나눈 경계다. 성수 4F 창가 띠 깊이는 4.1~4.5m 이고, ASHRAE 90.1 Appendix G 의 thermal block(외벽에서 15ft 안은 창가 존) 관례와 같다 |
| 방 경계에서 0.05~1m (애매한 띠) | 9% | 단순화와 실제 어긋남이 섞여 있다 |

이와 별도로 BIM 이 방을 안 그린 자리가 있다. 성수 1F·2F 매장 존 13개는 방과 겹치는 곳이 거의 없다(2F 방 140㎡ · 존 1,249㎡).

벽 두께 띠는 이웃 방과의 겹침으로 잡혀 "두 존에 걸친 방" 을 만들고, 3D·평면에서는 공조존이 벽을 덮는다. 존 경계와 방 경계를 맞출
방법을 여섯 가지로 나눠 성수에 같은 지표로 쟀다(존 합집합과 방 합집합의 IoU, 원본 IDF 바닥 보존, 비어 버린 존, 경계 위치).

## 결정

IDF 를 얹을 때(`attachIdf`) 층 맞추기·평면 맞추기 다음, 방과의 겹침을 재기 전에 층마다 존 바닥을 다듬는다(`trimZonesToRooms`).

- **방과 겹친 몫은 방 경계로 자른다.** 방마다 (방 ∩ 존) 조각으로 나눈다. 폭(2 × 넓이 / 둘레)이 0.6m 보다 좁거나 1㎡ 보다 작은 조각은 벽
  두께 띠로 보고, 그 방에서 가장 큰 조각을 가진 존에 붙인다. 방 안에서 어느 존도 덮지 않은 얇은 틈도 그 존이 메운다. 띠만 닿은 방은
  어느 존에도 붙이지 않는다. 정점을 옮기는 스냅이 아니라 조각마다 존을 정하는 방식이다. Ledoux & Arroyo Ohori(2017)의 pprepair(제약
  들로네 삼각분할 위에서 조각에 값을 정해 경계를 맞추는 것)를 방 단위로 줄인 것이고, 결과가 늘 유효한 다각형이다.
- **방 밖으로 나간 몫은 폭으로 가른다.** 폭 1m·넓이 2㎡ 에 못 미치는 띠(벽 중심선 몫)는 버린다. 그보다 두꺼운 덩어리는 BIM 이 방을 안
  그린 자리로 보고, 벽 형상만 빼고 IDF 외곽선 그대로 둔다. 남긴 넓이는 존의 `noRoomM2` 와 경고로 알린다.
- **창가·안쪽처럼 벽 없이 나눈 경계는 건드리지 않는다.** 방 하나를 존 여럿이 나누는 것은 오류가 아니다(ADR-0069).
- **구멍은 채운다.** 존 바닥은 바깥 고리만 담는다(`HvacZone.footprint`). 성수에서 다듬은 결과의 구멍 6개 21㎡ 가 모두 어느 존도 차지하지
  않은 자리였다.
- 방이 없는 층은 다듬지 않는다. 다 깎여 나간 존(벽 안에만 있던 것)은 IDF 외곽선 그대로 둔다. 다각형 연산이 실패한 층도 IDF 외곽선 그대로
  두고 경고한다.
- 넓이가 바뀐 존은 다듬기 전 넓이를 `idfAreaM2` 로 갖는다. GeoJSON 의 `hvacZone` feature 는 다듬은 형상을 내고 `footprintSource: "calc"`·
  `idfAreaM2`·`noRoomM2` 를 같이 적는다(ADR-0008). TTL 의 `ex:areaM2` 는 다듬은 넓이다.
- **TTL 의 `brick:hasPart` 규칙은 바꾸지 않는다.** 방 바닥의 절반 넘게를 덮는 존 하나만이다(ADR-0069, OE-IDF-05). 창가 존이 방을 갖지
  못하는 것(성수 49개 존)은 형상이 아니라 규칙의 문제라 여기서 정하지 않는다.
- 다각형 연산은 polygon-clipping(MIT)이다. 좌표를 1mm 로 맞춰 넣는다 — 반올림 없이는 성수 10F 의 교차 계산이 오류 없이 빈 결과를 냈다.

## 고려한 다른 길

성수 건축·기계 IFC + `Factorial.idf`, 존 79. IoU 는 존이 있는 층의 존 합집합과 방 합집합이다.

| 방법 | IoU | 원본 보존 | 빈 존 | 경계: 방 경계 / 벽 안 / 애매 / 열린 바닥 | 접은 까닭 |
|---|---|---|---|---|---|
| 지금(원본) | 0.672 | 100% | 0 | 17 / 30 / 9 / 44% | — |
| 방 합집합으로 자르기 | 0.824 | 78.5% | 6 | 52 / 5 / 6 / 39% | 방을 안 그린 자리의 존이 사라진다(1F 매장 셋) |
| 방 단위로 다시 짓기(존 = 넓이가 가장 큰 방들의 합) | 0.878 | 45% | 44 | 100 / 0 / 0 / 0% | 창가 존이 전부 사라지고 존끼리 124㎡ 겹친다(BIM 방끼리 겹친 자리) |
| 자르기 + 얇은 조각 정리 | 0.824 | 78.3% | 8 | 64 / 2 / 3 / 31% | 경계는 가장 깔끔하지만 자르기와 같은 문제 |
| 위 + 나뉜 방을 하위 공간으로 | 같음 | | | | 형상은 같고 TTL 에 엔티티 52개가 새로 생긴다. 창가 띠 경계는 벽이 아니라 계산 편의라 물리존이 될 수 없다(ADR-0069) |
| 층마다 ±1m·±1° 다시 맞추기 | 기준층 3F~9F 변화 없음, 10F +2%p | | | | ADR-0069 의 평면 맞추기로 충분하다 |
| 설비 위치로 방의 존 정하기 | 표가 있는 방 8개, 모두 존 여럿이 나누는 방 | | | | 존 설비를 BIM 기기로 푼 것 자체가 존 바닥 안의 점으로 정한 것이라 새 근거가 아니다 |
| **이 결정** | 0.701 (3F~9F 0.859) | 95% | 0 | 53 / 6 / 5 / 37% | — |

이 결정의 IoU 가 자르기보다 낮은 것은 방이 없는 자리 2,047㎡ 를 일부러 남겨서다. 방을 다 그린 3F~9F 에서는 0.83 → 0.86 이다.

- **임계값 하나로 정점을 스냅하기.** 작게 잡으면 맞출 짝을 놓치고 크게 잡으면 다른 곳의 다각형이 선으로 무너진다(Ledoux & Arroyo Ohori 2017).
  조각에 존을 정하는 방식은 폭 임계값이 조각을 띠로 볼지만 정하고 정점은 옮기지 않는다.
- **직접 짠 다각형 연산(`polygon.ts`).** 방 나누기·합치기는 실제로 생기는 경우만 풀고 나머지는 거절한다. 존과 방의 교차·차집합은 오목한
  모양과 구멍이 흔해 거절할 수 없다.

## 결과

- 성수(`Factorial.idf` + 건축 IFC, `check:sample`): 다듬은 존 66 · 깎은 넓이 573㎡ · 방 없는 자리를 IDF 그대로 둔 존 20(1F·2F 매장, 기준층
  aux 의 계단실, 10F 오른쪽 아래) 2,047㎡ · 연산 실패 0 · 벽 안을 지나는 경계 30% → 5% · 기준층 존 일곱 그대로(창가 띠 넷이 사무실 하나를
  나눈다) · 얹기 0.4초. 방에 든 물리존(67)과 걸친 방(9)은 거의 그대로다 — 창가·안쪽 분할이 그 숫자를 정한다.
- 다듬기는 IDF 를 얹을 때 한 번이다. 얹은 뒤 사람이 방 경계를 고치면 다시 다듬지 않는다(IDF 를 다시 얹거나 놓는 법을 고치면 다시 다듬는다).
- 되돌리려면 `attach.ts` 의 "바닥 다듬기" 블록과 `trim.ts` 를 걷어내고, `HvacZone.idfAreaM2`·`noRoomM2` 와 GeoJSON 의 같은 칸,
  `polygon-clipping` 의존성을 지운다.
