# ADR-0064 판본 비교의 정규화와 모호

## 맥락

OE-BIM-19 가 "단위·좌표·식별 정보를 정규화하여 판본을 비교한다" 와 "GUID 유지율의 분모·파일 역할과 추가/삭제/변경·미매칭/모호를 구분한다" 를 더했다
(2026-10-12). 짝짓기(`matchFingerprints`)는 GUID → Revit 요소 ID → 이름 → 위치 순이고, 위치는 설비 5cm·물리존 25cm 안에서 서로 하나뿐일 때만 짓는다.
그래서 원점을 옮겨 다시 낸 판본은 이름 없는 설비를 하나도 못 찾고, 길이 단위 선언이 틀린 판본(Duplex COBie Design, 1/1000)은 위치로 짓지 못하며
넓이가 전부 "바뀐 것" 으로 나왔다. 한 열쇠에 후보가 여럿이면 짓지 않는데, 그것이 "없어진 것·새것" 에 섞여 고객사에 할 말이 흐려졌다. Duplex MEP → MEP-2 는
같은 번호·이름의 방이 겹쳐 물리존 10개가 그랬다(없어진 것 5 · 새것 1 과 따로).

## 결정

- **단위**: 이름이 같은 층의 높이가 단위 배수로 다르면(ADR-0007 의 `storeyScaleMismatch`) 이전 판본의 좌표를 그 배수로, 넓이를 그 제곱으로 맞춘 뒤 견준다.
- **원점**: 위치를 빼고 GUID·Revit 요소 ID·이름으로 먼저 짝지어, 짝지은 설비의 좌표 차이 중앙값을 잰다. 짝이 3개 이상이고, 중앙값이 0.25m 이상이며,
  짝의 60% 넘게가 그 차이에서 5cm 안이면 원점이 옮겨진 것으로 보고 이전 판본 좌표를 그만큼 옮긴 뒤 위치로 짓고 옮김을 잰다(`originShift`).
  나머지는 실제로 옮긴 설비다.
- **식별 정보**: 이름·Revit 요소 ID 는 NFC·겹친 공백·앞뒤 공백을 맞춰 견준다(`normalizeKey`). 대소문자는 가른다. 편집 파일에 적는 지문은 바꾸지 않는다.
- **모호**: 짝을 못 지은 것 중 한 판본 안에서 같은 이름·Revit 요소 ID 가 겹쳤거나, 짝짓기가 후보 여럿을 본 것은 `ambiguous` 로 따로 센다. `added`·`removed`
  (미매칭)에는 넣지 않고, GUID 유지율의 분모(양쪽에 있는 것 = 짝지은 것)에도 넣지 않는다.
- **화면**: 기준 파일(지금 연 파일)과 견줄 판본을 적고, 맞춘 것(단위 배수·원점 이동·이름 정규화)을 한 줄로 보인다. 표에 분모·`GUID 그대로/분모`·없어짐·새것·
  짝 후보 여럿 칸을 둔다.

## 고려한 다른 길

- **원점을 IfcMapConversion·IfcSite 배치로 맞춘다.** 원점을 옮긴 판본이 지도 변환을 같이 바꾸리라는 보장이 없고, IFC2x3 에는 자리가 없다(R7). 짝지은 것의 실제
  좌표 차이가 판본 사이의 이동을 바로 말한다.
- **평균으로 잰다.** 실제로 옮긴 설비 몇 대가 평균을 끌어 원점 이동이 틀린다. 중앙값과 "60% 넘게 같은 차이" 로 막는다.
- **대소문자도 맞춘다.** `AHU-1` 과 `ahu-1` 이 한 모델에 따로 있으면 틀린 짝이 된다. 틀린 짝이 못 찾은 것보다 나쁘다는 짝짓기 원칙(versions.ts 머리)을 따라
  맞추지 않는다. 가진 파일에서 대소문자만 다른 이름을 따로 세어 보지는 않았다.
- **모호를 미매칭에 둔다(지금까지).** 없어진 것이 아니라 어느 것과 같은지 모르는 것이라, 고객사에 할 말(이름·태그를 하나뿐이게)이 다르다.

## 결과

- 원점을 옮겨 다시 낸 판본도 위치로 짝짓고, 옮긴 것으로 잘못 세지 않는다. Duplex 판본끼리는 원점·단위가 같아 짝 수가 그대로다(check:sample).
- 편집 파일 재적용(`applyEdits`)은 같은 `matchFingerprints` 를 쓰므로 이름 정규화의 덕을 같이 본다. 원점·단위 정규화는 판본 비교(`compareVersions`)에만 있다.
- 되돌리려면 `compareVersions` 의 정규화 두 단계와 `originShift` 를 걷고, `matchFingerprints` 의 `normalizeKey`·`ambiguous` 를 걷는다.
