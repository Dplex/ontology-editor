# ADR-0043 버전 파일은 내용으로 나눈다

## 맥락

ADR-0037 은 반영마다 버전 폴더 하나에 TTL·GeoJSON·GLB·편집 파일을 통째로 두고, 1주가 지난 버전은 히스토리에서만 감춘다. 합성 성수는 버전 하나가
232MB(GLB 214MB)라 반영·되돌리기 셋에 696MB 를 썼다. 되돌리기는 옛 버전을 그대로 복사했고, 흐름 방향만 고친 반영도 GLB 를 새로 두었다.

## 결정

- 반영할 때 판의 파일마다 SHA-256 을 재 `meta.json` 의 `hashes` 에 적는다. 앞 버전에 같은 해시의 파일이 있으면 그 파일에 **하드 링크**하고 `shared` 에 적는다.
- 되돌리기는 옛 버전의 파일을 복사하지 않고 링크한다.
- 링크를 못 거는 파일시스템이면 복사로 둔다(지금과 같다).
- 버전 파일은 반영 뒤 고치지 않으므로 링크해도 다른 버전이 바뀌지 않는다. 지울 때도 링크 수만 준다.

## 고려한 다른 길

- **내용 주소 저장소(blobs/<hash>)와 버전 폴더의 목록 파일.** 서버 읽기 경로를 다 바꿔야 한다. 하드 링크는 버전 폴더가 지금 모양 그대로다.
- **화면이 해시를 먼저 묻고 같으면 올리지 않기.** 올리는 시간(사내망 224MB 수 초)도 준다. 디스크가 먼저라 서버만 바꿨다 — 다음 단계로 둔다.
- **GLB 에서 이름(extras)을 빼 형상만 두기.** 층·설비 이름을 바꿔도 GLB 를 나눌 수 있지만, DT 쪽이 extras 를 읽는지 모른다(D11 질문).

## 결과

- 합성 성수: 반영·반영·되돌리기 696MB → 447MB(되돌리기가 v1 의 26개 파일을 모두 나눔). 층 이름만 고친 반영은 GeoJSON 20개를 나누고 GLB 는 새로 생긴다(층 이름이 GLB 의 층 노드에 있다).
- GLB 는 같은 모델이면 바이트까지 같다(mesh3d.test.ts). 흐름 방향·확정·연결처럼 형상·이름과 무관한 편집만 한 반영은 GLB 를 나눈다.
- 되돌리려면 layouts.ts 의 `dedupe`·`linkOrCopy` 를 걷어내고 되돌리기를 `cpSync` 로 돌린다. 이미 링크된 버전은 그대로 읽힌다.
