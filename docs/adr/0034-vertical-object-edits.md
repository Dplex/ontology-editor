# ADR-0034 수직 관통 오브젝트 옮기기·지우기·층별 고치기

## 맥락

OE-ML-07 은 다중층 편집 모드에서 수직 관통 오브젝트를 통째로 옮기고(모든 층 형상·연결 지점에 같은 이동량), 벽·물리존 경계와 충돌하면
V-03 을 보이되 막지 않으라고 한다. OE-ML-09 는 지우기 전에 영향을 보이고, 지우면 층별 표현과 참조를 걷되 BIM 원본과 연관 물리존은
남기며, 재임포트만으로 되살아나지 않게 하라고 한다. 둘 다 "여러 층의 관련 변경을 하나의 이력으로 되돌리고 저장 복원" 한다.
ADR-0033 은 오브젝트를 층별 조각(`Storey.verticalParts`)으로 두고 연관 물리존을 저장하지 않기로 했다. ADR-0032 는 다중층 작업 하나를
편집 이력 하나로 대신하기로 했다.

가진 BIM 의 계단 조각을 원래 자리와 x 로 1m 옮긴 자리에서 쟀다(2026-10-09):

| | 벽과 겹친 넓이 | 한 물리존이 담는 몫 |
|---|---|---|
| 병원 계단 3개(1층 조각) 원래 자리 | 0 · 0.26 · 0 ㎡ | 100 · 95.5 · 100 % |
| 같은 계단 +1m | 0.77 · 0.77 · 0.28 ㎡ | 62 · 60 · 80 % |
| Duplex 계단 2개 원래 자리 → +1m | 0.13 → 1.44 · 0.13 → 0.44 ㎡ | 100 → 99 · 98 → 99 % |
| FZK 나선 계단 원래 자리 → +1m | 0 → 0 ㎡ | 100 → 100 % |

원래 자리에서도 계단판 끝이 벽 두께에 들어 0.26㎡ 까지 겹친다. 그래서 겹침의 절대값으로는 충돌을 가를 수 없다.

## 결정

- **편집은 다중층 뷰에서만, 오브젝트 단위로 한다.** 층 편집 화면은 읽기 전용 그대로다(OE-ML-05). 다중층 뷰에서 고른 오브젝트는
  방향키(10cm, Shift 1m)·패널의 Δx·Δy 로 옮기고, Delete·[지우기] 로 영향을 보인 뒤 한 번 더 물어 지운다. 그 밖의 편집 키·도구 상자는
  다중층 뷰에서 끈다(되돌리기·다시 하기는 된다). 설비는 고르고 보기만 한다(패널 잠금). 만들기(OE-ML-06)·구간 바꾸기(OE-ML-08)는 다음이다.
- **층별 고치기는 고른 층 조각에만 한다**(OE-ML-07 후반, 2026-10-09 더함): 3D 의 꼭짓점 손잡이로 그 층 형상(크기 포함), 패널로 그 층 조각만
  옮기기·진입/종료 지점 x·y. 다른 층 조각은 그대로다. 변이 교차하는 형상은 적용하지 않고 손잡이를 되돌린다. 다중층 뷰는 편집 모드를 꺼 둔 채
  손잡이만 끌게 한다(`viewer.setHandleEdit`) — 편집 모드를 켜면 고른 설비도 끌린다.
- **옮기기는 모든 층 조각의 형상·진입/종료 지점에 같은 x·y 를 더한다.** 높이는 그대로다. 옮긴 조각에 `edited` 를 단다 —
  GeoJSON 은 `source`(처음 온 곳, bim)를 두고 `edited: true` 를 따로 낸다(OE-ML-02 "원본과 보정 구분"). 숫자가 아닌 이동량은 적용하지 않는다.
  `edited` 는 ADR-0008·0018 의 `…Source`(관계의 출처: bim·calc·edit)와 다른 축이다 — 관계가 아니라 오브젝트 형상이 BIM 원본인지 보정인지를
  말한다. 물리존 외곽선·설비 좌표처럼 다른 형상 편집은 아직 이 표시를 내지 않는다(OE-ML-02 만 원본·보정 구분을 수용 기준으로 요구한다).
- **지우기는 모든 층 조각을 걷는다.** 물리존은 그대로다. 연관 물리존·층간 연결은 저장하지 않으므로(ADR-0033) 고칠 것이 없다 — 옮기면 새
  자리의 물리존이, 지우면 겹침 추정(ADR-0032, `calc`)이 그 자리를 잇는다. 지운 계단을 가리키는 GeoJSON 참조는 생기지 않는다.
- **되돌리기는 모든 층의 조각 목록을 통째로 뜬 스냅샷 하나다**(`edit.ts` 의 `verticals`). 조각은 계단마다 지나는 층 수만큼이라 적다(병원 6개).
- **편집 파일은 연 때와 견준 결과만 적는다**: 오브젝트마다 `move`(첫 층 조각 기준점의 x·y 차) 또는 `removed`. 모든 층 조각이 연 때
  조각에 같은 이동량을 더한 모양이 아니면(층별로 고쳤으면) `move` 대신 `parts` 에 모든 층 조각의 끝 모양(형상·진입·종료)을 적는다.
  불러올 때 연 때와 다른 조각에만 `edited` 를 단다. 층 하나의 것이 아니라
  층별 임시 저장본에서는 건물 조각(`*`)에 든다. 불러올 때는 같은 GUID 의 계단에 이동량을 다시 더하거나 다시 지운다. 그래서 지운 계단은
  BIM 을 다시 열어도 편집 파일이 다시 지운다. 못 찾은 GUID 는 `missing.elements` 로 센다.
- **V-03 은 연 때 형상과 견준다.** 층마다 조각 형상이 연 때보다 벽과 **0.1㎡ 넘게 더** 겹치거나, 한 물리존이 형상의 **90% 미만**을
  담으면(연 때부터 그 아래였으면 연 때보다 5%p 더 내려가면) 그 층을 적는다. 막지 않는다. 형상이 없는 조각(끝 층 지점)은 재지 않는다.
  연 때 형상은 baseline 에 둔다(`Baseline.verticals`).
- **3D 누르기는 조각과 설비의 거리를 견준다.** 여러 층을 함께 보면 위층 조각 너머에 아래층 설비가 보인다. 설비가 늘 먼저면 위층 계단을
  누를 수 없어, 광선이 먼저 닿는 쪽을 고른다(추가 공간 오브젝트와 같은 규칙).

## 고려한 다른 길

- **편집 파일에 늘 조각을 통째로 적는다.** 단순하지만, BIM 이 계단을 고쳐 다시 낸 판본에서 원본 고침을 덮는다. 전체 이동만 한 계단은
  이동량만 적어 보정만 다시 얹고, 층별로 고친 계단만 통째로 적는다(이동량 하나로는 다시 만들 수 없다).
- **V-03 을 겹침의 절대값으로 가른다.** 원래 자리의 병원 계단 하나가 벽과 0.26㎡ 겹쳐, 0.1㎡ 기준이면 옮기지 않아도 경고가 뜬다.
- **다중층 뷰에서 다른 편집도 그대로 둔다.** 여러 층이 겹쳐 보이는 화면에서 설비를 끌면 어느 층 것을 끄는지 헷갈리고, OE-ML-01 은 모드에
  맞는 대상만 고치라고 한다. 설비·배관의 층간 편집은 라이저(OE-ML-12)와 같이 연다.

## 결과

- 병원 건축에서: 계단 하나를 1m 옮기면 1·2층 조각이 같이 가고 1층에 V-03(벽·경계)이 뜬다. 되돌리기 한 번이 한 이동이다. 지우면 조각
  6 → 4, 이은 STAIR ↔ STAIR 연결은 겹침 추정이 다시 잰다. 편집 파일로 저장해 다시 연 BIM 에 얹으면 같은 모습이다(`e2e/vertical-edit.spec.ts`).
- 개구부(OE-ML-03)·EL 정차 층·ES 운행 구간·샤프트 배관 소속은 데이터가 아직 없어 지우기 확인에 나오지 않는다.
- 되돌리려면 `src/lib/vertical-edit.ts`, `edit.ts` 의 `verticals` 스냅샷·`Baseline.verticals`·`diffVerticals`, `edit-file.ts` 의 `verticals`,
  App 의 다중층 편집 묶음을 걷는다. 그러면 다중층 뷰는 ADR-0032 순서 ④ 의 보기로 돌아간다.
