# ADR-0061 편집기 3D 옆 결과 비교 판은 지금 모델을 내보내기와 같은 함수로 쓰고 받는 쪽 규칙으로 다시 읽은 것을 워커에서 만들어 보이며, 고르기는 id 하나로 양쪽이 같고 평면은 3D 시점을 따라간다

## 맥락
"BIM 의 이 설비가 온톨로지의 어느 줄이 되나" 를 보려면 내보내기를 해서 파일을 받은 뒤 내보낸 파일 뷰어(viewer.html, ADR-0005)에 다시 놓아야
했다. 편집할 때마다 같은 일을 되풀이해야 했고, 편집기에서 고른 것과 뷰어에서 고른 것을 사람이 이름으로 맞춰야 했다.
2026-10-13 에테리온 데모(Revit 원본과 웹 뷰어를 좌우로 놓고 한쪽에서 고르면 양쪽이 같은 요소를 칠하는 화면)를 보고 희록님이 반영을 요청했다.

- 받는 쪽이 읽는 것은 모델이 아니라 파일이다. 모델에는 있는데 파일에서 빠진 것(덕트·배관의 `fso:` 주어, TTL 에 없는 feature)은 모델을
  그리는 편집기 3D 에서는 보이지 않는다.
- GeoJSON 좌표는 모델과 같은 건물 로컬 미터·같은 축이다(geojson.ts). 3D 가 바라보는 점을 그대로 평면 좌표로 쓸 수 있다.
- 쓰고 다시 읽는 시간(워커 안): Duplex MEP 16~22ms(주어 187 · feature 948), 성수 건축 70ms(주어 1,735 · feature 3,661). 판을 켜고 다 뜨기까지
  Duplex 0.2초, 성수 건축 0.9초 — 대부분 모델을 워커로 넘기는 사본 시간이다.

## 결정
- 시점 막대의 [결과 비교] 를 켜면 3D 칸 오른쪽에 판(ExportCompare.vue)이 뜬다. 판은 지금 모델을 내보내기와 같은 함수(`modelToTTL`·`modelToGeoJSON`)로
  쓰고 그 글을 받는 쪽 규칙(`readOntologyTTL`·`readGeoJSON`)으로 다시 읽은 것을 그린다(`compare.ts`). 화면 스레드가 아니라 워커(`compare.worker.ts`)에서 하고,
  편집이 멈추고 0.5초 뒤에 한 번 다시 한다. 다시 쓰는 동안 앞 결과를 그대로 두고 "다시 쓰는 중" 만 보인다.
- 고르기는 GlobalId 하나다. 3D·표·패널에서 고른 것(설비·물리존·룸·벽·문·창·존·오브젝트·수직 관통 조각)을 판이 칠하고, 판의 평면이나 관계 목록에서
  누르면 편집기가 같은 길(설비는 `select`, 물리존은 바닥 누르기 `pickSpace` + 비추기)로 고른다.
- 판의 평면은 3D 를 따라간다(`viewer.onView`, 프레임마다 한 번). 바라보는 점이 평면 가운데, 3D 화면 가로가 덮는 길이가 평면 폭이다. [3D 따라가기] 를 끄면 층 전체다.
  층은 3D 가 보는 층, 모든 층이면 고른 것의 층이다.
- 카드에는 TTL 주어 클래스, 그 블록 원문, 나가는·들어오는 관계(hasLocation·feeds·hasPart·hasPoint), GeoJSON feature, 받는 쪽이 아는 출처(`…Source` 속성)를 보인다.
  파일에 없으면 "내보낸 파일에 없습니다", TTL 에 없고 GeoJSON 에만 있으면 그렇다고 적는다. TTL 에 없는 feature 는 평면에 붉게 그린다.
- 평면 모양은 내보낸 파일 뷰어와 같이 쓴다(`plan-shapes.ts`).

## 고려한 다른 길
- 오른쪽에 내보낸 GLB 3D 를 띄운다 — 성수 GLB 는 214MB 이고 만드는 데 3~4초씩 걸린다(mesh3d.worker). 형상은 편집기 3D 와 같아 비교할 거리가 적고,
  받는 쪽이 의미를 읽는 곳은 TTL·GeoJSON 이다.
- 화면 스레드에서 모델을 바로 읽어 카드를 만든다 — 빠르지만 파일에서 빠지는 것이 판에서도 보여, "받는 쪽이 읽는 것" 을 보인다는 판의 뜻이 사라진다.
- 내보낸 파일 뷰어를 iframe 으로 붙인다 — 파일을 놓는 길이라 편집할 때마다 다시 놓아야 하고, 고르기를 잇기 어렵다.

## 결과
- 편집할 때마다 모델 사본을 워커로 넘긴다(판이 열렸을 때만). 성수 건축에서 0.9초쯤 판이 앞 결과를 보인다.
- 평면은 3D 시점의 가로 길이를 따르므로, 비스듬히 보는 시점에서는 3D 와 평면의 넓이가 다르게 보인다(평면은 위에서 본 것).
- 편집 리플레이에서 "편집 전 BIM | 편집 후 온톨로지" 로 나눠 보이는 것은 아직 하지 않았다 — 리플레이 장면 카드(replay.ts)가 이미 장면마다 TTL·GeoJSON 변화를 보인다.
- 되돌리려면 App.vue 의 `--- 내보낸 결과와 나란히 보기 ---` 절과 [결과 비교] 단추·판, `viewer.ts` 의 `onView`, `compare.ts`·`compare.worker.ts`·`ExportCompare.vue` 를 뺀다.
  `plan-shapes.ts` 는 내보낸 파일 뷰어가 계속 쓴다.
