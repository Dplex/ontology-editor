# ADR-0030 덕트·배관 구간의 경로

## 맥락

OE-PIP-13 은 유효한 x·y·z 경로가 있는 배관만 3D·GeoJSON 에 내고, 설비의 배치점 하나로 경로를 만들지 말라고 한다. 지금까지 GeoJSON 은
덕트·배관 구간도 다른 설비처럼 배치점 하나(`Point`)로 냈다. 경로는 3D 메시에만 있었고, 모델에는 끝을 옮긴 양(`endShift`)만 있었다.

구간의 경로를 어디서 얻을지가 문제였다. 메시는 모델 밖(`MeshMap`)에 있어서 GeoJSON 을 만드는 쪽이 볼 수 없다.

## 결정

- **임포트가 구간마다 형상의 중심선 두 끝을 모델에 남긴다**(`Equipment.axis`). 3D 의 끝점 추종과 같은 식(`segmentAxisOf`)이고 0.1mm 로
  반올림한다. 형상이나 배치점이 없는 구간에는 남기지 않는다.
- **중심선은 연 때 배치점에서 잰 상대 좌표다.** 구간을 통째로 옮기면 `position` 만 바뀌고, 끝을 늘이면 `endShift` 와 `position` 이 같이 바뀐다.
  상대로 두면 지금 경로를 `position`·`endShift` 두 값으로 늘 다시 세울 수 있다(`segmentPath`). 절대 좌표로 두면 통째로 옮긴 구간의 경로가
  제자리에 남는다.
- **GeoJSON 은 경로가 있는 구간을 `LineString`(두 끝, z 포함)으로 낸다.** 경로를 쓸 수 없는 구간은 `geometry: null` 에 `pathIssue`
  (좌표 없음 · 형상 없음 · 수치 오류 · 길이 0)를 적는다. 이음쇠와 기기는 지금처럼 `Point` 다.
- **형상 미반영과 의미는 따로다.** 경로가 없어도 연결·계통·방향은 TTL 에 그대로 나간다(TTL 은 좌표를 갖지 않는다, intent.md).
- 경로를 쓸 수 없는 구간은 완전성 검사 `conduit-path` 가 까닭과 GlobalId 로 보인다. 이것이 OE-PIP-13 의 "미반영 목록" 이다.

실측(형상과 같이 연 모델):

| | 구간 | 경로 있음 | 모델 크기 |
|---|---|---|---|
| Duplex HVAC | 231 | 231 | +13KB / 0.3MB |
| 병원 HVAC | 1,548 | 1,548 | +90KB / 2.3MB |
| 병원 MEP | 5,952 | 5,952 | +342KB / 9.0MB |
| 성수 기계 | 7,874 | 7,874 | +462KB / 10.7MB |

- 연 때 경로와 3D 메시의 중심선 차이: 0.08mm 이하
- 꺾임 이음쇠 200개를 옮긴 뒤 늘인 끝의 어긋남: 최대 0.4mm(Duplex) · 3.95mm(병원) · 0.8mm(성수). 배치점이 중심선에서 조금 떨어진 구간에서
  끝점 추종이 잡는 축 위 비율이 미세하게 달라서 생긴다
- 구간을 통째로 0.5m 옮긴 뒤 경로의 어긋남: 0

## 고려한 다른 길

- **GeoJSON 을 만들 때 메시를 넘긴다.** 내보내기가 메시에 묶여, 메시 없이 연 모델(테스트·검사 스크립트·편집 파일만 다시 얹은 모델)에서 결과가 달라진다.
- **경로를 절대 좌표로 둔다.** 통째로 옮긴 구간(끝을 늘인 적이 없으면 `endShift` 가 없다)의 경로가 따라가지 않는다. S1(GUID 가 바뀐 판본에 편집 다시 얹기)
  실측에서 드러났다.

## 결과

- GeoJSON 을 읽는 쪽은 `kind: "equipment"` 에서 `Point` 와 `LineString` 을 함께 받아야 한다. 이 repo 의 읽는 쪽(`read-export.ts`·`read-3d.ts`)은 받는다.
- 형상이 없는 구간을 미배치 목록에서 점 하나로 놓아도(OE-MAN-04) 경로가 생기지 않는다. GeoJSON 형상은 비고 `pathIssue` 가 남는다.
- 되돌리려면 `src/lib/export/geojson.ts` 의 `equipmentFeature` 에서 `segmentPath` 분기를 걷어내면 모든 구간이 다시 `Point` 로 나간다.
  `axis` 는 남아도 해가 없다.
