# ADR-0046 합칠 때 좌표계 어긋남(오프셋) 추정

## 맥락

OE-BIM-22 는 원점이 다른 두 파일을 열면 경고와 함께 x·y·회전 오프셋 값을 보이라고 한다(그 값으로 임포트 단계에서 맞춘다, OE-INT-04). 합치기(`merge.ts`)는
덧붙인 파일의 설비가 기준 파일 공간 범위에 얼마나 드는지로 어긋남을 잡았지만 "얼마나" 는 말하지 않았다. 두 파일에 공통 기준점(측량점)이 적혀 있지 않고,
IfcMapConversion 은 IFC4 부터라 가진 IFC2x3 파일에는 없다.

## 결정

- **같은 방 번호 쌍**: 층을 이름·높이로 맞춘 뒤(`matchStorey`), 층 안에서 하나뿐인 방 번호(Revit 기본 이름 "공간" 등은 뺀다)가 양쪽에 있으면 외곽선 넓이 중심을 짝짓는다.
  Revit 설비 판본의 MEP Space 는 건축 Room 을 베껴 번호가 같다.
- 쌍이 둘 이상이고 1m 넘게 퍼져 있으면 2D 최소제곱(Kabsch)으로 덧붙인 좌표를 기준에 겹치는 회전(원점 둘레, 반시계 +)과 이동을 구한다. 남는 차(제곱평균제곱근)를 같이 적는다.
- 쌍이 모자라면 두 파일이 차지한 범위(기준: 물리존 외곽선, 덧붙임: 외곽선과 설비 좌표)의 중심 차만 적고, 회전은 모른다고 적는다. 내용이 다른 두 파일의 범위라 대략값이다.
- 값은 합치기 보고서(`report.offset`)에 늘 두고, 경고 문장에는 정렬이 어긋났을 때만 붙인다. 모델 좌표는 바꾸지 않는다 — 맞출지는 사람이 정한다(OE-INT-04).

## 고려한 다른 길

- **IfcSite·IfcMapConversion 의 값 견주기.** 가진 IFC2x3 파일에는 MapConversion 이 없고, Site 배치는 두 판본이 같아도 프로젝트 원점이 다를 수 있다. 실제 형상이 겹치는지를 재는 쪽이 원인과 상관없이 맞다.
- **설비 좌표로 짝짓기.** 건축 파일에는 설비가 없다. 방은 두 판본에 다 있다.
- **바로 맞춰 합치기.** 쌍이 잘못 짝지어지면(번호 재사용) 설비 수백 대가 틀린 자리에 조용히 놓인다. 값을 보이고 사람이 고르게 둔다.

## 결과

- 실측: Duplex 건축+MEP 18쌍 회전 0° · 이동 0, 병원 건축+MEP 261쌍 회전 0° · 이동 2cm, 병원 건축+HVAC 250쌍 회전 -0.2° · 남는 차 1.88m(번호가 같은데 자리가 다른 방이 섞임). 거짓 경고는 늘지 않는다(경고는 정렬 비율로만 낸다).
- 시험: `merge.test.ts`(범위 중심 · 30° 돌리고 옮긴 판본 복원 · 같은 좌표계 0) · `check-sample.test.ts`(Duplex·병원).
- 되돌리려면 `align.ts` 와 `MergeReport.offset` 을 걷어낸다.
