# ADR-0012 커스텀존 별명은 여러 개다 — 첫 이름이 rdfs:label, 나머지는 ex:alias

## 맥락

ADR-0004 는 커스텀존 별명을 하나로 정했다. OE-OBJ-01(prd-done)은 "커스텀 존 당 1개", 용어집·OE-SPC-06(prd-review)은 "별명 복수" 라
서로 달랐고, prd-done 쪽을 따랐다. 이를 **여러 개**로 바꾼다. 같은 공간을 사람마다 다르게 부르기 때문이다(임원석 · 임원 구역 ·
경영진석). Agent 가 어느 이름으로 물어도 존을 찾을 수 있어야 한다.

## 결정

- 모델: `CustomZone.name`(첫 이름) + `aliases?: string[]`(더 붙인 별명). 별명은 앞뒤 공백을 지우고, 빈 것·이름과 같은 것·중복을 뺀다.
  별명이 없으면 이 key 가 없다(별명 기능 이전과 같은 형식)
- TTL: 첫 이름이 `rdfs:label`, 나머지는 `ex:alias "…", "…"`. `rdfs:label` 을 여럿 두지 않는다 — 수신 측은 블록의 label 을 하나만
  읽고(read-ttl.ts), 여러 개면 어느 것이 이름인지 알 수 없다
- GeoJSON: 커스텀존 feature 의 `properties.aliases`(없으면 이 항목이 없다)
- 편집 파일: `customZones` 의 존마다 `aliases`
- 두 존을 합치면 없어지는 존의 이름·별명이 합친 존의 별명으로 남는다 — 그 이름으로 부르던 사람이 찾을 수 있게
- 나누면 새 조각은 `이름 2` 이고 별명을 물려받지 않는다(어느 조각이 그 이름의 공간인지 알 수 없다)
- 검색: 설비를 찾을 때 그 설비가 속한 커스텀존의 이름·별명으로도 찾는다("임원석" 을 입력하면 그 존 안의 설비)

## 결과

- 수신 측이 `ex:alias` 를 읽어야 별명으로 찾을 수 있다. 읽지 않으면 첫 이름만 보인다(지금과 같다) — 수신 측에 알려야 한다
- 되돌리려면: `aliases` 를 지우고 TTL·GeoJSON 의 해당 줄·항목을 빼면 된다. 편집 파일의 `aliases` 는 예전 화면이 무시한다
