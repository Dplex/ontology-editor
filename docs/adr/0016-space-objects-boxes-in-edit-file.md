# ADR-0016 추가 공간 오브젝트는 바닥에 선 축 정렬 상자로 두고, 넣은 3D 모델은 편집 파일에 담는다

## 맥락

추가 공간 오브젝트(OE-OBJ-09)는 책상·의자·소파처럼 공간을 꾸미는 사물이다. 라이브러리에서 골라 놓고(OE-SPC-14), 사람이
3D 모델을 넣어 종류를 늘릴 수 있으며(OE-P3-08), 서로 겹칠 수 없다(OE-OBJ-16). 처음에는 BIM 에 이 오브젝트가 없어 사람이 놓은 것만
있었다. 2026-10-13 에 성수 10층 인테리어(가구 314개)와 조경 파일(스테이지·지형·주변 건물 매스 131개)이 와서 BIM 에서도 받는다(아래
"BIM 에서 받는 오브젝트"). 정해야 할 것은 넷이었다.

- 모양과 자리를 무엇으로 둘까
- 겹침을 무엇과 견줄까
- 넣은 모델 파일을 어디에 둘까
- 온톨로지(TTL·GeoJSON)로 낼까

## 결정

**오브젝트는 층 바닥에 선 축 정렬 상자다.** 데이터는 바닥 가운데 자리(`at`)와 가로·세로·높이(`size`), 라이브러리 항목
열쇠(`item`)뿐이다(`Storey.spaceObjects`). 3D 는 항목의 모델을 그 상자에 맞춰 축마다 늘려 그린다.

- 내장 항목 17개(책상·2인 책상·회의 테이블·의자·소파·책장·파티션·칠판·화분·캐비닛·TV·사무기기·위생도기·가구·주변 건물·지형·스테이지)는 상자 조각 몇 개로 만든 모델이다.
  뒤의 여덟은 BIM 에서 받으려고 더했고(2026-10-13) 사람도 골라 놓을 수 있다. 조각은
  항목 상자 안의 비율 좌표라서 크기를 바꾸면 비율대로 늘어난다(`space-object.ts` 의 `LIBRARY`).
- 돌리기는 두지 않았다. 사무 가구는 대부분 벽이나 다른 가구와 나란히 놓는다. 필요해지면 `rotation` 하나를 더하고 상자를
  돌린 외곽으로 겹침을 잰다.

**겹침은 추가 공간 오브젝트끼리만 견준다.** OE-OBJ-16 의 표가 "추가 공간 오브젝트: 불가" 로 적은 범위를 그대로 따랐다.
점유 영역은 바닥에서 높이만큼 선 상자이고, 맞닿음 여유는 설비와 같은 1cm(`OVERLAP_TOLERANCE`)다. 모든 층의 오브젝트와
견준다. 겹침은 3차원 자리로 정하고 층 소속은 상관없다. 설비·벽과는 견주지 않는다.

**넣은 모델은 glb 바이트를 그대로 편집 파일에 담는다**(`objectLibrary`, base64). 편집 파일이 이 에디터의 유일한 저장 단위라서,
모델을 다른 데 두면 편집 파일을 다른 PC 에서 열었을 때 오브젝트의 모양을 잃는다.

- 편집 파일에는 놓인 오브젝트가 쓰는 항목만 남긴다. 넣고 안 쓴 모델까지 저장할 때마다 실으면 파일만 커진다.
- 모델 파일 상한은 1MB 다(`MODEL_MAX_BYTES`). 편집 파일은 자동 저장·임시 저장으로 브라우저 저장소(사이트마다 약 5MB)에 두
  벌 남는다. base64 로 1.33배가 되면 1MB 모델 두 벌이 2.7MB 다.
- glTF 재질(PBR)은 읽을 때 Lambert 로 바꾼다(docs/dev/ui-notes.md).

**온톨로지로는 층 GeoJSON 에만 `kind: "spaceObject"` 로 내보내고 TTL 에는 넣지 않는다**(ADR-0023). PRD 는 "레이아웃 편집 단위로는
온톨로지에 저장하고 관리한다" 고 적었지만, DT 뷰어마스터 노출은 TBD 이고 받는 쪽(OE-INT)이 쓸 클래스·속성이 정해지지 않았다
(이슈 #51 `needs-pm`).

## BIM 에서 받는 오브젝트 (2026-10-13 더함)

- **가구(IfcFurnishingElement·IfcFurniture·IfcSystemFurnitureElement)는 모든 파일에서 받는다.** 이름으로 항목을 고른다(`object-names.ts`
  — 의자·소파·회의 테이블·책상·책장·캐비닛·파티션·칠판·화분·TV·사무기기·위생도기, 모르면 가구).
- **방도 포트도 없는 파일의 Proxy 는 주변 모델로 받는다**(지형·스테이지·그 밖은 주변 건물). 방이 있는 건축 파일의 남은 Proxy(캐노피·단열
  모서리)와 포트가 있는 설비 파일의 남은 Proxy(MCC·발전기)는 지금처럼 읽지 않는다 — 이것까지 받으면 성수 건축만 404개가 주변 건물이 된다.
- 상자는 형상의 축 정렬 외곽이다. 형상을 읽는 임포트(`importIfcWithMeshes`)에서만 만들고 형상은 재고 버린다. 바닥에서 뜬 것(상부장·지하로
  내려간 지형)은 `base` 에 적는다. id 는 GlobalId, `source: 'bim'` 이다.
- **BIM 에서 받은 것끼리는 겹쳐도 막지 않는다**(책상 밑 의자처럼 BIM 이 그렇게 놓았다). 사람이 놓는 것과 BIM 의 것은 지금처럼 막는다.
  크기 상한 20m 도 사람이 치는 값에만 건다(주변 건물·지형은 수십 m).
- **편집 파일은 BIM 오브젝트를 연 때와 달라진 것만 적는다**(`bimObjects` — 옮김·크기·이름·종류·지움). 사람이 놓은 것처럼 끝 목록을 적으면
  열자마자 바뀐 것이 수백 건이 되고, 지운 것이 다시 열면 돌아왔다.
- 합칠 때(`merge.ts`) 맞춘 층에도 덧붙인 파일의 오브젝트를 얹는다. 전에는 맞춘 층에서는 말없이 버려졌다.
- GeoJSON 의 `spaceObject` 에 `base`·`source`(`bim`·`edit`)를 더했다. TTL 에는 여전히 넣지 않는다.
- 성수 엘리베이터 파일(`EVEV.#1~6`)은 오브젝트가 아니라 설비다 — 이름 사전의 엘리베이터에 `EVEV` 를 더해 brick:Elevator 로 받는다.

## 고려한 다른 길

- **설비와도 겹침을 막기**: 책상 위 스탠드, 책장 옆 콘센트처럼 가구와 겹쳐 보이는 설비가 흔하다. 원칙 표에 없는 쌍까지
  막으면 BIM 그대로의 설비 옆에 가구를 못 놓는다.
- **모델 파일을 8084 서버에 따로 올리기**: 저장소 하나가 더 생기고, 파일로 내려받은 편집 파일만으로는 모양이 돌아오지 않는다.
- **모델 크기를 넣을 때 고정하기(늘이지 않기)**: 크기 조절(OE-SPC-14)을 하면 모양이 상자와 어긋난다. 축마다 늘리면 상자와
  보이는 모양이 늘 같다.

## 결과

- 쉬워진 것: 겹침 판정이 상자 비교라서 400개를 놓아도 12ms 다(병원 건축 First Floor 에서 잼).
- 어려워진 것: 1MB 를 넘는 모델은 넣지 못한다. 줄이거나(glTF 압축 도구) 상한을 올려야 한다. 올리면 자동 저장이 저장소를 넘겨
  조용히 멈출 수 있다. 임시 저장은 그때 파일로 내려받는다.
- 되돌리려면 `Storey.spaceObjects`·`Model.objectLibrary` 와 편집 파일의 `spaceObjects`·`objectLibrary` 를 걷어낸다.
  다른 편집은 이 필드를 읽지 않는다.
