# ADR-0010 포트가 없는 파일에서 형상으로 연결을 추정할 때 흐름 없는 기기(조명·콘센트·감지기·비치품)는 넣지 않는다

## 맥락

포트(`IfcDistributionPort`)가 없는 파일은 메시 꼭짓점이 5mm 안에서 맞닿는 요소를 연결로 추정하고(`topology.ts` 의 `inferConnections`),
고립된 요소는 50mm 까지 범위를 넓혀 가장 가까운 요소와 연결한다(`connectGaps`). 여기에 **모든 설비**가 들어가 있었다. 이 온톨로지의 연결은 공기·물이
지나가는 경로(`brick:feeds` 의 근거)인데, 조명·콘센트·감지기·거울·소화기함은 흐름이 없다(`kinds.ts` 의 `flow: {}`).

측정(병원 건축 + MEP, 포트 없음):

- 형상 추정 연결 13,890개 중 283개가 흐름 없는 기기와 연결돼 있었다. 대부분 **천장의 조명 ↔ 디퓨저**(범위 확장 연결이 고립된 디퓨저를 옆 조명에
  연결했다)이고, 나란히 붙은 조명끼리 16쌍, 콘센트끼리·콘센트 ↔ 전선관, 욕실 부속끼리였다
- 디퓨저 수백 개는 유일한 연결 상대가 조명이었다. 덕트에 닿은 적이 없는데 연결망 검사에서 "연결됨" 으로 보였다

포트가 있는 파일 3개를 정답으로, 포트를 가리고 형상으로만 추정해 비교했다(흐름 없는 기기 포함 → 제외):

| 파일 | 포트 연결 | 정밀도 | 재현율 |
|---|---|---|---|
| 병원 HVAC | 3,693 | 99.9% → 99.9% | 87.8% → 87.8% |
| Duplex HVAC | 485 | 95.3% → 95.3% | 70.9% → 70.9% |
| ifc4Mep | 1,995 | 79.5% → 79.5% | 75.0% → 75.0% |

포트가 흐름 없는 기기를 연결하는 경우가 한 번도 없어서, 제외해도 맞는 연결은 하나도 잃지 않는다.

## 결정

형상 추정과 범위 확장 연결의 대상에서 **종류를 아는 흐름 없는 기기**(`equipmentKind(kind).flow` 가 비어 있는 것)를 제외한다(`import.ts`).
종류를 모르는 기기는 그대로 포함한다 — 흐름 여부를 모르는 것을 제외하면 맞는 연결을 잃을 수 있다. 포트가 있는 파일은 형상 추정을 하지
않으므로 바뀌지 않는다.

## 고려한 대안

- 그대로 둔다 — 틀린 연결 283개가 남고, 디퓨저가 조명에 연결돼 "연결됨" 으로 보인다. 연결망 검사가 실제보다 좋게 나온다
- 연결은 만들고 화면·export 에서 거른다 — 범위 확장 연결이 이미 그 조명을 상대로 골라서, 디퓨저가 맞는 상대(덕트 이음쇠)를 찾을 기회를
  잃는다. 제외하고 다시 돌리면 병원 MEP 에서 디퓨저 ↔ 덕트 이음쇠 1개가 새로 연결됐다
- IFC 클래스(`IfcLightFixture` 등)로 거른다 — 종류 사전에 이미 흐름 정보가 있고, 같은 기준을 완전성 검사(`checks.ts`)와 겹침 규칙
  (`overlap.ts` 의 `standalone`)이 쓴다. 기준을 하나로 유지한다

## 결과

- 바뀐 수(check:sample): 병원 건축+MEP 연결 13,890 → 13,608, 연결망에 든 기기 850 → 849/884(조명에만 연결돼 있던 말단),
  "연결 없던 설비" 경고 2,551대 중 745대 → 516대 중 464대(흐름 없는 기기를 포함하지 않는다). Duplex MEP 785 → 783(조명 ↔ 위생기구 2),
  병원 건축 2 → 0(욕실 부속끼리)
- 규칙 방향(일치·어긋남)과 포트 정답 기준 재현율·정밀도는 그대로다
- 흐름 없는 기기는 원래 연결망 검사·흐름 추적에 나오지 않아 화면에서 잃는 정보가 없다. 전기 연결(분전반 → 콘센트)을 다루게 되면 이
  결정을 다시 검토한다 — 그때는 흐름 종류(전기)를 사전에 추가해 `flow` 가 비어 있지 않게 된다
- 되돌리려면 `import.ts` 의 형상 추정 입력에서 `flows` 필터를 빼고, check:sample 의 위 숫자를 되돌린다
