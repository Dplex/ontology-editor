# ADR-0033 수직 관통 오브젝트의 데이터 모양과 계단 읽기

> 아래 "결과" 의 "편집기 화면에는 아직 그리지 않는다" 와 "사람이 고치는 것은 OE-ML-06~09" 는 그 뒤에 바뀌었다 — 층 편집 화면 표시·읽기 전용은
> OE-ML-05 PR, 다중층 뷰에서 옮기기·지우기·층별 고치기는 [ADR-0034](0034-vertical-object-edits.md) 다. 데이터 모양 결정은 그대로다.

## 맥락

OE-ML-02 는 수직 관통 오브젝트(EL·ES·계단·샤프트)를 물리존과 따로 두고, 오브젝트 id 아래 종류·출처·관통 층·층별 형상·층별 진입/종료 지점·연관
물리존 id 를 기록하라고 한다. 층별 표현은 부모 id 와 층 id 로 식별하고, 계단·ES 는 층마다 형상과 지점이 달라도 된다. OE-ML-19 는 명시된
오브젝트의 연결을 겹침 추정보다 먼저 쓰라고 한다. ADR-0032 의 순서 ② 다.

가진 BIM 7개의 계단(2026-10-09 실측):

- IfcStair 는 50개다(병원 3 · 성수 35 · Office_A 2 · Duplex 2 · FZK 1 · Institute 4 · dental 3). IfcTransportElement·IfcRamp 는 0 이다.
- Revit 은 계단을 **층 구간 하나씩** 내보내고 시작 층에 담는다(IfcRelContainedInSpatialStructure). 형상은 하위 부재(IfcRelAggregates)인
  계단판(IfcStairFlight)·참(IfcSlab)·난간(IfcRailing)·IfcMember 에 있다. FZK·Institute 는 하위 부재 없이 자기 형상이다.
- 난간을 빼면 계단 위 끝이 위층 바닥보다 0~0.17m 낮다(병원 4.52 / 2층 4.57, Office_A 4.22 / 4.27, 성수 9F 39.93 / 40.10).
  난간을 넣으면 1m 쯤 높다(병원 5.67). 자기 형상인 FZK·Institute 는 0.9m 높다.
- 성수 B1F 의 계단 하나(0.9m)와 B5F 의 둘은 한 층 안의 몇 계단이다. B5F 의 둘은 중간층 B5'F 를 지나 B4F 에 닿는다.

## 결정

- **오브젝트를 따로 두지 않고 층별 조각(`Storey.verticalParts`)을 둔다.** 조각은 `parentId`·종류·이름·출처·평면 형상·진입 지점·종료 지점을
  갖고, 같은 `parentId` 의 조각을 모으면 오브젝트다(`verticalObjects`). 층 단위 임시 저장·합치기·층별 내보내기가 다른 층 요소와 같은 길을
  탄다. 시작/끝 층·관통 층은 조각에서 나온다.
- **계단은 형상을 읽는 임포트에서 IfcStair 로 만든다.** 계단판·참만 재고 난간·IfcMember 는 뺀다(하위 부재가 없으면 자기 형상).
  - 끝 층: 시작 층보다 1m(`MIN_RISE`) 넘게 높고, 위 끝 + 0.3m(`STOREY_REACH`) 이하인 층 중 가장 높은 층. 없으면 수직 관통이 아니라 만들지
    않고 임포트 경고에 수를 적는다(성수 35 중 3).
  - 관통 층: 시작 층부터 끝 층까지. 사이 층 조각에는 형상만 있다.
  - 형상: 그 층 높이 구간에 든 점의 평면 볼록 껍질. 끝 층은 다다르는 자리뿐이라 형상이 없다.
  - 진입 지점: 아래 끝 0.2m 안 점의 평균(시작 층). 종료 지점: 끝 층 바닥 + 0.3m 아래에서 가장 높은 점부터 0.2m 안 점의 평균(끝 층).
- **연관 물리존은 저장하지 않는다.** 진입·종료 지점이 드는 같은 층 물리존을 그때 짚는다(`locate`, 겹치면 가장 작은 물리존). 사람이
  물리존을 나누거나 지워도 낡은 id 가 남지 않는다.
- **오브젝트가 이은 물리존이 먼저다(OE-ML-19).** 시작 층 진입 지점의 물리존과 끝 층 종료 지점의 물리존을 잇고(출처는 오브젝트의 출처,
  지금은 `bim`), 그 두 물리존은 겹침 후보에서 뺀다. 한쪽을 못 짚으면 잇지 않고, 짚은 쪽은 겹침 후보에 남는다. 계단실이 아닌 물리존도 잇는다.
- **GeoJSON 에만 낸다.** 조각마다 feature 하나(`kind: "vertical"`, id `<parentId>@<층 id>`)이고, 같은 오브젝트의 이웃 조각을
  `verticalConnects` 로 가리킨다. 계단은 `passable: false` 다(OE-ML-04). TTL 은 수신 측과 클래스를 정할 때까지 내지 않는다(ADR-0008 과 같은 까닭).
- **EL·ES 는 다음 PR 이다.** 샘플에 IfcTransportElement 가 없어 이름 사전 설비(엘리베이터·에스컬레이터)에서 만들어야 하고, EL 은 정차 층
  (OE-ML-10, #181)이 걸려 있다.

## 고려한 다른 길

- **모델 최상위에 오브젝트 목록을 두고 층별 표현을 그 안에 둔다.** PRD 문장에 더 가깝지만, 층 id·물리존 id 를 품은 목록이 층 밖에 생겨
  합치기(층 id 를 바꿔 맞춘다)·층 단위 임시 저장(ADR-0014)마다 따로 옮겨 적어야 한다.
- **층마다 따로 나온 계단(성수 1F→2F, 2F→3F …)을 하나의 오브젝트로 묶는다.** 수직 통로 하나를 한 id 로 보이는 장점이 있지만, 자리가 겹치는지로
  묶어야 해서 겹침 추정이 하나 더 생긴다. 지금은 BIM 의 계단 하나가 오브젝트 하나다. 층을 따라가는 것은 물리존의 `verticalConnects` 로 된다.
- **난간까지 넣어 형상을 잡는다.** 위 끝이 1m 높아져 끝 층을 넘겨짚는다(병원 5.67 이면 STOREY_REACH 를 1.2m 로 넓혀야 하고, 그러면 층고가 낮은
  건물에서 한 층을 더 건넌다).
- **연관 물리존 id 를 임포트 때 저장한다.** 물리존 편집(나누기·합치기·지우기)마다 고쳐 줘야 하고, 빠뜨리면 없는 id 를 내보낸다.

## 결과

- 가진 BIM 에서: 병원 오브젝트 3 · Office_A 2 · dental 3 은 계단이 이은 물리존 짝이 겹침 추정과 같다(대조 시험이 있다). 성수는 32 개이고
  계단이 이은 짝 26 이 겹침만의 24 를 모두 품고, 둘이 더해졌다(B5F↔B4F 는 사이 층을 건넌다, B1F 로비↔1F 계단실). FZK(거실↔갤러리)·
  Institute(층마다 복도)는 계단실 종류가 없어 겹침으로는 0 이었다가 이어진다. Duplex 는 2층 복도에 외곽선이 없어 0 그대로다.
- 물리존의 `verticalConnectsSource` 는 계단이 이은 것이 `bim` 이다. 병원 기준선(`check:sample` 의 `HOSPITAL_VERTICAL`)이 `bim` 으로 바뀌었다.
- 편집기 화면에는 아직 그리지 않는다(ADR-0032 순서 ③ 층 편집 읽기 전용). 내보낸 파일 뷰어에는 보인다.
- 되돌리려면 `src/lib/ifc/import.ts` 의 "계단(OE-ML-02)" 묶음과 `Storey.verticalParts` 를 걷어내고, `vertical.ts` 의 `explicitSpaceLinks` 호출을
  뺀다. 그러면 ADR-0032 의 겹침 추정만 남는다.
