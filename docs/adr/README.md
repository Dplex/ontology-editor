# docs/adr/ — 아키텍처 결정 기록

**왜 이렇게 만들었나** 를 결정 하나에 파일 하나로 남긴다. PRD(`docs/prd/`)가 "무엇을" 이라면 ADR 은 "어떻게, 왜 그 길을" 이다.
`intent.md` 의 절들도 결정이지만 이미 서사로 자리 잡아서 옮기지 않는다 — ADR 에서 그 절을 링크한다.

55 의 문서 챗봇(8084 에서 **Alt+Shift+K**)이 이 폴더와 `docs/prd/`·`intent.md` 를 읽고 답한다(ADR-0001).
그래서 아래 틀을 지키면 챗봇이 상태·관련 티켓으로 찾아 준다.

## 언제 쓰나

작업하다 아래에 해당하는 결정을 하면 **같은 PR 에** ADR 을 하나 더한다. 세션에서 정하고 코드에만 남긴 결정은 챗봇에게 없는
것이다 — "왜 이렇게 했어?" 에 "문서에 없다" 가 나온다.

- **쓴다**: 길이 둘 이상 있었고 하나를 골랐다(구조·저장 위치·라이브러리·데이터 모양) · 실측하고 접은 방법(숫자와 함께 —
  "FootPrint 만 읽으면 Revit 방이 0개") · 임계값을 정했다(SNAP 5cm, 배치점 0.5m 같은 것과 그 근거 파일) · PRD 와 다르게 가거나
  PRD 가 비워 둔 것을 개발이 정했다(관련 D##·티켓을 frontmatter 에) · 이전 ADR 을 뒤집었다(새 ADR + 옛 것 `대체됨`)
- **안 쓴다**: 버그 수정, 이름·문구 손질, 티켓 요구사항을 그대로 구현한 것(그건 PR 본문의 확인 방법·테스트가 맡는다)
- **상태**: 사람이 세션에서 고른 것이면 `채택` 에 `deciders` 를 그 사람으로, Claude 가 혼자 정한 것이면 `제안` 으로 쓰고
  PR 본문에 "ADR-nnnn 확인 부탁" 을 적는다. merge 로 `제안` 이 저절로 `채택` 이 되지는 않는다 — 사람이 고친다
- 맥락에는 **왜**와 **실측한 숫자**를, 결과에는 **되돌리려면 무엇을 고치나**를 적는다. 챗봇이 가장 자주 받는 질문이 그 둘이다
- `docs/dev/` 의 작업 규칙(IFC 함정 등)은 그대로 둔다. 같은 내용을 ADR 로 옮기지 말고, 새 결정만 ADR 로 쓴다

## 파일 이름과 틀

`NNNN-짧은-제목.md`. 번호는 이어서 매기고 재사용하지 않는다(대체된 결정도 지우지 않는다).

```markdown
---
id: "ADR-0001"
title: "문서 챗봇은 읽기 전용 MCP 로 55 의 gemini 에 붙인다"
status: "채택"          # 제안 · 채택 · 대체됨 · 폐기
date: "2026-10-02"
deciders: ["정희록"]
prd: ["D10"]            # 관련 PRD 결정·오픈 이슈 (D##, Q##)
tickets: ["OE-COM-04"]  # 관련 티켓
supersedes: []          # 이 결정이 대체한 ADR
superseded_by: ""       # 이 결정을 대체한 ADR
---

# ADR-0001 문서 챗봇은 읽기 전용 MCP 로 55 의 gemini 에 붙인다

## 맥락
무엇이 문제였나. 어떤 제약이 있었나(실측한 숫자가 있으면 숫자로).

## 결정
무엇을 하기로 했나. 한 문단.

## 고려한 다른 길
- 다른 길 — 왜 안 골랐나

## 결과
이 결정으로 쉬워진 것·어려워진 것. 되돌리려면 무엇을 해야 하나.
```

- 결정이 바뀌면 고치지 말고 새 ADR 을 쓰고 옛 것의 `status` 를 `대체됨`, `superseded_by` 를 새 번호로 둔다.
  그때 맞던 이유가 남아야 "왜 바꿨나" 에 답할 수 있다.
- 본문에서 티켓은 `OE-XXX-nn`, PRD 결정은 `D10`, 다른 ADR 은 `ADR-0001` 로 적는다. 챗봇의 `docs_links` 가 이 꼴로 잇는다.
