# ADR-0006 요구사항 보고서의 '다른 자리'는 export 설정으로 고쳐지는 것만 — 형상 중심으로 옮긴 배치점(R11)은 '일부'로 집계한다

## 맥락

OE-BIM-17 의 수용 기준은 "'다른 위치'는 '설정을 바꿔 달라' 문구" 다. BIM→DT 문서(`docs/bim-to-dt-ontology.md`) 4장 "상태" 표도 다른 위치를 "값이 있고 에디터도 읽지만
표준 위치가 아니다(`Category Code`, `System Name`, `PSet_Revit_*`) → export 설정을 바꿔 달라" 로 정의한다.

보고서(`src/lib/requirements.ts`)가 "다른 자리" 로 집계하던 것 중 두 가지는 값의 위치 문제가 아니라 에디터가 다른 key 로 보완한 것이다.

- R11 — 배치점이 형상에서 0.5m 넘게 떨어져 있어 형상 중심으로 옮겨 읽은 설비(OE-BIM-12, 성수 277대, ifc4Mep 50대)
- R13 — 버전 비교에서 GUID 가 바뀌어 Revit 요소 ID·이름·위치로 찾은 요소(OE-BIM-19)

둘을 따로 판단했다. **R13 은 설정으로 고칠 수 있다.** BIM→DT 문서 4.1 은 R13 을 "GUID 유지 설정" 으로 적었고, 같은 Revit 으로 다시 export 한 Duplex MEP 에서
설비 344대 중 217대의 GUID 가 바뀐 것이 그 근거다 — 모델은 그대로인데 export 가 GUID 를 새로 만들었다. Revit IFC export 에서 IFC GUID 를
요소 매개변수에 저장하게 하면 다음 버전도 같은 GUID 로 export 된다. **R11 은 설정으로 고칠 수 없다.** 패밀리 삽입점이 몸체에서 떨어진 문제라
모델(패밀리)을 고쳐야 한다. R11 을 다른 자리로 두면 "설정을 바꿔 달라" 는 틀린 요청이 된다.

## 결정

- "다른 자리" 는 **export 설정만 바꾸면 표준 자리로 옮겨지는 것만** 집계한다. 그런 R 과 바꿀 설정을 `EXPORT_SETTING` 표에 둔다:
  R10(IFC4 로), R13(IFC GUID 를 요소 매개변수에 저장), R14(분류 관계로), R16(IfcSystem 으로), R21(표준 Pset 이름으로 매핑),
  R23(IfcExportAs), R24(IfcExportType).
- 줄마다 `ask`(고객사에 할 요청)를 만든다. 다른 자리면 항상 "내보내기 설정을 바꿔 달라 — {무엇을}" 이고, 일부에 다른 자리 항목이 섞이면
  그 뒤에 "나머지는 값을 넣어 달라…" 를 붙인다. 화면의 요구사항 표에 "고객사에 할 요청" 칸으로 표시된다.
- R11 의 형상 중심으로 옮긴 설비는 표준에서 빼고 **일부**로 집계한다. 숫자는 설명(note)에 남기고, 요청은 "삽입점을 형상 위로 고쳐 달라" 다.

측정: 보유 샘플 BIM 8개(AC20·ifc4Mep·Duplex 4·병원 2)에서 파일 하나로 확인했을 때 다른 자리가 나온 R 은 정확히 R13 을 뺀 6개다(R10 6개 파일,
R14 5, R16 4, R21 3, R24 3, R23 1). R13 은 버전 비교에서 나온다(mep.ifc → mep-v2.ifc, 2개). 표에 없는 R 에서 다른 자리가 나오면
`check:sample` "가진 BIM 에서 다른 자리인 줄은 모두 설정 요청이다" 가 실패한다.

## 결과

- R11 은 형상 중심으로 옮긴 설비가 있으면 표준이 아니라 일부가 된다(ifc4Mep 은 50대라 일부). 성수 기계도 일부로 바뀔 것이다(이 PC 에는
  성수가 없어 확인하지 못했다).
- 설정 이름(IfcExportAs·IfcExportType, IFC GUID 저장, 속성 매핑 파일)은 Revit 기준이다. 다른 저작 도구에는 같은 기능의 다른 메뉴가 있다.
- 되돌리려면: `requirements.ts` 의 R11 `counted(…, 0, …)` 의 둘째 인자를 moved 로 되돌리고, `EXPORT_SETTING` 에 R11 을 넣는다. 단, 요청
  문구가 실제로는 설정 문제가 아니라는 점을 감수해야 한다.
