# ADR-0071 설비 종류는 IFC 표준 값을 이름 사전보다 먼저 읽는다

## 맥락
OE-BIM-14 와 OE-REQ-03 은 "유효한 IFC 표준 값(어휘 표)이 있으면 그 값으로 확정하고, 표준 값이 없을 때만 이름 사전 후보를 제안한다" 고 한다.
OE-BIM-14#1 은 "IFC에 유효한 종류가 있으면 사전 이름 일치만으로 바뀌지 않는다" 다.

임포터(`resolveEquipmentKind`)는 반대로 **이름 사전을 먼저** 봤다(`intent.md` "이름이 먼저다"). 까닭은 두 가지였다.
- 성수의 `EF-11` 은 IFC 로는 `IfcFan` 이지만 이름이 배기팬이라고 더 좁게 말한다.
- 병원 건축의 안전손잡이·거울·소화기함 101대는 IFC 로는 `IfcSanitaryTerminal` 이라, 이름으로 흐름 없는 비치품으로 둔다.

두 예는 모두 IFC 가 **클래스만** 말한 경우다(팬의 값 `CENTRIFUGAL…` 은 생김새라 어휘 표에 없고, 위생기구는 표에 클래스만 있다).
IFC 가 **클래스와 값**을 말했고 그 `클래스.값` 이 어휘 표(`kinds.ts` 의 `ifc`)에 그대로 있는 설비를 가진 BIM 9벌(AC20·ifc4Mep·Duplex MEP·
Duplex 건축·병원 HVAC·MEP·전기·건축·Office_A)에서 세면, 이름 사전 때문에 다른 종류가 된 것은 **0대**였다(2026-10-15 실측).

## 결정
설비 종류는 아래 순서로 정한다.
1. IFC 가 말한 `클래스.값` 이 어휘 표에 그대로 있으면 그 종류다(출처 BIM). 이름 사전이 다른 종류를 말해도 바꾸지 않는다.
2. 아니면 이름 사전(출처 사전).
3. 아니면 IFC 가 말한 클래스(출처 BIM).
4. 아니면 값을 말하지 않은 클래스의 추측(`CLASS_GUESS`, 출처 사전).

"유효한 IFC 표준 값" 을 `클래스.값` 이 표에 있는 것으로 읽었다. 클래스만으로 정해지는 종류(`Fan`·`Boiler`·`SanitaryTerminal`)는
이름이 더 좁은 종류를 말할 수 있어 2번이 먼저다. 이 읽기가 PRD 의 뜻과 맞는지는 OE-BIM-14 이슈에 PM 확인을 요청했다.

방 종류(OmniClass 코드)와 이름 사전의 순서는 이 결정에 넣지 않았다. 표준 코드를 먼저 읽으면 병원의 `JAN. CL.`(청소도구실) 9개가
OmniClass 의 창고(13-75 11 11)로 바뀐다.

## 고려한 다른 길
- **IFC 를 늘 먼저(클래스만이어도)** — `EF-11` 이 팬, 병원 비치품 101대가 위생기구로 돌아가 연결망 검사에 "떨어짐" 으로 다시 뜬다.
- **지금대로 이름 사전이 늘 먼저** — 가진 BIM 에서는 결과가 같지만, 고객사가 R24 대로 클래스와 값을 적어도 이름 하나로 종류가 바뀔 수 있다.
  OE-BIM-14#1 을 지키지 못한다.

## 결과
가진 BIM 의 임포트 결과는 바뀌지 않는다(`check:sample`). 고객사가 R24 대로 `클래스.값` 을 적은 설비는 이름이 무엇이든 그 종류로 남는다.
되돌리려면 `kinds.ts` 의 `resolveEquipmentKind` 첫 두 줄(`equipmentKindOfIfcValue`)을 지운다.
