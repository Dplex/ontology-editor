# ADR-0032 E18 다중층을 이 repo 에서 어디까지 하나 · 층간 겹침 후보 규칙

## 맥락

E18(다중층 에디터 · 수직 관통 오브젝트) 티켓 19개가 2026-10-08 에 모두 `prd-done` 이 됐다(#394·#406). D10 으로 R1 편집 범위는 이 repo 가
맡는다. PRD 는 서버가 있는 플랫폼을 전제로 쓰였다. OE-ML-01 은 다중층 뷰에 들어가기 전에 층 편집을 "별도 작업으로 저장·검증·확정" 하고
"새 다중층 세션 작업 ID" 를 만들라고 한다(OE-WF-03). 이 repo 는 서버 없이 브라우저에서 돌고, 임시 저장본도 층마다 브라우저에 하나다(ADR-0014).
OE-WF-03 은 아직 `prd-review` 다.

지금 있는 것과 없는 것(2026-10-09 실측):

- **층간 연결**은 `vertical.ts` 가 내보낼 때 계산한다. 계단실·승강로 물리존이 바로 위층의 같은 종류 물리존과 바닥이 절반 넘게 겹치면 잇는다.
  아래층 방마다 가장 많이 겹친 위층 방 하나를 골랐다 — 위층 방 하나를 아래층 방 둘이 고르면 둘 다 이어졌다.
- **수직 관통 오브젝트**(OE-ML-02)는 모델에 없다. 계단은 IfcStair 로 읽을 수 있다(샘플 7개 파일 모두 있음: Duplex 2 · 병원 3 · 성수 35 ·
  Office_A 2 · FZK 1 · Institute 4 · dental 3). EL·ES 의 IfcTransportElement 는 샘플에 0 이라 이름 사전 설비에서 만든다.
- **슬래브**(IfcSlab)는 임포터가 읽지 않는다. 개구부 자동 생성(OE-ML-03)은 슬래브 형상부터 읽어야 한다.
- EL·ES 는 층 편집 화면에서 이미 잠긴다(OE-EQP-07, 1225b23).

OE-ML-19 는 겹침 후보 규칙을 바꿨다. 높이로 줄 세운 이웃 층의 같은 종류, 유효 면적, 겹친 면적 ÷ 작은 면적 **50% 초과**는 같다. 새로 생긴 것은
**양쪽이 서로를 최고 후보로 고를 때만** 일대일로 잇는 것, 동률·다대일은 모호 후보로 두고 내보내지 않는 것, 추정 출처를 표시하는 것,
병원 기준선을 "대상 ID·기대 연결·출처" 로 고정하는 것(OE-EQP-16 "7개 중 6개 이상")이다.

## 결정

**범위.** 다중층은 브라우저 안에서 한다. 서버가 있어야 하는 것만 대신하거나 미룬다.

| 이 repo 에서 한다 | 대신한다 | 미룬다(막힌 까닭) |
|---|---|---|
| ML-02 데이터 모델(편집 파일에 저장) · ML-05 층 편집 읽기 전용 · ML-01 의 보기(진입 경로 ①②, ③ 은 OE-PIP-15 와 같이) · ML-06~09 생성·이동·구간 변경·삭제 · ML-12~14 라이저·분기·오프셋 · ML-11 ES 방향 · ML-04 의 ES·계단·샤프트 통과 불가 · ML-16~18 · ML-19 층간 연결 | ML-01 의 세션 확정·작업 ID → 지금의 편집 이력(되돌리기 한 번 = 다중층 작업 하나)과 편집 파일 저장. 여러 층에 걸친 변경을 스냅샷 하나로 묶는다(OE-UI-05) | ML-03 개구부(슬래브를 아직 안 읽는다) · ML-10 EL 정차 층(#181 PM 답) · ML-15 색(glossary 에 색 값 없음, OE-OBJ-12 와 같은 질문) · ML-04 의 EL 층별 통과(ML-10 다음) · R2 잠금(OE-COM-05) |

진행 순서는 한 조각이 PR 하나다: ① 이 ADR + ML-19 겹침 후보 → ② ML-02 데이터 모델(계단은 IfcStair, EL·ES 는 이름 사전 설비에서, 물리존은
그대로 두고 id 로 잇는다) → ③ ML-05 읽기 전용 → ④ 다중층 뷰 화면 → ⑤ 편집(ML-06~09, 12~14, 18).

**층간 겹침 후보(OE-ML-19).**

- 후보: 높이로 줄 세운 바로 위층의 같은 종류(계단실·승강로) 물리존이고, 겹친 면적 ÷ 두 물리존 중 작은 면적이 0.5 를 **넘는다**.
  비율 비교는 1e-9 를 같다고 본다(삼각형으로 나눠 잰 넓이라 정확히 절반이 끝자리에서 흔들린다).
- 뺀다: 넓이가 0 이거나 잴 수 없는 외곽선, 높이가 없는 층, **높이가 같은 두 층**(위아래가 아니라 같은 층이 두 번 들어온 것). 건물은 모델 하나가
  하나다(건축·설비 파일을 합쳐도 같은 건물).
- 잇는다: 아래층 물리존의 최고 후보가 위층 물리존이고, 그 위층 물리존의 최고 후보도 그 아래층 물리존이며, 양쪽 모두 최고 비율이 하나일 때.
- 모호 후보: 그 밖의 후보 전부다. 까닭은 `tie`(한쪽의 최고 비율이 둘 이상)와 `not-mutual`(한쪽만 고름 — 다대일, 큰 물리존 하나에 작은 물리존 둘이 걸린 것)
  둘이다. `verticalConnections()` 가 돌려주고 GeoJSON 에는 내보내지 않는다.
- 출처: GeoJSON 물리존 feature 에 `verticalConnectsSource: "calc"` 를 `verticalConnects` 와 같이 낸다(ADR-0008 의 `*Source`). 사람이 정한 연결
  (ML-02)이 생기면 그 물리존은 겹침 후보에서 빼므로 물리존 하나의 연결은 출처가 하나다. 그래서 대상별 출처가 아니라 값 하나로 둔다.
- 모델에 저장하지 않고 내보낼 때 계산한다(전과 같다). 사람이 모호 후보를 확인한 결정은 ML-02 의 명시 연결로 저장한다.
- 기준선: `check:sample` 이 병원 건축의 계단실·승강로 7개를 id 로 박고 기대 연결·출처를 대 본다. 모호 후보가 0 인 것도 본다.

## 고려한 다른 길

- **세션 확정·작업 ID 를 브라우저 안 버전 목록으로 흉내 낸다.** 서버 없이는 "확정" 을 받아 줄 곳이 없고, 층마다 임시 저장본이 하나라는
  OE-WF-03 과도 부딪힌다. OE-WF-03 이 정해지면 그때 붙인다.
- **한쪽 최고 후보로 잇는 지금 방식을 둔다.** 위층 물리존 하나에 아래층 물리존 둘이 이어지는 다대일을 막지 못한다. 틀린 층간 연결은 빠진 연결보다
  로봇 경로에 나쁘다.
- **모호 후보를 GeoJSON 의 다른 키로 내보낸다.** 읽는 쪽이 유효 연결로 오인할 수 있다. 확인하는 화면(다중층 뷰)이 생기면 거기서 보이고, 확인한 것만 저장한다.
- **출처를 대상 id 별 객체로 낸다.** 위 까닭으로 물리존 하나의 출처는 하나라 필요 없다.

## 결과

- 가진 BIM 에서 숫자는 바뀌지 않는다(계단실·승강로 → 이어진 것, 모호 후보): 병원 건축 7 → 6, 0 · 성수 건축 32 → 26, 0 · Office_A 5 → 4, 0 ·
  dental 7 → 6, 0 · Duplex 건축 2 → 0, 0. 높이가 같은 층은 일곱 파일 모두 없다. 규칙·출처·모호 처리와 기준선이 새로 생겼다.
- 모호 후보는 아직 화면에 보이지 않는다. 다중층 뷰(순서 ④)에서 보이고 확인하게 한다.
- 되돌리려면 `vertical.ts` 의 `verticalConnections` 에서 상호 확인(`top`)을 걷어내고, `geojson.ts` 의 `verticalConnectsSource` 를 빼고,
  `check:sample` 의 `HOSPITAL_VERTICAL` 기준선을 지운다. 세션 확정을 붙이려면 OE-WF-03 이 정해진 뒤 새 ADR 로 이 ADR 의 "대신한다" 칸을 대체한다.
