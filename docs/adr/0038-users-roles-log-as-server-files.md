# ADR-0038 사람·역할·로그는 서버 파일

> 맨 끝의 "(다음 PR)" 인 편집 잠금·서버 임시 저장본은 [ADR-0039](0039-floor-drafts-and-locks-as-server-files.md) 가 했다.

## 맥락

버전에는 반영자가 붙고(OE-WF-13) 로그에는 사용자가 남는다(OE-COM-04). R1 은 편집 권한을 나누지 않지만(OE-COM-01), R2 는 "Viewer 는 편집 진입 거부,
Admin·Super Admin 은 편집·[반영하기], 권한 없는 반영 API 호출은 거부" 이고 권한 값은 PRD_009 권한 카탈로그다(OE-XPRD-04). 이 PoC 에는 로그인·
카탈로그·시스템 로그(PRD_009)가 없다. 2026-10-09 인터뷰에서 사용자가 "서버 users.json 에서 고르기", "Viewer 는 편집·반영 막기", "로그와 층 잠금
둘 다" 로 정했다(ADR-0037 과 같은 서버 파일 방식).

## 결정

- **사람 목록은 `data/.users.json`**(`[{ name, role }]`, 역할 `viewer`·`admin`·`super_admin`)이다. 없으면 서버가 기본 셋(편집자·관리자·보기 전용)으로
  만든다. 사람을 바꾸려면 이 파일을 고친다(화면에서 고치지 않는다).
- **화면 위의 [사용자] 칸에서 고르고 브라우저가 기억한다.** 쓰기 요청(편집 저장·반영·되돌리기·로그)에 `X-OE-User`(URL 인코딩한 이름)를 붙인다.
  반영자는 고른 사람이다 — 몸통의 이름은 쓰지 않는다.
- **보기 전용은 화면과 서버 양쪽에서 막는다.** 화면은 [편집] 을 끄고 이유를 보이며, E 키 등 다른 길로 편집 모드가 되면 보기로 돌린다. 서버는 사람이
  없으면 401, 보기 전용이면 403 이다. 사람 목록을 못 받는 곳(손으로 연 파일만 쓰는 곳)은 예전처럼 묻지 않는다.
- **승인 단계는 없다**(OE-COM-02). 편집할 수 있는 사람이 직접 반영한다.
- **시스템 로그는 `data/.log.jsonl`** 에 한 줄씩 쌓고 지우지 않는다(버전 7일 보관과 무관, OE-WF-20). 항목은 유형·일시·사용자·열쇠(사이트)·대상 층·
  버전 번호. 반영·되돌리기·편집 저장은 서버가 적고, 편집 시작·종료·임시 저장은 화면이 `POST /__data/__log` 로 보낸다. 유형 이름은 PRD_009 의
  '레이아웃 반영 / 되돌리기'(OE-XPRD-01)를 화면 표시에 쓴다. 버전 히스토리 아래 "최근 기록" 으로 그 건물의 10줄을 보인다.

## 고려한 다른 길

- **이름만 받고 역할은 R2 에.** 인터뷰에서 Viewer 막기까지 하기로 했다.
- **사내 계정(SSO) 연동.** 다른 모듈이 필요하다. 이 PoC 는 사내망 누구나 이름을 고를 수 있어 보안이 아니라 권한 자리를 흉내 낸 것이다.
- **로그를 버전 폴더에 둔다.** 버전은 7일이 지나면 감추고, 로그는 기간과 무관하게 남아야 해서 따로 둔다.

## 결과

- 편집 잠금(OE-COM-05)·서버 임시 저장본도 같은 사람을 쓴다(다음 PR).
- 기존 [편집 저장](8084)도 사람이 필요해졌다. 사람을 고르지 않으면 서버가 401 을 주고 화면이 "사용자를 고르세요" 를 보인다.
- 되돌리려면 `src/server/users.ts`·`activity-log.ts` 와 `data-catalog.ts` 의 연결, `App.vue` 의 "사람·역할"·"시스템 로그" 묶음을 걷어낸다.
