# ADR-0026 수동 공조존의 저장 자리와 담당 기준

## 맥락

IDF 공조존 임포트가 R2 로 가면서(#404) R1 에서 공조존을 만드는 길은 공간 편집의 공조존 도구뿐이다(OE-ZON-01, OE-MAN-05). 이 저장소에는
IDF 로 읽은 공조존(`model.hvac.zones`)과 그것을 TTL·GeoJSON·3D 로 내는 코드가 이미 있었다. 정할 것은 셋이었다.

- 사람이 만든 공조존을 어디에 두나
- 담당 물리존을 무엇으로 정하나(물리존을 고른 것, 경계를 그린 것)
- "계통도의 서비스 영역에 반영" 을 TTL 의 무엇으로 내나
- 경계를 고치는 법(OE-ZON-04). 물리존의 꼭짓점 편집(3D 손잡이·평면도 손잡이·`[ ]` 키·꼭짓점 넣기·지우기)은 모두 `space:` 표시와 물리존 id 에 묶여 있어,
  공조존에 같은 것을 달려면 다섯 길을 다 열어야 한다. 커스텀존도 같은 이유로 손잡이 없이 나누기·합치기만 있다

## 결정

- **층마다 `Storey.hvacZones` 에 둔다**(커스텀존과 같다). IDF 공조존은 `model.hvac` 그대로 두고, 읽는 쪽(TTL·GeoJSON·3D·화면)은
  `hvac-zone.ts` 의 `hvacZonesOf` 로 둘을 함께 본다. 모양(`HvacZone`)은 같고 `source: 'edit'`·`servedBy`·`drawn` 칸만 더했다. 편집 파일은
  바뀐 층의 목록을 통째로 적고, 층별 임시 저장본도 그 층 조각에 들어간다.
- **담당 물리존은 사람이 정한 것이 1차 기준이다(OE-MAP-02).** 물리존을 골라 만들면 고른 물리존이 담당이고, 바닥은 그 물리존들의 합집합이다
  (벽 두께 틈은 메운다). 경계를 그려 만들면 경계와 0.05㎡ 넘게 겹치는 물리존이 담당이다(OE-ZON-02 "물리존 ∩ 공조존"). 그래서 한 물리존을 두
  공조존으로 나눠 그리면 둘 다 그 물리존을 담당한다. IDF 공조존의 "방 바닥의 절반 넘게" 기준(idf/attach.ts)은 쓰지 않는다 — 반으로 나누면
  어느 쪽도 절반을 넘지 못한다.
- **담당 설비가 공조존을 `brick:feeds` 하고, 공조존이 담당 물리존을 `brick:hasPart` 한다.** IDF 공조존을 내던 방식(설비 feeds 존, 존 hasPart
  방)과 같다. 사람이 정한 것이라 규칙 방향처럼 확정을 거치지 않는다.
- 공조존은 한 층의 물리존으로만 만든다. 여러 층을 담당하는 공조기는 층마다 공조존을 만들어 담당 설비로 고른다.
- **경계는 다시 그려서 고친다.** 공조존 한 줄의 [경계 다시 그리기] 로 새 경계를 찍는다(Enter 마침, Esc 취소, 그리기 규칙은 [경계를 그려 만들기] 와 같다).
  다시 그리면 그린 공조존(`drawn`)이 되고 새 경계와 0.05㎡ 넘게 겹치는 물리존이 담당이며 몫(`spaceShares`)도 새로 잰다 — 골라 만든 목록을 두면 바닥과
  담당이 어긋난다(사무실을 고른 공조존을 창고까지 걸치게 그리면 창고가 공백 Z-01 로 남는다). 겹치는 물리존이 없으면 막고, 담당 설비와 이름은 그대로 둔다.

## 고려한 다른 길

- **물리존처럼 꼭짓점 손잡이로 경계 고치기.** 위 다섯 길을 공조존 id 로도 열어야 한다. 공조존은 물리존 몇 개를 묶는 단위라 꼭짓점이 많지 않아,
  꼭짓점 하나를 옮기려 해도 경계를 다시 찍는 비용을 받아들였다.

## 결과

- 3D 의 공조존 외곽선, IDF 공조존 표 옆의 물리존 공조존 이름, TTL·GeoJSON 이 IDF 공조존과 같은 길로 수동 공조존을 보인다.
- 경계를 그린 공조존의 담당 물리존은 만들 때 정한 것이 그대로 남는다. 그 뒤 물리존을 나누거나 합치면 다시 재는 것(OE-MAP-02 "분할하면 두 조각
  모두 원래 공조존의 담당")은 아직 없다.
- 골라 만든 공조존을 다시 그리면 "골라 만든 것" 이 아니게 된다. 되돌리기(Ctrl+Z)로 돌아온다.
- 되돌리려면(담당 기준을 절반 넘게 덮는 것으로 하려면) `hvac-zone.ts` 의 `overlappedSpaces` 를 고친다. 경계를 손잡이로 고치게 바꾸려면 `App.vue` 의
  `startHvacZoneOutline`·`hvacZoneOutline` 그리기 목적을 걷어내고 물리존 꼭짓점 편집(`moveVertex`·`dropVertex`·`insertSpaceVertex`)이 공조존 id 도 받게
  고친다. `reshapeHvacZone`(`hvac-zone.ts`)은 그 마지막 단계로 그대로 쓴다.
