# ADR-0031 수동 배관의 모양

> "한 층 안에서만 그린다" 는 [ADR-0035](0035-cross-storey-pipes.md) 가 바꿨다 — 다중층 뷰에서는 보기 범위의 다른 층 설비까지 층간 배관을 그린다. 나머지 결정은 그대로다.

## 맥락

OE-PIP-11 은 점(x·y·z)을 차례로 찍어 배관 폴리라인을 그리라고 한다. 시작과 끝은 설비·다른 배관에 잇고, Flow Type 과 계통을 고른다.
모델에는 폴리라인이 따로 없다. BIM 배관은 구간과 이음쇠가 각각 설비 하나인 사슬이고(ADR-0029), 구간의 경로는 배치점에서 잰 중심선이다(ADR-0030).

## 결정

- **그린 배관도 구간·이음쇠 사슬이다.** 찍은 점 사이의 변마다 구간 하나(`DuctSegment`·`PipeSegment`), 꺾인 자리마다 이음쇠 하나
  (`DuctFitting`·`PipeFitting`)를 편집에서 더한 설비(`added`)로 만든다. 구간에는 중심선(`axis`)을 둔다. 그래서 BIM 배관에 만든 꼭짓점 옮기기
  (OE-PIP-10), 끝점 추종(OE-PIP-12), 경로 LineString(OE-PIP-13), 완전성 검사가 따로 손대지 않아도 그린 배관에 그대로 된다.
- **이음은 `manual` 연결이고 방향을 정하지 않는다**(`directed: false`). 규칙 방향은 화면에만 보이고, 확정 전에는 TTL `feeds` 에 나가지 않는다(K4·K14).
  잇기만 해서는 담당 관계가 생기지 않는다.
- **Flow Type 은 그린 조각에만 둔다**(`Equipment.flowType`, 범례 19개, `flow-type.ts`). BIM 배관은 계통으로 가르고 있어 이번에 Flow Type 을
  붙이지 않는다. 덕트(공기)·배관(물·냉매·증기)과 IFC 클래스가 Flow Type 의 매체로 정해진다.
- **계통은 고른 것에 넣는다.** 고르지 않았으면 양 끝이 같은 계통일 때만 그 계통이다. 양 끝 설비의 계통은 바꾸지 않는다(서로 다른 계통을 합치지 않는다).
- **한 층 안에서만 그린다.** 끝이 다른 층이면 막는다. 층간 배관은 다중층 뷰(OE-PIP-15)의 일이다.
- **꺾임점은 시작 설비 높이의 수평면에 찍는다.** 마지막 변은 끝 대상 높이로 기운다. 높이가 다른 꺾임점은 꼭짓점 옮기기(OE-PIP-10)로 고친다.
- **3D 형상은 화면이 만든다.** 단면 0.3m(덕트)·0.08m(배관)의 네모 관이다. 보여 주기용이라 모델·내보내기에는 없다. 편집 파일을 다시 얹으면 다시 만든다.
- **되돌리기 한 번에 전부 빠진다.** 새로 생긴 구간·이음쇠마다 "없던 상태" 스냅샷을 묶는다. 연결·계통 자리도 같이 빠진다.
- **편집 파일**은 더한 설비 줄(`equipmentAdded`)에 `conduit`(역할·IFC 클래스·Flow Type·중심선·끝 이동)을 적는다. 이음은 기존 연결 줄이다.

## 고려한 다른 길

- **폴리라인 객체 하나(꼭짓점 목록)로 둔다.** 그리기는 단순하지만, BIM 배관과 모양이 달라 꼭짓점 옮기기·끝점 추종·경로·검사를 두 벌 만들어야 한다.
- **BIM 배관에도 Flow Type 을 붙인다.** 계통 이름·종류에서 추정해야 하는데(냉수 공급/환수를 가르지 못하는 계통이 많다) 이번 범위를 넘는다.

## 결과

- 그린 배관의 이름은 `SA 덕트 1`, `SA 이음 2` 처럼 Flow Type 과 순번이다. 패널에서 고칠 수 있다.
- Flow Type 색(OE-OBJ-12 "정해진 색", OE-ML-15)은 아직 없다.
- 되돌리려면 `src/lib/manual-pipe.ts` 와 `src/App.vue` 의 "수동 배관 그리기" 묶음, 편집 파일의 `conduit` 를 걷어낸다. 모델에 남는 필드는 `flowType` 하나다.
