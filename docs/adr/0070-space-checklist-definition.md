# ADR-0070 방별 체크리스트의 정의

## 맥락

온톨로지가 얼마나 찼는지는 건물 단위로만 보였다. 등급 칩과 완전성 검사가 건물 전체를 세서, "어느 방이 왜 비었나" 를 보려면 검사를 하나씩 펼쳐야 했다.
DT 화면이 묻는 질문(이 설비는 어느 방에, 이 방은 어느 공조기가 맡나)은 방 단위다. 그래서 방 하나에 대해 "다 찼다" 를 정해야 했다.

가진 BIM 을 건축 + 설비로 합쳐 아래 정의로 쟀다(2026-10-15).

| 샘플 | 방 | 방 종류 있음 | 급기 말단 있는 방 / 그중 TTL 에 급기 | 다 찬 방 |
|---|---|---|---|---|
| Duplex 건축+HVAC | 21 | 4 | 0 / 0 | 2 |
| Duplex 건축+MEP | 21 | 4 | 0 / 0 | 4 |
| 병원 건축+HVAC | 272 | 174 | 200 / 200 | 169 |

## 결정

**항목은 이미 내보내거나 이미 계산하는 것만 쓴다.** 새 판정을 만들지 않는다. 아홉 항목은 외곽선, 공간명, 방번호(층 안에서 겹치지 않음), 방 종류,
경계 0.5m 안의 미소속 기기 없음, 말단–원천, 급기가 TTL 에 나감, 말단·VAV 계통, 공조존이다. 방번호는 받는 쪽이 버리는 `ex:roomNumber` 인데도 센다.
운영자는 방을 번호로 부르고, 받는 쪽 파서가 넓어지면 바로 쓰인다(화면에 "받는 쪽이 버림" 을 같이 적는다).

**항목마다 채움·빔·해당 없음이다.** 해당 없음은 점수의 분모에서 뺀다. 공조존이 없는 건물에서 모든 방을 빔으로 세면 점수가 다른 항목을 가리기 때문이다.
해당 없음의 조건은 다음과 같다.

- 말단–원천: 방에 공기 말단이 없다.
- 급기: 방에 급기 말단이 없다. 환기 그릴만 있는 방은 공기가 방에서 원천으로 들어가서 `brick:feeds` 로 적지 않는다(`ttl.ts`).
- 계통: 방에 VAV·말단이 없다.
- 공조존: 건물에 공조존이 없거나, 방 종류가 계단실·승강로다. 종류가 빈 방은 공조 대상으로 본다.
- 경계 근처 미소속 기기: 외곽선이 없다.

**급기는 확정된 방향만 채움이다.** 내보내기와 같은 연결(`fluidConnections(withInferred(…, true))`)로 원천에서 급기 말단까지 가서 그 방에 닿아야 한다.
확정 전의 규칙 방향으로만 닿으면 빔이고, 화면에서 닿는 원천을 같이 보여 확정하면 채워진다고 말한다. 화면 방향으로 세면 점수가 오르지만,
TTL 에 없는 것을 채움으로 보이게 된다.

체크리스트는 화면 상태다. 아무것도 내보내지 않는다.

## 결과

- 방 패널에 체크리스트 카드, 보기 필터의 공간 칸에 방마다 점수와 [빈칸 있는 방만], 층 요약에 "다 찬 방" 이 생겼다. 빈 항목의 [고치기] 는 이미 있는 편집
  (이름 칸, 종류 고르기, 설비 고르기 → 고칠 것)으로 데려간다.
- 등급 0~4 는 방 단위로 내리지 않는다. 등급은 원본 BIM 이 얼마나 주는지 재고, 체크리스트는 지금 온톨로지가 얼마나 찼는지 본다.
- 되돌리려면 `src/lib/space-checklist.ts` 와 App.vue 의 `--- 방별 체크리스트` 절·`space-checklist` 템플릿, FloorSummary 의 `fullRooms` 를 뺀다.
  항목을 바꾸면 `space-checklist.test.ts` 의 기대값과 이 ADR 의 표를 같이 고친다.
