# ADR-0024 방 종류는 같은 공간명 단위로 사람이 정하고, 이름을 고쳐도 남는다

## 맥락

방 종류(TTL 의 Brick 클래스)는 이름 사전 → OmniClass 순으로 읽었고(R14), 사람이 바꾸는 길은 이름을 고치는 것뿐이었다(OE-SPC-01).
OE-SPC-17 은 "같은 공간명의 방은 종류를 일괄 수정할 수 있다" 를 요구한다. 성수 건축은 방 508개 중 349개를 사전이 모르는데, 그중
`S.T` 95개·`P.S` 77개처럼 층마다 되풀이되는 약어가 대부분이다(2026-10-09 실측). 정할 것은 셋이었다.

- "같은 공간명" 을 어디까지 묶을까
- 사람이 정한 종류를 이름을 고칠 때 어떻게 할까
- 이름 사전이 읽는 값과 같은 종류를 고르면 어떻게 할까

## 결정

- **같은 공간명은 건물 전체(모든 층)에서 묶는다.** 공간명 앞뒤 빈칸은 견주지 않는다. 공간명이 비면 그 방 하나다. 층마다 되풀이되는
  약어가 일괄 수정이 필요한 경우라서 층으로 나누면 같은 일을 층 수만큼 한다.
- **사람이 정한 종류는 출처가 `edit` 이고 이름을 고쳐도 남는다.** 이름을 따라 바뀌는 것은 이름 사전·OmniClass 로 정한 종류뿐이다. 사람이
  고른 것을 다른 편집이 조용히 덮지 않게 하려는 것이다. [이름으로 정하기] 를 고르면 사람이 정한 것을 거두고 사전으로 돌아간다.
- **이름 사전이 읽는 값과 같은 종류를 고르면 거두는 것과 같다.** 편집 파일에 값이 같은 편집이 쌓이지 않는다. "모름" 을 고르면 사전이 잘못
  읽은 종류를 지운 것으로 남는다(`brick:Room`).
- 편집 파일은 물리존 줄의 `kind`(만든 물리존은 `spacesAdded` 의 `kind`)에 남는다. 리포트는 공간명·바뀌기 전 종류마다 한 줄이다.

## 결과

- 성수의 `S.T`·`P.S` 처럼 약어인 방은 사전에 넣지 않아도 사람이 한 번에 종류를 정할 수 있다. 약어를 사전에 넣을지는 PM 확인 대상이다
  (티켓의 "사용자가 확인한 뒤 사전에 보강").
- 되돌리려면(이름을 고치면 사람이 정한 종류도 따라가게 하려면) `edit.ts` 의 `renameSpace` 에서 `kindSource !== 'edit'` 조건을 뺀다.
