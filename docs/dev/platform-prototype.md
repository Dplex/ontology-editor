# 온톨로지 구축 자동화 플랫폼 프로토타입

실행: `npm run dev` 후 http://localhost:5174/prototype.html.
기존 BIM 에디터는 index.html, 산출물 뷰어는 viewer.html을 그대로 사용한다.

## 구현 범위

- 사이트·층 작업 화면, 온톨로지 존재 여부에 따른 초기 구축/운영 편집 자동 분기(OE-UI-01~04).
- 실제 IFC 워커 임포트, 건축+설비 합치기, IDF 기존 임포터 사용. 가져온 모델과 샘플을 별도 사이트로 보존한다.
- 기존 Three.js 뷰어로 3D·층 표시, 평면도, 오브젝트·출처 조회, 이름/방번호 보정, 설비 좌표 수정·추가·삭제.
- 평면 클릭으로 물리존·커스텀존 작성, 편집 되돌리기/다시 실행. 수동 시작은 OE-MAN-01의 R2 체험이다.
- D1의 C안: 공간 외곽선 85%, 설비 배치점 90%, 소속 85%의 제안 기준, 중복/빈 방번호 차단.
- 층별 단일 임시 저장본(설비 연결·계통 소속 포함), 재진입 시 이어서 편집, 미저장 이동 확인, 변경 요약·3D 미리보기.
- 기존 storeyFiles의 실제 TTL/GeoJSON 다운로드, 수신 규칙 reader와 SHA-256 결과, 11항 리포트 화면·JSON.
- 브라우저 반영본·최근 1주일 버전·되돌리기(새 버전 생성). 이 기능은 prd-review 요구사항의 체험이다.
- docs/prd 티켓 250개를 빌드 시 읽는 요구사항 탐색·R1/R2·기획 상태 필터. PRD를 수정하지 않는다.

## 저장 및 한계

작업 데이터는 이 브라우저 localStorage의 ontology-platform-prototype-v1에만 남는다.
DT 서버 반영·권한·다중 사용자 잠금·공유 저장·다른 소비 시스템 영향 분석은 구현하지 않는다(D-INT).
SR 캠퍼스는 합성 모델이며 BIM 분석 수치로 주장하지 않는다.
IFC 형상 메시 캐시는 탭 메모리에만 둔다. 새로고침 후 의미 모델·좌표는 남지만 상세 메시 대신 기본 기하로 표시된다.
대용량 모델은 브라우저 저장 용량을 넘길 수 있다. 저장 실패 시 탭 내 상태를 유지하고 오류를 표시하므로 산출물로 보존한다.
공조존의 사용자 매칭 확인·Z 검사, 벽·문·창·배관·수직 편집과 생산용 모든 제약은 기존 상세 에디터/후속 구현 범위다.
상세 에디터 링크는 별도 작업이며 프로토타입 편집본을 자동 전달하지 않는다.
현재 층의 오브젝트 생성/이름/좌표 보정만 지원하며 설비 형상 편집·외벽 부착/천장 제약의 완전한 검증을 주장하지 않는다.
JSON 리포트는 U5가 결정되기 전의 임시 출력이며 범용 Turtle 검증(rdflib) 또는 실제 DT 서버 등록 검증과 구분한다.

## 확인

`npm run build`, `npm test`, `$env:PLATFORM_BROWSER_CHANNEL='chrome'; npx playwright test -c playwright.platform.config.ts`.
샘플 초기 화면, 초기 구축/운영 편집, 임시 저장 왕복, 버전 복원, 실제 IFC 임포트·오류, PRD 탐색을 확인한다.
