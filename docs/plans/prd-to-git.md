### 2.1 티켓 파일 하나의 틀

```markdown
---
id: OE-BIM-12
epic: E05
title: 배치점 보정
prd: "#6"
release: R1.5            # R1 | R1.5 | R2  (둘이면 본문에 항목별로, 필드는 앞 것)
priority: P1             # P1 | P2 | P3
owner: ontology-editor   # ontology-editor | srcn | tbd   (D10 의 주체 구분, Jira 라벨과 같은 말)
status: poc-done         # poc-done(✔) | poc-partial(◐) | todo(✗) | blocked(⏸) | srcn-unknown(SRCN?) | unknown(?)
status_note: 성수 277대 보정 표시
blocked_by: []           # D1, Q4 같은 결정·이슈 번호
depends: [R11]           # OE 번호(범위는 풀어서) · R · K · S · D

## 수용 기준
```

- **요구사항 · 수용 기준은 PM 소유, 검증 · 메모는 개발 소유.** 한 파일에 두는 이유는 PR 에서 요구 변경과 구현 변경이 같이 보이기 위해서다.

- `[v1.4]` 와 ~~취소선~~ 은 뗀다. 첫 커밋이 v1.4 스냅숏이라 "이번 판에 새로 든 것" 은 git 이 말한다. 변경 이력 표는 남긴다.

1. **정본 분리는 그대로.** 등급 · R · F · E · K-아닌-규칙은 `bim-to-dt-ontology.md`, 기능(#·OE) · 릴리즈 · D · KPI · K · S 는 `docs/prd/`. 번호로만 참조, 본문 복사 금지. 같은 repo 라 이제 상대 링크가 된다.
2. **변경은 PR.** 요구사항·수용 기준 절은 PM 이, 검증·메모 절은 개발이 고친다. 한 PR 에서 둘이 같이 바뀌는 것이 정상이다.
3. **ID 는 바꾸지 않는다.** 티켓이 없어지면 파일을 지우지 않고 `status: dropped` 와 이유. 번호 재사용 금지(원문 부록 E 4항과 같다).
4. **릴리즈·우선순위·상태는 머리 필드만.** 본문에 "(R1.5 → R2 이동)" 같은 표시를 쓰지 않는다. git 이력이다.
5. **열린 것은 `questions.md` 한 곳.** 티켓 본문에는 번호(`D1`)만. 결정되면 그 표에서 상태를 바꾸고 결론 한 줄.
6. **주간 대조는 없어진다.** 원문 3항("PRD 버전 ↔ 정본 커밋 해시")은 두 문서가 다른 곳에 있을 때의 규칙이었다.
7. **티켓 발행** 때 `jira:` 를 채운다. Jira Description 첫 줄은 파일 링크. 요구사항 본문을 Jira 에 복사하지 않는다 — 복사하면 두 벌.

## 8. 하지 않는 것

- Jira 와의 자동 동기화. 발행·상태 반영은 손으로 한다. 자동화는 티켓이 실제로 발행되고 흐름이 보인 뒤에 판단한다.
- `decisions/` 폴더. `questions.md` 의 D 표가 그 역할을 한다.
- 분해 스크립트의 repo 보존. 원문을 다시 정본으로 만드는 길을 남기지 않는다.
- 티켓 250개의 "검증 (이 repo)" 절을 이번에 전부 채우는 것. 옛 07 파일에서 옮기는 ~45건까지다. 나머지는 그 티켓을 다음에 건드릴 때 채운다 — 빈 절은 "—" 로 두어 "없다" 와 "비어 있다" 를 가른다.
