## 구현 확인 결과

OE-OBJ-12(배관 오브젝트)의 수용 기준을 지금 구현과 비교했습니다. 아래 PR 들이 merge 되면 수용 기준 셋이 충족됩니다. 요구사항의 "Flow Type 에 따라 정해진 색" 은 색 값이 정해져 있지 않아 아래에 여쭙니다.

| 수용 기준 | 지키는 PR · 시험 |
|---|---|
| Flow Type 범례에 없는 값으로 배관을 만들 수 없다 | 수동 배관 PR(OE-PIP-11, #192): 범례 19개만 고를 수 있고, 다른 값은 막음. `src/lib/manual-pipe.test.ts` "범례에 없는 Flow Type … 은 막고 아무것도 남기지 않는다" |
| 양 끝이 설비나 다른 배관에 연결되지 않은 배관은 생성 전 검증에서 위반으로 나온다 | 완전성 검사 "덕트·배관 구간과 이음쇠가 양쪽 모두 이어져 있다"(conduit-ends). 해제 보정으로 생긴 열린 끝도 사유를 보입니다. 수동 배관은 끝 대상을 고르기 전에는 그리지 않아 열린 끝이 생기지 않습니다 |
| 설비를 옮기면 연결 배관의 끝점 좌표가 설비를 따라간다 | 끝점 추종(OE-PIP-12, #193). 그린 배관도 같은 장치로 따라감(`e2e/manual-pipe.spec.ts`) |

**확인 부탁드리는 것: Flow Type 색**
- 요구사항은 "배관은 Flow Type 에 따라 정해진 색으로 그린다(OE-ML-15 와 같은 체계)" 이고, OE-ML-15 는 "glossary 의 공통 Flow Type 범례와 색상 정의" 를 쓰라고 합니다.
- glossary 의 Flow Type 표에는 코드·이름만 있고 색 값이 없습니다. 개발이 색을 정하면 OE-ML-15 의 "임의의 색으로 확정하지 않는다" 와 어긋납니다.

**확인 대상**
1. glossary 에 Flow Type 별 색을 정해 주시면 그 색으로 그린다 (개발 권장. 즉, 색 값이 정해질 때까지 그린 배관은 매체(덕트·배관)별 기본 색입니다.)
2. 개발이 색 초안을 PR 로 올리고 검토받는다 (초안은 공조 설계 도면의 관례(급기 파랑·환기 초록 등)를 따릅니다.)

확인 부탁드립니다.
