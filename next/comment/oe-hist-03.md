## 구현 확인 결과

OE-HIST-03(편집 파일 저장·불러오기)의 요구사항과 지금 구현을 비교했습니다. 수용 기준을 지키는 구현과 시험이 이미 있어 **코드 수정은 없습니다.**

| 수용 기준 | 지키는 시험 |
|---|---|
| 저장·불러오기 거친 TTL·GeoJSON = 원본 편집 결과 | `src/lib/edit-file.test.ts` 와 편집마다의 왕복 시험(공조존·수동 배관·끝 대상 바꾸기 등). `check:sample` "편집을 무작위로 섞기 (실제 BIM)": 저장·불러오기가 화면과 같고, 전부 되돌리면 연 때와 같음 |
| Duplex 재내보내기 판본(GUID 63% 변경)에서 편집 보존 | `check:sample` "S1: 같은 Revit 으로 다시 낸 MEP-2(GUID 가 바뀐 설비 217대)에 MEP 에서 한 편집이 다시 얹힌다" — 두 판본에 다 있는 설비 344대 중 217대(63%)가 GUID 가 바뀌었고, Revit 요소 ID 로 짝지어 편집이 다시 얹힘 |
| (R2) IDF 재임포트 후 편집 값 보존 | R2 라 이번 확인에서 뺐습니다 |
| 사람이 지정한 소속이 저장·불러오기 뒤에도 유지되고, 다시 연 판본에서 그 설비가 외곽선 안에 들면 지정이 풀리고 알림이 보인다 | `src/lib/space-assign.test.ts` "지정한 소속이 저장·불러오기(층 조각을 거쳐도) 뒤에도 유지되고 TTL·GeoJSON 이 같다" · "다시 연 판본에서 그 설비가 외곽선 안에 들면 지정을 쓰지 않고 "사람 지정 해제" 로 알린다", `e2e/space-assign.spec.ts` |

요구사항 본문의 나머지도 같습니다.
- **불러올 때 값을 덮어쓰지 않고 편집 함수를 다시 거친다**: `applyEdits`(`src/lib/edit-file.ts`)가 옮기기·종류·연결 같은 편집 함수를 차례로 불러 소속을 다시 판정합니다.
- **에디터가 만든 `U_` id 는 식별 정보로 찾지 않는다**: `edit-file.ts` 의 `isEditorId` 로 지문 짝짓기에서 뺍니다.
- **한 식별 정보에 둘 이상이 걸리면 얹지 않는다**: `src/lib/versions.test.ts` "한 열쇠에 둘 이상이 걸리면 그 열쇠로는 짓지 않는다".
- **BIM 배관의 형상 보정·연결 해제 보정도 다시 열어 얹으면 남는다**: `check:sample` "BIM 배관 다시 열기 (OE-PIP-14)".
