## 요약

OE-ROB-04 는 "로봇 팀이 R1 GeoJSON 의 통과·연결 속성 포맷을 확인한다" 입니다. 확인할 문서가 없어서 `docs/geojson-robot.md` 를 더했습니다.
지금 에디터가 내보내는 값만 적었고, 아직 나가지 않는 것(엘리베이터·에스컬레이터·계단·샤프트의 통과 속성)은 "아직 없는 것" 으로 따로 적었습니다.

## 구현한 것

- **파일과 좌표**: 층마다 `floor-<층 이름>.geojson`, IFC 세계 좌표(m), id 는 GlobalId(TTL 주어와 같음), 형상 없는 객체도 `geometry: null` 로 남음
- **통과 속성 `passable`**: 문 `true`, 창·벽 `false`. 벽의 외벽·내력 여부 키
- **방-문-방 `connects`**: 문이 잇는 물리존 id, 근거 `connectsSource`(`bim` 공간 경계 · `calc` 좌표). 문 자리 읽기를 끄고 열었을 때 달라지는 점
- **층간 연결 `verticalConnects`**: 계단실·승강로가 아래·위층에서 이어진 물리존 id, 잇는 조건
- **실측**: Duplex·병원·성수 건축에서 문·`connects` 분포, 근거, `verticalConnects` 수
- **예시**: 병원 건축의 문 하나와 계단실 하나(실제 내보낸 값)

코드는 바꾸지 않았습니다.

**문서에 넣은 실측값**(문·창 자리를 켜고 연 결과)

| | 문 | `connects` 2개 · 1개 · 0개 · 3개 | `verticalConnects` 가 있는 물리존 |
|---|---|---|---|
| Duplex 건축 | 14 | 9 · 4 · 0 · 1 | 0 / 21 |
| 병원 건축 | 249 | 222 · 21 · 2 · 4 | 6 / 269 |
| 성수 건축 | 528 | 270 · 224 · 34 · 0 | 26 / 508 |

## 확인 방법

1. `docs/geojson-robot.md` 를 엽니다
2. 병원 건축(`data/NBU_MedicalClinic/NBU_MedicalClinic_Arch.ifc`)을 "읽을 것 → 문·창 자리" 를 켜고 연 뒤 [GeoJSON] 을 받습니다. 문서의 예시 문 `1byTDaqS91rBnWJlv$nn_r` 과 계단실 `0ztdC3L1HAzhbhMHypqc0q` 가 같은 값입니다

## 테스트

문서만 바뀌어 화면은 없습니다. 실측값은 세 파일을 임포트해 `modelToGeoJSON` 결과를 센 것입니다.

결과: `npm test` 871 통과
