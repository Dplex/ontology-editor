## 요약

덕트·배관 구간이 GeoJSON 에 배치점 하나(`Point`)로 나가던 것을, 형상에서 읽은 경로(두 끝, `LineString`)로 바꿨습니다.
경로를 쓸 수 없는 구간(좌표 없음 · 형상 없음 · 수치 오류 · 길이 0)은 형상을 비우고 까닭을 적으며, 완전성 검사에 미반영 목록으로 보입니다. 연결·계통·방향은 형상과 상관없이 TTL 에 그대로 나갑니다.

## 구현한 것

- **경로 읽기**: 임포트가 구간마다 형상의 중심선 두 끝을 모델에 남깁니다(`axis`, 0.1mm 반올림). 형상이나 배치점이 없는 구간에는 남기지 않습니다. 배치점 하나로 경로를 만들지 않습니다.
- **지금 경로**: 구간을 통째로 옮기거나 끝을 늘이면(배관 꼭짓점 옮기기 · 끝점 추종) 경로가 같이 바뀝니다. 그래서 중심선은 연 때 배치점에서 잰 상대 좌표로 둡니다.
- **GeoJSON**
  - 경로가 있는 구간: `"geometry": {"type": "LineString", "coordinates": [[x, y, z], [x, y, z]]}`
  - 경로가 없는 구간: `"geometry": null`, `"pathIssue": "형상 없음(경로를 모름)"` 같은 까닭
  - 이음쇠와 기기는 지금처럼 `Point` 입니다
  - 원본의 (0,0,0) 좌표는 유효한 값으로 씁니다
- **미반영 목록**: 완전성 검사에 "덕트·배관 구간에 유효한 경로(서로 다른 두 끝 좌표)가 있다" 줄을 더했습니다. 어긴 구간마다 까닭과 BIM GlobalId 가 보입니다.
- GLB 대조(`read-3d.ts`)도 `LineString` 의 두 끝을 형상 범위와 견줍니다.
- 왜 이렇게 저장하는지는 ADR-0030 에 적었습니다(ADR-0030 확인 부탁드립니다).

**실제 BIM 에서 잰 값**

| | 구간 | 경로 있음 | 모델 크기 |
|---|---|---|---|
| Duplex HVAC | 231 | 231 | +13KB / 0.3MB |
| 병원 HVAC | 1,548 | 1,548 | +90KB / 2.3MB |
| 병원 MEP | 5,952 | 5,952 | +342KB / 9.0MB |
| 성수 기계 | 7,874 | 7,874 | +462KB / 10.7MB |

- 넷 다 GeoJSON 읽기 검사 문제 0건입니다
- 연 때 경로와 3D 형상의 중심선 차이는 0.08mm 이하입니다
- 꺾임 이음쇠 200개를 옮긴 뒤 늘인 끝의 어긋남은 최대 0.4mm(Duplex) · 3.95mm(병원) · 0.8mm(성수)이고, 구간을 통째로 옮긴 뒤는 0 입니다
- 경로가 없는 구간은 픽스처 `mep.ifc` 의 DUCT-01(형상 없음)과 ifc4Mep 의 미배치 덕트 6개(좌표·형상 없음)입니다
