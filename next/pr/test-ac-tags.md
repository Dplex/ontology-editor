## 요약

"PRD 티켓의 수용 기준을 우리 시험이 덮나" 에 기준 단위로 답할 길이 없었습니다. 티켓 id 를 부르는 시험은 있었지만, 그 티켓의 어느 기준을 재는지는 PR 본문에만 있었습니다.
시험 제목에 `[티켓 id#기준 번호]` 태그를 달고, 태그가 실제 기준을 가리키는지 `npm test` 가 보며, `npm run ac:coverage` 가 기준마다 재는 시험을 `docs/dev/ac-coverage.md` 에 씁니다. 이 브랜치에서 구현한 티켓 36장의 시험에 태그를 먼저 달았습니다.

## 구현한 것

- **태그 규칙**(`docs/dev/testing.md` "수용 기준 태그"):
  - `it('… [OE-ML-09#2] [OE-EQP-16#3~]', …)` — 번호는 티켓 md 의 "## 수용 기준" 에서 1 부터(글머리표가 있으면 글머리표, 없으면 문단 줄)
  - `~` 는 기준의 일부만 잰다는 뜻입니다. 예: 기준은 "EL·ES·계단·샤프트" 인데 시험은 계단만 잴 때. 보고서가 "일부" 로 따로 셉니다
  - 큰 시험 안의 한 대목은 그 위 주석에 답니다(`// [OE-EQP-16#1]`)
  - "OE-xxx 의 수용 기준을 따른다·과 같다" 로 위임한 기준에는 달지 않습니다
  - 기능 PR 은 자기 티켓의 태그를 답니다. PR md 틀(`next/pr-template.md`)에도 적었습니다
- **`scripts/ac-coverage.ts`**: 티켓 md 의 수용 기준 읽기, 시험 파일(`src`·`e2e`·`e2e-seongsu`·`scripts`)의 태그 읽기, 기준별 짝, 보고서 쓰기
- **`src/lib/ac-tags.test.ts`**(`npm test` 에 듦): 모든 태그가 있는 티켓의 있는 기준을 가리키고 위임한 기준이 아닌지. PM 이 기준을 줄이면 여기서 걸리고, 그때 태그를 새 번호로 옮깁니다
- **`npm run ac:coverage`** → `docs/dev/ac-coverage.md`: R1 Epic 별 "기준 · 다 잼 · 일부 · 비율" 표와, 태그가 있는 티켓의 기준마다 ✓(다 잼)·◐(일부만)·✗(없음)·→(위임)과 재는 시험. `npm test` 에는 넣지 않았습니다(파일을 씁니다)
- **태그를 단 티켓 36장**: 다중층(ML-01·02·04·05·07·09·19, OBJ-14, EQP-07·16), 공조존·매핑(ZON-01·02·04·05, MAP-02~06, EQP-08), 배관(PIP-08·10~14), 공간·설비(SPC-12·17, OBJ-03·09, MAN-02·03, EQP-11·15, EXT-05, WF-06). 짝은 각 PR 본문의 "수용 기준 대조" 표와 테스트 절에서 옮겼고, 시험 본문을 읽어 확인했습니다
