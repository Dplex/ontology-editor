## 요약

10-08 에 merge 한 PR 들 뒤로 성수 화면 시험(`npm run e2e:seongsu`)이 E(설비 편집)에서 멈추고, 뒤의 7개(F~K·L)는 돌지 않았습니다. 시험이 바뀐 동작을 아직 모르는 것이라, 시험을 지금 동작에 맞췄습니다.

## 무엇이 멈췄고 어떻게 맞췄나

| 시험 | 멈춘 까닭(바뀐 동작) | 맞춘 것 |
|---|---|---|
| E 설비 편집 | 성수 FCU 는 천장 설비(플레넘)라 바닥·벽 쪽에서는 위치·이름 칸이 잠김(#369 천장 편집 모드) | FCU 를 고르면 패널의 [천장 편집으로] 를 눌러 천장 편집 모드에서 고침. 방향키는 화면 방위를 따르므로 x 만이 아니라 평면 자리(x·y)가 바뀌었는지를 봄. 바닥에 설비를 더하는 E-11 앞에서 모드를 나옴 |
| F 물리존 | 나누면 새 조각(공간명 끝 `-2`)이 골라짐(#381, 방번호를 사람이 넣게) | 합칠 상대를 `-2` 가 아니라 원래 방 이름으로 고름 |
| G 연결 | 방향을 모르는 연결의 표시가 "연결" → "방향 미지정", `D` 는 미리보기이고 `Enter` 가 [적용](#385) | "방향 미지정" 연결을 짚고 `D` → `Enter` 로 하류 적용, `D` 두 번으로 반대 방향 미리보기를 거두면 하류 그대로 |
| H 종류·되돌리기 | FCU 를 옮기려 천장 편집 모드에 들어가면 한 층만 보이고, 다른 층에 저장 안 한 편집이 있으면 저장 여부를 물음 | 여러 편집 뒤 되돌리기(I-1)·글자 칸(I-4)은 바닥 설비(공조기)로 함 |
| J 한 번에 고치기 | "연결망에 붙어 있다" 의 고치기가 [연결 후보 확인] → 후보의 [잇기] 두 단계(#388). 통과 수에 천 단위 쉼표 | 후보 목록에서 첫 후보의 [잇기] 를 누름. 숫자를 쉼표째 읽음 |
| O 계통 | 확정한 계통의 덕트 계통을 바꾸면 근거가 바뀐 확정 방향은 재검토로 바뀌어 내보내지 않음(#386) | feeds 가 늘지 않고, 줄면 계통 확정 표에 "재검토" 가 보이는지를 봄. 성수에서 7,208 → 7,206(재검토 2) |
| K·L 저장·불러오기 | H 와 같음 | 옮기는 설비를 공조기로 |

공통으로 바꾼 것
- `pickDevice` 가 지금 모드에서 고칠 수 없는 설비를 고르면 패널의 [천장 편집으로]/[바닥·벽으로] 로 모드를 맞추고 다시 고릅니다.
- 시험마다 처음에 바닥·벽 쪽, 모든 층 보기로 돌아갑니다. 앞 시험이 천장 편집 모드에 둔 채 끝날 수 있어서입니다.

시험의 기대값은 `docs/seongsu-test.md` 에 이미 지금 동작으로 적혀 있습니다(O-5 는 #386, G-1 은 #385 가 고침). 시험 코드만 따라오지 못하고 있었습니다.
